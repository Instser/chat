# 07-03 17:05 续写接收中断问题修复

## 问题描述

用户反馈续写功能在接收AI响应时会中断，只能接收到一部分内容就停止了。从日志分析发现：

### 问题现象
```
2025-07-03 16:54:40.316 [reactor-http-nio-3] INFO - 完成智能分块流式发送，总字符数: 67, 实际发送: 67, 分块大小: 10
```
续写在接收了一部分内容后就停止接收新的响应块，没有收到完成标记`[DONE]`。

### 问题分析

经过代码审查发现以下问题：

#### 1. **WebClient缺少超时配置**
- 续写流程中的WebClient没有设置超时时间
- 正常聊天有30秒超时，但续写没有配置
- 可能导致长时间等待或连接中断

#### 2. **异常处理导致流中断**
- `sendContentBySmartChunking`方法中的IOException会导致continue跳过
- InterruptedException会break跳出循环，提前结束流
- JSON处理异常可能导致整个流中断

#### 3. **错误传播机制不完善**
- 流式处理中的异常可能导致整个响应流中断
- 缺乏错误恢复机制

## 解决方案

### 1. **增加WebClient超时配置**

为续写流程添加更长的超时时间：
```java
webClient.post()
    .uri(model.getBaseUrl())
    .contentType(MediaType.APPLICATION_JSON)
    .bodyValue(requestBody)
    .retrieve()
    .bodyToFlux(DataBuffer.class)
    .timeout(Duration.ofSeconds(60))  // 续写设置更长的超时时间
```

### 2. **增强异常处理机制**

#### 智能分块发送异常处理
```java
} catch (InterruptedException e) {
    log.warn("续写分块发送被中断: {}", e.getMessage());
    Thread.currentThread().interrupt();
    // 不要break，尝试发送剩余内容
    log.info("尝试继续发送剩余内容...");
} catch (IOException e) {
    log.error("续写发送分块内容失败，尝试重试: {}", e.getMessage());
    // 重试一次
    try {
        String chunkContent = chunk.toString();
        String vercelFormat = String.format("0:%s\n", mapper.writeValueAsString(chunkContent));
        response.getWriter().write(vercelFormat);
        response.getWriter().flush();
        sentChars += chunkContent.length();
        log.info("续写分块重试发送成功");
    } catch (Exception retryException) {
        log.error("续写分块重试也失败，跳过此块: {}", retryException.getMessage());
    }
    chunk.setLength(0);
}
```

#### 流式响应异常处理
```java
.doOnNext(chunk -> {
    try {
        // 处理响应块
        if (isValidJson(jsonBuffer.toString())) {
            try {
                String contentSent = processContinuationJson(jsonBuffer.toString(), response, 
                        originalContent, continuationContent, alignedContentForSaving, alignmentDone);
                // 处理成功逻辑
                jsonBuffer.setLength(0);
            } catch (Exception jsonProcessException) {
                log.error("处理续写JSON失败，跳过此块: {}", jsonProcessException.getMessage());
                jsonBuffer.setLength(0); // 清空缓冲区，继续处理下一块
            }
        }
    } catch (Exception e) {
        log.error("处理续写响应块失败，但继续处理: {}", e.getMessage());
        // 不要抛出异常，继续处理下一个chunk
    }
})
```

### 3. **错误恢复机制**

#### WebClient错误处理
```java
.doOnError(error -> {
    log.error("续写请求失败: {}", error.getMessage(), error);
    // 发送错误信息给前端
    try {
        String errorContent = "续写请求失败，请重试";
        String vercelFormat = String.format("0:%s\n", new ObjectMapper().writeValueAsString(errorContent));
        response.getWriter().write(vercelFormat);
        response.getWriter().flush();
        hasContentSent[0] = true;
    } catch (Exception e) {
        log.error("发送续写错误消息失败", e);
    }
})
.onErrorReturn("")  // 错误时返回空字符串，避免异常传播
```

## 技术改进

### ✅ 超时控制
- 续写超时时间设置为60秒（比正常聊天的30秒更长）
- 避免因网络延迟导致的连接中断

- 单个响应块处理失败不影响整个流程
- JSON处理异常被隔离，清空缓冲区继续处理

- 使用`onErrorReturn("")`避免异常传播导致流中断
- 保持流的连续性，即使部分内容失败

### ✅ 日志增强
- 详细记录各种异常情况
- 区分续写和正常聊天的日志信息
- 便于问题排查和性能监控
