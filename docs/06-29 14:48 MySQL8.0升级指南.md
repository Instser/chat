## 概述

本文档分析当前项目从MySQL 5.7升级到MySQL 8.0所需的数据库和代码改动。项目当前使用MySQL 5.7.40，计划升级到MySQL 8.0以获得更好的性能和新特性支持。

## 当前环境分析

### 数据库版本
- **当前版本**: MySQL 5.7.40-log
- **目标版本**: MySQL 8.0.x
- **字符集**: utf8mb4_unicode_ci
- **存储引擎**: InnoDB

### 技术栈
- **Java**: JDK 17 (无需修改)
- **Spring Boot**: 3.1.12 (兼容MySQL 8.0)
- **MyBatis-Plus**: 3.5.7 (兼容MySQL 8.0)
- **MySQL驱动**: mysql-connector-j (已是8.0兼容版本)
- **连接池**: Druid 1.2.23 (兼容MySQL 8.0)

## 数据库层面改动

### 1. 保留字冲突处理

MySQL 8.0新增了一些保留字，需要检查表名和字段名：

#### 需要检查的字段
```sql
-- 检查可能的保留字冲突
SELECT TABLE_NAME, COLUMN_NAME 
FROM INFORMATION_SCHEMA.COLUMNS 
WHERE TABLE_SCHEMA = 'chat' 
AND COLUMN_NAME IN ('rank', 'groups', 'window', 'lead', 'lag', 'first_value', 'last_value');
```

#### 当前项目影响评估
经过分析，当前项目表结构中**没有使用MySQL 8.0新增保留字**，无需修改。

### 2. SQL模式调整

MySQL 8.0默认SQL模式更严格：

#### 当前配置检查
```sql
-- 检查当前SQL模式

```

#### 建议配置
```sql
-- 设置兼容的SQL模式

```

### 3. 字符集和排序规则

#### 当前状态
- 数据库字符集: utf8mb4
- 排序规则: utf8mb4_unicode_ci

#### MySQL 8.0优化
```sql
-- 检查字符集配置
```

## 应用层面改动

### 1. 数据库连接配置

#### 当前配置 (application.yml)
```yaml
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://203.0.113.10:3306/chat?useUnicode=true&characterEncoding=utf8&zeroDateTimeBehavior=convertToNull&useSSL=true&serverTimezone=GMT%2B8
```

#### MySQL 8.0优化配置
```yaml
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://203.0.113.10:3306/chat?useUnicode=true&characterEncoding=utf8mb4&zeroDateTimeBehavior=convertToNull&useSSL=true&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useServerPrepStmts=true&cachePrepStmts=true&rewriteBatchedStatements=true
```

#### 新增参数说明
- `allowPublicKeyRetrieval=true`: 允许客户端获取服务器RSA公钥
- `useServerPrepStmts=true`: 使用服务器端预编译语句
- `cachePrepStmts=true`: 缓存预编译语句
- `rewriteBatchedStatements=true`: 重写批量语句以提高性能

### 升级后优化建议

#### 1. 利用MySQL 8.0新特性优化查询

```sql
-- 使用窗口函数优化聊天记录查询
CREATE VIEW v_latest_chat_messages AS
SELECT
    message_id,
    session_id,
    user_id,
    content,
    create_time,
    ROW_NUMBER() OVER (PARTITION BY session_id ORDER BY create_time DESC) as rn
FROM t_chat_message
WHERE deleted = 0;

-- 使用CTE优化复杂统计查询
WITH user_chat_stats AS (
    SELECT
        user_id,
        COUNT(*) as total_messages,
        COUNT(DISTINCT session_id) as total_sessions,
        MAX(create_time) as last_chat_time
    FROM t_chat_message
    WHERE deleted = 0
    GROUP BY user_id
)
SELECT u.username, s.*
FROM user_chat_stats s
JOIN t_user u ON s.user_id = u.id
WHERE s.total_messages > 10;
```
