# 用户修改网络搜索内容接口设计方案

**时间**: 2025-07-19 22:50
**版本**: v1.4 - 去CDN简化版
**作者**: instser

## 1. 需求分析

### 1.1 功能需求
- 允许用户修改自己会话中消息关联的网络搜索内容
- 支持修改`t_web_search_content`表中的`content`字段
- 确保用户只能修改自己的数据，保证数据安全

### 1.2 业务场景
- 用户对AI返回的网络搜索结果不满意，希望手动编辑优化
- 用户需要补充或删除某些网络搜索结果
- 用户希望调整网络搜索结果的内容格式

### 1.3 数据格式
- `content`字段格式：`[{"url":"","title":"","content":"","favicon":""}]`
- 前端传递的`content`参数需要与数据库格式保持一致

## 2. 接口设计

### 2.1 接口基本信息
- **接口路径**: `PUT /api/chat/messages/{messageId}/web-search-content`
- **请求方法**: PUT
- **认证方式**: JWT Token认证
- **权限要求**: 用户只能修改自己的数据

### 2.2 请求参数

#### 2.2.1 路径参数
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| messageId | String | 是 | 消息ID（UUID格式） |

#### 2.2.2 请求体参数
```json
{
  "content": [
    {
      "url": "https://example.com",
      "title": "示例标题",
      "content": "示例内容，最大500字符",
      "favicon": "https://example.com/favicon.ico"
    }
  ]
}
```

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| content | Array | 是 | 网络搜索结果数组，**直接存储到数据库，不做任何格式转换** |

#### 2.2.3 数据处理方式
- **前端传递**：JSON数组格式的content
- **后端处理**：直接将content数组转换为JSON字符串存储
- **数据库存储**：JSON格式，与现有格式完全一致
- **验证方式**：类型安全验证 + JSON格式验证，不修改具体字段内容

#### 2.2.4 类型安全保护
- **接收类型**：使用`List<Map<String, Object>>`替代`List<Object>`
- **结构验证**：验证每个元素都是Map类型
- **大小限制**：数组最多50个元素，总JSON大小不超过100KB
- **内容保护**：不修改content内容，仅进行类型安全检查

### 2.3 响应格式

## 3. 安全设计

### 3.1 权限验证
1. **用户认证**: 通过JWT Token验证用户身份
2. **数据权限**: 验证消息是否属于当前用户
3. **会话权限**: 验证会话是否属于当前用户

### 3.2 数据验证
1. **参数验证**: 验证messageId格式（UUID）
2. **类型安全**: 验证content为`List<Map<String, Object>>`类型
3. **结构验证**: 验证每个元素都是Map结构，但不修改内容
4. **大小限制**: 数组最多50个元素，总JSON大小不超过100KB
5. **直接存储**: 通过类型验证后直接存储，不修改content内容

### 3.3 防护措施
1. **SQL注入防护**: 使用参数化查询
2. **XSS防护**: 对用户输入进行转义处理
3. **频率限制**: 用户每分钟最多修改10次（与聊天请求限制一致）
4. **并发控制**: 使用Redis分布式锁防止同一消息并发修改
5. **事务保护**: 使用数据库事务确保数据一致性

### 4.6 处理流程与性能优化
**优化后的处理流程**：
1. **预检查阶段** (性能优化)
   - 参数格式验证：messageId UUID格式检查
   - 内容基础验证：null检查、数组长度检查
   - 快速失败：避免不必要的后续处理

2. **权限验证阶段** (性能优化)
   - 缓存用户权限：避免重复数据库查询
   - 批量权限检查：一次查询验证消息和会话权限

3. **频率限制检查** (高性能)
   - Redis计数器：O(1)时间复杂度
   - 内存降级：Redis故障时的快速响应

4. **并发控制** (性能保障)
   - Redis分布式锁：30秒超时自动释放
   - 锁粒度优化：按messageId加锁，减少锁竞争

5. **数据库操作** (性能优化)
   - 事务范围最小化：只包含必要的数据库操作
   - 批量更新：一次SQL更新多个字段
   - 索引优化：确保messageId和userId有复合索引

6. **响应优化** (性能提升)
   - 异步日志记录：不阻塞主流程
   - 精简响应数据：只返回必要信息

```java
        concurrentConflictCounter.increment();
    }
```

```java
@Aspect
@Component
public class WebSearchPerformanceAspect {

    private final WebSearchMetrics metrics;
    private final AtomicInteger activeRequests = new AtomicInteger(0);

    @Around("@annotation(com.instser.chat.annotation.WebSearchMonitoring)")
    public Object monitorPerformance(ProceedingJoinPoint joinPoint) throws Throwable {
        Timer.Sample sample = metrics.startTimer();
        activeRequests.incrementAndGet();

        try {
            Object result = joinPoint.proceed();
            metrics.recordSuccess(sample);
            return result;
        } catch (Exception e) {
            String errorCode = extractErrorCode(e);
            metrics.recordError(sample, errorCode);
            throw e;
        } finally {
            activeRequests.decrementAndGet();
        }
    }

    private String extractErrorCode(Exception e) {
        if (e instanceof WebSearchException) {
            return ((WebSearchException) e).getErrorCode().name();
        }
        return "UNKNOWN_ERROR";
    }
}
```

```java
@Service
public class WebSearchCacheService {

    private final RedisTemplate<String, Object> redisTemplate;
    private final WebSearchContentDao webSearchContentDao;

    // 权限缓存：5分钟过期，最大1000个条目
    private final LoadingCache<String, Boolean> permissionCache = Caffeine.newBuilder()
            .maximumSize(1000)
            .expireAfterWrite(5, TimeUnit.MINUTES)
            .recordStats() // 启用统计信息
            .build(this::loadUserPermission);

    // 缓存用户权限验证结果
    public boolean hasPermission(Long userId, String messageId) {
        String cacheKey = "perm:" + userId + ":" + messageId;
        return permissionCache.get(cacheKey);
    }

    // 加载用户权限（从数据库）
    private Boolean loadUserPermission(String cacheKey) {
        try {
            String[] parts = cacheKey.replace("perm:", "").split(":");
            Long userId = Long.valueOf(parts[0]);
            String messageId = parts[1];

            return webSearchContentDao.checkUserPermission(userId, messageId);
        } catch (Exception e) {
            log.warn("加载用户权限失败，cacheKey: {}", cacheKey, e);
            return false; // 权限验证失败时默认无权限
        }
    }


    // 缓存统计监控
    @Scheduled(fixedRate = 300000) // 每5分钟监控一次
    public void monitorCacheUsage() {
        CacheStats stats = permissionCache.stats();
        log.info("权限缓存统计 - 大小: {}, 命中率: {:.2f}%, 加载次数: {}",
                permissionCache.estimatedSize(),
                stats.hitRate() * 100,
                stats.loadCount());
    }
}
```

### 5.3 性能优化的数据处理示例
```java
@WebSearchMonitoring
@Transactional(rollbackFor = Exception.class)
public boolean updateWebSearchContent(String messageId, List<Map<String, Object>> content, Long userId) {
    Timer.Sample sample = webSearchMetrics.startTimer();

    try {
        // 1. 预检查阶段 - 快速失败
        validateBasicParameters(messageId, content);

        // 2. 权限验证 - 使用缓存优化
        if (!webSearchCacheService.hasPermission(userId, messageId)) {
            throw new WebSearchException(WebSearchErrorCode.NO_MESSAGE_PERMISSION);
        }

        // 3. 频率限制检查 - 高性能Redis计数
        if (!webSearchRateLimitService.checkUserUpdateRateLimit(userId)) {
            webSearchMetrics.recordRateLimit();
            throw new WebSearchException(WebSearchErrorCode.RATE_LIMIT_EXCEEDED);
        }

        // 4. 并发控制 - 分布式锁
        String lockKey = "web_search_update_lock:" + messageId;
        boolean lockAcquired = redisTemplate.opsForValue()
                .setIfAbsent(lockKey, "1", 30, TimeUnit.SECONDS);

        if (!lockAcquired) {
            webSearchMetrics.recordConcurrentConflict();
            throw new WebSearchException(WebSearchErrorCode.CONCURRENT_MODIFICATION);
        }

        try {
            // 5. 数据库更新 - 批量操作
            String newContentJson = JSON.toJSONString(content);
            int updatedRows = webSearchContentDao.updateContentByMessageId(
                    messageId, newContentJson, content.size(), userId);

            if (updatedRows == 0) {
                throw new WebSearchException(WebSearchErrorCode.WEB_SEARCH_CONTENT_NOT_FOUND);
            }

            // 6. 异步日志记录 - 不阻塞主流程
            asyncLogService.logWebSearchUpdate(userId, messageId, content.size());

            webSearchMetrics.recordSuccess(sample);
            return true;

        } finally {
            // 7. 确保锁被释放
            redisTemplate.delete(lockKey);
        }

    } catch (WebSearchException e) {
        webSearchMetrics.recordError(sample, e.getErrorCode().name());
        throw e;
    } catch (Exception e) {
        webSearchMetrics.recordError(sample, "UNKNOWN_ERROR");
        throw new WebSearchException(WebSearchErrorCode.DATABASE_ERROR, e);
    }
}

// 基础参数验证 - 快速失败
private void validateBasicParameters(String messageId, List<Map<String, Object>> content) {
    // UUID格式验证
    try {
        UUID.fromString(messageId);
    } catch (IllegalArgumentException e) {
        throw new WebSearchException(WebSearchErrorCode.MESSAGE_ID_INVALID);
    }

    // 内容基础验证
    if (content == null || content.isEmpty()) {
        throw new WebSearchException(WebSearchErrorCode.CONTENT_NULL);
    }

    if (content.size() > 50) {
        throw new WebSearchException(WebSearchErrorCode.CONTENT_TOO_MANY_ITEMS);
    }

    // 结构验证
    for (Map<String, Object> item : content) {
        if (item == null || !isValidContentFields(item)) {
            throw new WebSearchException(WebSearchErrorCode.CONTENT_INVALID_STRUCTURE);
        }
    }

    // 大小验证
    String jsonString = JSON.toJSONString(content);
    if (jsonString.getBytes(StandardCharsets.UTF_8).length > 100 * 1024) {
        throw new WebSearchException(WebSearchErrorCode.CONTENT_TOO_LARGE);
    }
}

// 内容字段验证
private boolean isValidContentFields(Map<String, Object> item) {
    return item.containsKey("url") &&
           item.containsKey("title") &&
           item.containsKey("content") &&
           item.containsKey("favicon");
}
```

### 6.5 Redis降级策略详解

#### 6.5.1 降级触发条件
- **Redis连接异常**: 网络中断、Redis服务不可用
- **Redis操作超时**: 响应时间超过阈值
- **Redis内存不足**: 内存使用率过高导致操作失败

#### 6.5.2 降级实现机制
```java
@Component
public class WebSearchRateLimitService {

    private final RedisTemplate<String, Object> redisTemplate;
    private final ConcurrentHashMap<String, ConcurrentHashMap<Long, Boolean>> fallbackCache = new ConcurrentHashMap<>();

    // 降级状态管理
    private volatile boolean redisAvailable = true;
    private volatile long lastRedisCheckTime = 0;
    private static final long REDIS_CHECK_INTERVAL = 30000; // 30秒检查一次

    public boolean checkUserUpdateRateLimit(Long userId) {
        String key = "web_search_update:rate_limit:user:" + userId;

        // 检查Redis可用性
        if (shouldCheckRedisAvailability()) {
            checkRedisAvailability();
        }

        if (redisAvailable) {
            try {
                return checkRateLimitWithRedis(key, 10);
            } catch (Exception e) {
                log.warn("Redis频率限制失败，切换到内存降级: {}", e.getMessage());
                redisAvailable = false;
                return checkRateLimitWithMemory(key, 10);
            }
        } else {
            return checkRateLimitWithMemory(key, 10);
        }
    }

    private boolean checkRateLimitWithRedis(String key, int maxRequests) {
        // Redis实现（与ChatRateLimitService保持一致）
        long currentTime = System.currentTimeMillis();
        String timeWindow = String.valueOf(currentTime / 60000); // 分钟级窗口
        String redisKey = key + ":" + timeWindow;

        Long count = redisTemplate.opsForValue().increment(redisKey);
        redisTemplate.expire(redisKey, 60, TimeUnit.SECONDS);

        return count <= maxRequests;
    }

    private boolean checkRateLimitWithMemory(String key, int maxRequests) {
        // 内存降级实现（与ChatRateLimitService保持一致）
        long currentTime = System.currentTimeMillis();
        long timeWindow = 60; // 60秒窗口

        ConcurrentHashMap<Long, Boolean> requests = fallbackCache.computeIfAbsent(key, k -> new ConcurrentHashMap<>());

        // 清理过期记录
        requests.entrySet().removeIf(entry -> currentTime - entry.getKey() > timeWindow * 1000);

        // 记录当前请求
        requests.put(currentTime, true);

        return requests.size() <= maxRequests;
    }

    private void checkRedisAvailability() {
        try {
            redisTemplate.opsForValue().get("health_check");
            redisAvailable = true;
            log.info("Redis连接恢复正常，切换回Redis频率限制");
        } catch (Exception e) {
            redisAvailable = false;
            log.warn("Redis连接仍然异常，继续使用内存降级: {}", e.getMessage());
        }
        lastRedisCheckTime = System.currentTimeMillis();
    }

    private boolean shouldCheckRedisAvailability() {
        return !redisAvailable && (System.currentTimeMillis() - lastRedisCheckTime > REDIS_CHECK_INTERVAL);
    }
}
```

1. **无缝切换**: Redis故障时自动切换到内存缓存
2. **自动恢复**: 定期检查Redis状态，恢复后自动切换回Redis
3. **一致性保证**: 内存缓存使用相同的限制逻辑
4. **性能保障**: 降级期间仍能提供频率限制功能

## 12. 简化设计说明

### 12.1 移除CDN的原因
1. **复杂性过高**: CDN集成增加了系统复杂度，不符合当前需求
2. **成本考虑**: 对于中小规模应用，CDN成本效益不明显
3. **维护负担**: CDN配置、监控、故障处理增加运维复杂度
4. **实际需求**: 网络搜索内容修改是低频操作，不需要CDN优化

### 12.2 简化后的架构优势
1. **实现简单**: 专注核心功能，减少外部依赖
2. **部署容易**: 无需配置CDN服务，降低部署门槛
3. **成本可控**: 避免CDN相关费用
4. **维护方便**: 减少故障点，提高系统稳定性

### 12.3 性能保障措施
1. **本地缓存**: Caffeine缓存提供毫秒级响应
2. **Redis缓存**: 分布式缓存保证高可用
3. **连接池优化**: 数据库和Redis连接池调优
4. **异步处理**: 非关键路径异步化处理
