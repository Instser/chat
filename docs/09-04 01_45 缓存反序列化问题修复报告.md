# UserAccount缓存反序列化问题修复报告

**时间**: 2025-09-04 01:45  
**版本**: v1.0  
**问题等级**: 中等  

## 问题描述

系统出现间歇性的Redis缓存反序列化错误：

```
Unrecognized field "packageExpired" (class com.instser.chat.entity.UserAccount), not marked as ignorable
```

## 问题根本原因

### 1. 序列化/反序列化不一致
- Jackson在序列化UserAccount对象时，会将以`is`开头的boolean方法当作属性序列化
- `isPackageExpired()` → JSON字段`packageExpired`
- `isMembershipExpired()` → JSON字段`membershipExpired`  
- `getRemainingDays()` → JSON字段`remainingDays`

### 2. 实体类缺少对应字段
- UserAccount类中没有这些"虚拟字段"的实际属性
- 反序列化时Jackson无法找到对应的setter方法
- 导致反序列化失败

### 3. 间歇性触发原因
- **L1缓存命中**: 直接返回Java对象，不涉及序列化，无问题
- **L2缓存命中**: 需要JSON反序列化，触发错误
- **数据库查询**: 查询后序列化到缓存时产生虚拟字段

## 修复方案

### 1. 添加JsonIgnore注解
为所有计算方法添加`@JsonIgnore`注解，避免序列化：

```java
@JsonIgnore
public boolean isPackageExpired() { ... }

@JsonIgnore  
public long getRemainingDays() { ... }

@JsonIgnore
public boolean isMembershipExpired() { ... }
```

### 2. 导入必要依赖
```java
import com.fasterxml.jackson.annotation.JsonIgnore;
```

### 3. 缓存清理优化
增强HybridCacheManager的clear()方法，支持清理特定模式的缓存：
- 清理`user:account:*`模式的用户账户缓存
- 保持对支付缓存的清理功能
- 添加详细的清理日志

## 修复文件清单

1. **UserAccount.java**
   - 添加JsonIgnore导入
   - 为isPackageExpired()方法添加@JsonIgnore
   - 为getRemainingDays()方法添加@JsonIgnore  
   - 为isMembershipExpired()方法添加@JsonIgnore

2. **HybridCacheManager.java**
   - 添加Set导入
   - 优化clear()方法，支持用户账户缓存清理
