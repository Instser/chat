**📅 创建时间**: 2025-07-16 02:55:00

**📊 文档版本**: v1.0  
**🎯 适用范围**: 开发、测试、生产环境  

## 📋 概述

本指南介绍如何通过启动参数和Actuator端点来管理金语聊天系统的日志级别。系统支持两种方式：
1. **启动参数设置**：在应用启动时设置日志级别
2. **Actuator端点动态调整**：运行时动态调整日志级别（仅限localhost访问）

## 🚀 方法一：启动参数设置

### 1. 基本语法
```bash
java -jar chat.jar --logging.level.<logger-name>=<level>
```

### 2. 常用启动参数

#### 🔧 开发环境启动
```bash
# 开发环境 - 详细日志
java -jar chat.jar \
  --logging.level.com.instser.chat=DEBUG \
  --logging.level.org.springframework=INFO \
  --logging.level.root=INFO
```

#### 🚀 生产环境启动
```bash
# 生产环境 - 精简日志
java -jar chat.jar \
  --logging.level.com.instser.chat=INFO \
  --logging.level.org.springframework=WARN \
  --logging.level.root=WARN
```

#### 🧪 测试环境启动
```bash
# 测试环境 - 调试日志
java -jar chat.jar \
  --logging.level.com.instser.chat=DEBUG \
  --logging.level.org.springframework=INFO \
  --logging.level.root=INFO
```

#### 🔍 问题排查启动
```bash
# 问题排查 - 全面日志
java -jar chat.jar \
  --logging.level.com.instser.chat=DEBUG \
  --logging.level.com.instser.chat.service.serviceimpl.ChatServiceImpl=DEBUG \
  --logging.level.com.instser.chat.service.serviceimpl.PaymentServiceImpl=DEBUG \
  --logging.level.root=INFO
```

#### 🗄️ 开启SQL日志
```bash
# 开启SQL日志用于数据库问题排查
java -jar chat.jar \
  --logging.level.com.instser.chat=DEBUG \
  --logging.level.com.instser.chat.dao=DEBUG \
  --logging.level.org.apache.ibatis.logging.jdbc=DEBUG \
  --logging.level.java.sql.Connection=DEBUG \
  --logging.level.java.sql.Statement=DEBUG \
  --logging.level.java.sql.PreparedStatement=DEBUG \
  --logging.level.java.sql.ResultSet=DEBUG
```

## 🔧 方法二：Actuator端点动态调整

### 1. 端点访问地址
- **基础地址**: `http://127.0.0.1:8081/actuator`
- **安全限制**: 只允许localhost (127.0.0.1) 访问

### 2. 使用Spring Boot Actuator

#### 查看当前日志级别
```bash
# 查看指定Logger的级别
curl http://127.0.0.1:8081/actuator/loggers/com.instser.chat

# 查看所有Logger的级别
curl http://127.0.0.1:8081/actuator/loggers
```

#### 动态修改日志级别
```bash
# 设置应用日志为DEBUG级别
curl -X POST http://127.0.0.1:8081/actuator/loggers/com.instser.chat \
  -H "Content-Type: application/json" \
  -d '{"configuredLevel": "DEBUG"}'

# 设置聊天服务为DEBUG级别
curl -X POST http://127.0.0.1:8081/actuator/loggers/com.instser.chat.service.serviceimpl.ChatServiceImpl \
  -H "Content-Type: application/json" \
  -d '{"configuredLevel": "DEBUG"}'

# 恢复为INFO级别
curl -X POST http://127.0.0.1:8081/actuator/loggers/com.instser.chat \
  -H "Content-Type: application/json" \
  -d '{"configuredLevel": "INFO"}'

# 重置为继承级别（null表示继承父Logger级别）
curl -X POST http://127.0.0.1:8081/actuator/loggers/com.instser.chat \
  -H "Content-Type: application/json" \
  -d '{"configuredLevel": null}'
```

### 3. 使用自定义日志管理接口

#### 查看日志级别
```bash
# 获取所有主要Logger的级别
curl http://127.0.0.1:8080/api/management/logs/levels

# 获取指定Logger的级别
curl http://127.0.0.1:8080/api/management/logs/levels/com.instser.chat
```

#### 设置日志级别
```bash
# 设置指定Logger的级别
curl -X POST "http://127.0.0.1:8080/api/management/logs/levels/com.instser.chat?level=DEBUG"

# 重置Logger级别
curl -X DELETE http://127.0.0.1:8080/api/management/logs/levels/com.instser.chat
```

#### 使用预设配置
```bash
# 设置开发环境日志级别
curl -X POST http://127.0.0.1:8080/api/management/logs/presets/development

# 设置生产环境日志级别
curl -X POST http://127.0.0.1:8080/api/management/logs/presets/production

# 设置问题排查日志级别
curl -X POST http://127.0.0.1:8080/api/management/logs/presets/debugging

# 开启SQL日志
curl -X POST http://127.0.0.1:8080/api/management/logs/sql/enable

# 关闭SQL日志
curl -X POST http://127.0.0.1:8080/api/management/logs/sql/disable
```

## 📊 日志级别说明

| 级别 | 用途 | 性能影响 | 适用场景 |
|------|------|----------|----------|
| **ERROR** | 错误信息 | 最小 | 所有环境 |
| **WARN** | 警告信息 | 很小 | 所有环境 |
| **INFO** | 关键信息 | 小 | 生产环境推荐 |
| **DEBUG** | 详细信息 | 中等 | 开发和调试 |
| **TRACE** | 最详细信息 | 较大 | 特殊调试 |

## 🔒 安全注意事项

### 1. Actuator端点安全
- Actuator端点运行在独立端口8081
- 只允许localhost (127.0.0.1) 访问
- 生产环境建议通过防火墙进一步限制访问

### 2. 日志级别安全
- DEBUG级别会输出详细信息，可能包含敏感数据
- 生产环境避免长期使用DEBUG级别
- 定期检查和调整日志级别

### 3. 性能考虑
- DEBUG级别会显著增加日志输出量
- 监控磁盘空间使用情况
- 根据需要调整日志轮转策略

## 📝 最佳实践

### 1. 环境区分
- **开发环境**: DEBUG级别，便于调试
- **测试环境**: INFO级别，关注关键流程
- **生产环境**: WARN级别，只记录警告和错误

### 2. 动态调整
- 使用Actuator端点进行临时调整
- 问题排查完成后及时恢复原有级别
- 记录调整操作和原因

### 3. 监控告警
- 监控ERROR和WARN级别日志数量
- 设置日志文件大小告警
- 定期分析日志内容

