# 2026-08-03 17:56 家用服务器本地 Redis 部署与后端切换

> 北京时间：2026-08-03 17:56  
> 版本：v1.0

## 背景

后端运行在家用服务器 `home.example.com`（SSH 端口 27016）。  
此前 Redis 默认连接远程 Redis Cloud：

- host: `redis-13095.crce178.ap-east-1-1.ec2.redns.redis-cloud.com`
- port: `13095`

存在跨网延迟与超时风险（日志中可见 Redisson 对云 Redis 的 PING timeout）。  
目标：在后端同机部署本地 Redis，后端改为连接本机 `127.0.0.1:6379`。

## 本次改动

### 1. 家用服务器安装 Redis

- 机器：`home.example.com`
- 包：`redis-server` / `redis-tools`（Ubuntu 22.04，版本 6.0.16）
- 服务：`redis-server.service`（enabled + active）
- 监听：`127.0.0.1:6379`（仅本机，不对外）
- 认证：`requirepass your-redis-password`（无 ACL 用户名）
- 配置文件：`/etc/redis/redis.conf`
  - `bind 127.0.0.1`
  - `protected-mode yes`
  - `requirepass your-redis-password`
  - `supervised systemd`

> 注意：Ubuntu 默认 `bind 127.0.0.1 -::1` 在本机解析 `-::1` 失败会导致启动失败。  
> 已改为仅 `bind 127.0.0.1`。

### 2. 后端配置修改

- `src/main/resources/application.yml`
  - 默认 host/port：`127.0.0.1` / `6379`
  - 默认 password：`your-redis-password`
  - 默认 username：空（本地 Redis 无 ACL 用户）
  - 仍支持环境变量覆盖：`REDIS_HOST` / `REDIS_PORT` / `REDIS_USERNAME` / `REDIS_PASSWORD`
- `src/main/java/com/instser/chat/config/RedissonConfig.java`
  - 默认连接改为本机 6379
  - 修复认证逻辑：仅密码时也能连接（不再强制 username+password 同时存在）

### 3. 构建与部署

- 构建：JDK 17 +  
  `mvn clean package -Dmaven.test.skip=true -Dmaven.compiler.proc=full`
- 产物：`target/chat-0.0.1-SNAPSHOT.jar`（约 111MB）
- 上传：`home.example.com:/tmp/chat-new.jar`
- 备份：`/opt/chat/chat-0.0.1-SNAPSHOT.jar.bak.localredis.YYYYMMDDHHMM`
- 替换：`/opt/chat/chat-0.0.1-SNAPSHOT.jar`
- 重启：`supervisorctl restart chat:chat_00`
- 结果：`chat:chat_00 RUNNING`

## 运维速查

### Redis 常用命令（家用服务器）

```bash
ssh -p 27016 Instser@users.noreply.github.com
sudo systemctl status redis-server
redis-cli -a 'your-redis-password' --no-auth-warning ping
redis-cli -a 'your-redis-password' --no-auth-warning INFO server
sudo tail -f /var/log/redis/redis-server.log
```

### 后端重启

```bash
sudo /www/server/panel/pyenv/bin/supervisorctl -c /etc/supervisor/supervisord.conf restart chat:chat_00
sudo /www/server/panel/pyenv/bin/supervisorctl -c /etc/supervisor/supervisord.conf status
```

### 如需临时改回云 Redis

启动时覆盖环境变量即可（或改 yml 后重新打包）：

```bash
REDIS_HOST=... REDIS_PORT=13095 REDIS_USERNAME=default REDIS_PASSWORD=...
```

## 后续建议

1. 视情况将 Redis 密码从配置默认值改为仅环境变量注入，减少明文落库。
2. 可执行 `sysctl vm.overcommit_memory=1` 消除 Redis 启动警告。
3. 本地 Redis 为干净实例，原云 Redis 会话缓存不会自动迁移；依赖缓存的登录态/限流等会重新建立。
