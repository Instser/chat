# 前后台登录会话隔离（admin-token 独立 Cookie）v1.0

**日期**：2026-09-15 17:33（北京时间）
**状态**：已完成开发与构建验证，**待部署**
**变更范围**：后端（Spring Boot）+ admin-web（Vue3），无 DB/依赖变更

## 一、需求与问题

用户诉求：**同一浏览器中，应用前台和 admin 后台能用不同账号同时登录、互不顶号**。

改造前痛点：前台与后台共用同一个 `auth-token` Cookie（同一 JWT 密钥、同一 `/api/auth/login` 入口）。在后台登录管理员会覆盖前台的普通用户身份；前台登录又会把后台管理员会话顶掉（admin-web 校验 `role!=='admin'` 后强制登出），前后台身份无法并存。

## 二、方案设计

账号体系**不变**——管理员仍是 `t_user` 中 `role='admin'` 的用户，角色管理功能完整保留。隔离做在**会话层**：

| 项 | 前台 | 后台 |
|---|---|---|
| 登录端点 | `POST /api/auth/login`（不变） | `POST /api/admin/auth/login`（新增） |
| Cookie | `auth-token`（不变） | `admin-token`（新增，HttpOnly，12h） |
| 签名密钥 | `jwt.secret`（不变） | `jwt.admin.secret`（独立，新增） |
| 认证过滤器 | `JwtAuthenticationFilter`，**跳过 `/admin/**`** | `AdminJwtAuthenticationFilter`（新增，**只处理 `/admin/**`**） |

关键机制：
1. **双 Cookie 并存**：两个 Cookie 名称不同、path 同为 `/api`，浏览器同时携带，互不覆盖。
2. **路径分流**：`AdminJwtAuthenticationFilter` 只处理剥离 context-path 后以 `/admin/` 开头的路径；`JwtAuthenticationFilter` 对 `/admin/**` 一律跳过。前台 token 在后台路径彻底无效，反之亦然。
3. **token 物理隔离**：admin token 用独立密钥 HS512 签名且 claims 带 `authType=admin` 校验——即使把两个 Cookie 内容互换粘贴也验不过。
4. **权限不变**：`/admin/**` 仍 `hasRole("ADMIN")`；admin 过滤器加载用户后额外校验 `ROLE_ADMIN`，非管理员 token 不设置认证。
5. **登出各自独立**：`/auth/logout` 只清 `auth-token`，`/admin/auth/logout` 只清 `admin-token`。

## 三、后端改动（7 新增 + 4 修改）

**新增**：
- `config/AdminJwtConfig.java` — `jwt.admin.*` 配置（secret/expiration=43200/cookie-name=admin-token/http-only=true/secure/same-site/path=/api 等，全部支持环境变量覆盖）
- `util/AdminJwtUtil.java` — admin token 生成/校验/Cookie 构造；`validateToken` 额外要求 `authType=admin`
- `security/AdminJwtAuthenticationFilter.java` — 只处理 `/admin/**`；admin-token Cookie（其次 Bearer）→ 校验 → 复用 `UserDetailsServiceImpl` 加载 → 必须 `ROLE_ADMIN` 才设置 SecurityContext
- `admin/controller/AdminAuthController.java` — `POST /admin/auth/login`（走 `authenticationManager` 与前台同一套认证，支持用户名或邮箱；非管理员拒发 Cookie）、`GET /admin/auth/me`、`POST /admin/auth/logout`、`PUT /admin/auth/change-password`（校验原密码，改 `t_user` 密码）
- `admin/dto/AdminLoginRequest.java`、`admin/dto/AdminChangePasswordRequest.java`、`admin/vo/AdminUserVO.java`（id/username/lastLoginTime）

**修改**：
- `config/SecurityConfig.java` — `/admin/auth/login` permitAll（位于 `/admin/**` 规则之前）；admin 过滤器注册在用户过滤器之前
- `security/JwtAuthenticationFilter.java` — `shouldNotFilter` 先剥离 context-path（原先含 context-path 导致跳过项实际不生效，一并修正）；新增 `/admin/` 前缀一律跳过
- `application.yml` — 新增 `jwt.admin` 段
- `README-OPS.md` — 环境变量表追加 `JWT_ADMIN_SECRET` / `JWT_ADMIN_EXPIRATION` / `JWT_ADMIN_COOKIE_NAME`

**登录错误响应约定**（与前台 `/auth/login` 的嵌套错误结构不同）：admin 登录失败返回**顶层错误码** `Result.failed(...)`——6005 用户名或密码错误 / 6008 当前账号不是管理员 / 6001 登录失败。admin-web 响应拦截器按外层 `code!==200` 自动 reject 并弹出真实消息。

## 五、部署后效果与验收

**行为变化**：
- 同浏览器：前台登普通用户 A + 后台登管理员 B，同时在线互不干扰；两边登出互不影响。
- 部署后所有已登录的后台会话失效（旧 `auth-token` 在 `/admin/**` 不再被接受），管理员需在 `/admin/` 用原账号密码重新登录一次。前台用户会话不受影响。
- 管理员在前台仍是普通用户身份（除非其在前台也登录），前台越权旁路（支付接口 isAdmin 判断）行为不变。

**验收清单**（部署后执行）：
1. 前台 `POST /api/auth/login` 与后台 `POST /api/admin/auth/login` 各自返回 `Set-Cookie: auth-token=...` / `admin-token=...`，两 Cookie 并存
2. 带 `admin-token` 调 `GET /api/admin/auth/me` → 200；带 `auth-token` 调 `GET /api/admin/users` → 401（前台 token 进不了后台）
3. 普通用户账号登后台 → 提示「当前账号不是管理员」，不下发 Cookie
4. 后台登出后前台会话仍在；反之亦然
5. 后台「修改密码」用新密码可重新登录后台（前台同账号密码同步变化，因同一 `t_user` 行）
