## 项目背景

当前项目已实现基础文件上传功能，支持多种文件格式上传并存储到数据库。现需要增强对Office文档（Word、Excel、PowerPoint）和PDF文件的解析能力，将文档内容转换为结构化文本格式存储，以便AI聊天功能能够理解和处理文档内容。

## 当前技术栈分析

- **Java版本**: JDK 17 (固定)
- **框架**: Spring Boot 3.1.12
- **数据库**: MySQL 5.7
- **文件存储**: 数据库content字段存储完整文件内容
- **现有支持格式**: 文本文件、图片、JSON等基础格式

## 实现架构设计

### 1. 服务层设计
```java
public interface DocumentParserService {
    /**
     * 解析文档内容
     * @param fileBytes 文件字节数组
     * @param fileName 文件名
     * @param fileType MIME类型
     * @return 解析后的文本内容
     */
    String parseDocument(byte[] fileBytes, String fileName, String fileType);
}
```

### 2. 解析器工厂模式
```java
public class DocumentParserFactory {
    public static DocumentParser getParser(String fileType) {
        switch (fileType) {
            case "application/vnd.openxmlformats-officedocument.wordprocessingml.document":
            case "application/msword":
                return new WordDocumentParser();
            case "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet":
            case "application/vnd.ms-excel":
                return new ExcelDocumentParser();
            case "application/vnd.openxmlformats-officedocument.presentationml.presentation":
            case "application/vnd.ms-powerpoint":
                return new PowerPointDocumentParser();
            case "application/pdf":
                return new PdfDocumentParser();
            default:
                return new DefaultTextParser();
        }
    }
}
```

### 3. 数据库存储策略
- **统一存储**: 解析后的文本内容直接存储到现有的content字段
- **不保存原始文件**: 不再存储原始文件的Base64编码，节省存储空间
- **解析状态**: 新增parse_status字段标记解析状态（可选）
- **解析时间**: 新增parsed_at字段记录解析时间（可选）

### 4. 修改现有上传逻辑示例
```java
// 在FileUploadServiceImpl.uploadFile方法中修改文件内容处理逻辑
if (isDocumentFile(detectedType)) {
    // 文档文件：使用解析器解析内容
    try {
        DocumentParser parser = DocumentParserFactory.getParser(detectedType);
        fileContent = parser.parseDocument(fileBytes, originalFilename, detectedType);
        log.info("文档解析成功，内容长度: {}", fileContent.length());
    } catch (Exception e) {
        log.error("文档解析失败: {}", e.getMessage());
        throw new RuntimeException("文档解析失败：" + e.getMessage());
    }
} else if (isTextFile(detectedType)) {
    // 文本文件：直接转换为字符串
    fileContent = new String(fileBytes, "UTF-8");
} else {
    // 其他文件类型不支持
    throw new IllegalArgumentException("不支持的文件类型：" + detectedType);
}
```

## 文件上传处理流程

### 1. 同步解析流程
```
用户上传文件 → 文件类型检测 → 选择解析器 → 解析文档内容 → 存储到content字段 → 返回成功/失败
```

### 2. 处理逻辑
- 用户上传文件后，立即进行文档解析
- 解析成功：将文本内容存储到content字段，返回成功信息
- 解析失败：记录错误信息，返回失败信息
- 不保存原始文件，只保存解析后的文本内容

### 3. 性能优化考虑
- 设置文件大小限制（建议20MB以内，避免解析超时）
- 解析超时控制（建议30秒内完成）
- 对于解析失败的文件，可以降级为普通文本处理

## 错误处理策略

### 1. 解析失败处理
- 记录详细错误日志
- 返回友好的错误提示给用户
- 解析失败时不保存文件记录

### 2. 格式兼容性
- 对不支持的文档版本提供降级处理
- 加密文档返回"文档已加密，无法解析"提示
- 损坏文档返回"文档已损坏，无法解析"提示

## 安全考虑

### 1. 文件安全
- 验证文件真实格式（魔数检测）
- 防止恶意文档攻击
- 限制解析资源消耗和时间

### 2. 内容安全
- 解析后的文本内容访问权限控制
- 用户只能访问自己上传文件的解析内容
- 敏感信息过滤（可选）

## 总结

本方案基于Apache POI和PDFBox提供了简化的文档解析解决方案，能够有效提取Word、Excel、PowerPoint和PDF文档的文本内容并直接存储到数据库。通过同步解析和统一存储策略，简化了系统架构，节省了存储空间，为AI聊天功能提供了高效的文档内容支持。

### 核心优势
1. **简化存储**: 不保存原始文件，只存储解析后的文本内容
2. **即时反馈**: 用户上传后立即获得解析结果
3. **统一处理**: 所有文档类型解析后都以文本形式存储
4. **节省空间**: 相比存储原始文件，大幅减少存储需求
5. **易于维护**: 简化的存储逻辑降低了系统复杂度
