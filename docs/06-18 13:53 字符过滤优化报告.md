## 问题分析

### 用户反馈
用户发现在日志中仍然出现`??`问号，特别是在AI响应内容中出现类似：
```
### ?? 文件结构（HTML + CSS + JS）
```

### 问题排查

#### 1. 日志分析
通过检查日志文件发现：
- 问号出现在特定位置：`### ?? 文件结构（HTML + CSS + JS）`
- 这些问号在多次AI响应中重复出现
- 问号位置固定，不像随机的编码错误

#### 2. 原因分析
经过分析，发现问题可能有两个原因：

**原因1：AI模型原始输出**
- AI模型可能使用`??`作为占位符或格式化符号
- 这是AI模型生成内容的一部分，不是编码问题

**原因2：字符过滤过于激进**
- 之前的`cleanContent`方法过滤了太多字符范围
- 可能误删了某些Unicode字符，导致显示为问号
- 过滤范围：`[\uFFFD\u0000-\u001F\u007F-\u009F]`包含了很多正常字符

## 修复方案

### 🔧 优化字符过滤策略

#### 1. 简化cleanContent方法
```java
// 修复前（过于激进）
String cleaned = content.replaceAll("[\uFFFD\u0000-\u001F\u007F-\u009F]", "");

// 修复后（精确过滤）
String cleaned = content.replaceAll("[\uFFFD\u0000]", "");
```

**优化说明**：
- 只过滤真正有问题的字符：替换字符（\uFFFD）和空字符（\u0000）
- 保留所有其他字符，包括控制字符和扩展字符
- 避免误删正常的Unicode字符

#### 2. 简化isValidCharacter方法
```java
// 修复前（过于严格）
private boolean isValidCharacter(char ch) {
    if (ch == '\uFFFD') return false;
    if (ch >= '\u0000' && ch <= '\u001F') {
        return ch == '\t' || ch == '\n' || ch == '\r';
    }
    if (ch >= '\u007F' && ch <= '\u009F') return false;
    return true;
}

// 修复后（宽松策略）
private boolean isValidCharacter(char ch) {
    if (ch == '\uFFFD') return false;  // 替换字符
    if (ch == '\u0000') return false;  // 空字符
    return true;  // 其他所有字符都有效
}
```

**优化说明**：
- 只排除最关键的问题字符
- 保留所有Unicode字符，包括特殊符号和表情符号
- 避免过度过滤导致内容丢失

#### 3. 添加调试日志
```java
// 调试：记录原始内容
log.debug("原始AI内容: [{}]", content.replace("\n", "\\n").replace("\r", "\\r"));

// 调试：记录清理后内容
if (!content.equals(cleanContent)) {
    log.debug("内容已清理: [{}] -> [{}]", 
        content.replace("\n", "\\n").replace("\r", "\\r"),
        cleanContent.replace("\n", "\\n").replace("\r", "\\r"));
}
```

**调试说明**：
- 记录AI返回的原始内容
- 对比清理前后的内容差异
- 帮助识别是否有字符被误删

## 技术原理

### 🎯 字符过滤原则

#### 1. 最小化过滤
- **原则**：只过滤确实有问题的字符
- **目标**：保留所有可能有用的内容
- **策略**：宁可保留，不要误删

#### 2. 精确识别问题字符
```java
// 真正的问题字符
\uFFFD  // 替换字符（�），编码错误时产生
\u0000  // 空字符，可能导致字符串截断
```

#### 3. 保留有用字符
```java
// 保留的字符范围
\u0001-\u001F  // 控制字符（可能包含格式信息）
\u007F-\u009F  // 扩展控制字符
所有Unicode字符  // 包括特殊符号、表情等
```
