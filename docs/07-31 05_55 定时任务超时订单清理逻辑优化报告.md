# 07-31 05:55 定时任务超时订单清理逻辑优化报告

## 📋 问题描述
系统中的定时任务没有正确对超时的订单进行清理，导致超时未支付订单无法及时被取消。

## 🔍 问题分析

### 1. 原有问题
- **定时任务执行频率不够**：原来每2分钟执行一次，对于5分钟超时的订单可能存在时间窗口
- **订单过期判断逻辑不够严格**：缺少详细的空值检查和日志记录
- **数据库查询条件不够精确**：缺少expire_time非空检查
- **缺少专门的过期订单清理机制**：过期订单处理混合在批量任务中

### 2. 根本原因
- 定时任务配置虽然正确启用，但执行逻辑存在缺陷
- 数据库查询可能返回不完整的过期订单列表
- 缺少足够的日志监控，难以追踪问题

## 🔧 优化方案

### 1. 数据库查询优化

#### 优化前
```sql
SELECT * FROM t_user_order WHERE payment_status = 0 AND expire_time < NOW() AND deleted = 0
```

#### 优化后
```sql
SELECT * FROM t_user_order WHERE payment_status = 0 AND expire_time IS NOT NULL AND expire_time < NOW() AND deleted = 0 ORDER BY expire_time ASC LIMIT 200
```

**改进点**：
- 添加 `expire_time IS NOT NULL` 检查
- 增加 `ORDER BY expire_time ASC` 排序
- 限制查询数量避免性能问题

### 2. 定时任务频率优化

#### 优化前
- 主要任务：每2分钟执行一次
- 只有一个综合性定时任务

#### 优化后
- 主要任务：每1分钟执行一次
- 新增专门的过期订单清理任务：每30秒执行一次

**改进点**：
- 提高执行频率，确保及时处理
- 分离关注点，专门处理过期订单

### 3. 订单过期判断逻辑优化

#### 优化前
```java
private boolean isOrderExpired(UserOrder order) {
    return order.getExpireTime() != null &&
           LocalDateTime.now().isAfter(order.getExpireTime()) &&
           order.getPaymentStatus() == 0;
}
```

#### 优化后
```java
private boolean isOrderExpired(UserOrder order) {
    if (order == null) {
        log.warn("订单对象为空，无法判断是否过期");
        return false;
    }
    
    if (order.getExpireTime() == null) {
        log.debug("订单{}没有设置过期时间", order.getOrderNo());
        return false;
    }
    
    if (order.getPaymentStatus() == null || order.getPaymentStatus() != 0) {
        log.debug("订单{}支付状态不是待支付(0)，当前状态: {}", order.getOrderNo(), order.getPaymentStatus());
        return false;
    }
    
    LocalDateTime now = LocalDateTime.now();
    boolean expired = now.isAfter(order.getExpireTime());
    
    if (expired) {
        log.info("发现过期订单: {}, 过期时间: {}, 当前时间: {}, 超时: {}分钟", 
                order.getOrderNo(), 
                order.getExpireTime(), 
                now,
                java.time.Duration.between(order.getExpireTime(), now).toMinutes());
    }
    
    return expired;
}
```

**改进点**：
- 添加完整的空值检查
- 增加详细的日志记录
- 计算并记录超时时间

### 4. 新增专门的过期订单清理任务

```java
@Scheduled(fixedRate = 30000) // 30秒
public void expiredOrderCleanupTask() {
    log.debug("【过期订单清理】开始执行过期订单清理任务 - {}", LocalDateTime.now());

    CompletableFuture.runAsync(() -> {
        try {
            List<UserOrder> expiredOrders = orderService.getExpiredOrders();
            
            if (!expiredOrders.isEmpty()) {
                log.info("【过期订单清理】发现{}个过期订单需要处理", expiredOrders.size());
                
                int canceledCount = 0;
                for (UserOrder order : expiredOrders) {
                    if (cancelExpiredOrder(order)) {
                        canceledCount++;
                    }
                }
                
                log.info("【过期订单清理】过期订单处理完成，成功取消: {}/{}", canceledCount, expiredOrders.size());
            }
        } catch (Exception e) {
            log.error("【过期订单清理】过期订单清理任务执行异常", e);
        }
    }, taskExecutor);
}
```

**特点**：
- 专门处理过期订单
- 高频执行（30秒一次）
- 详细的执行日志
- 异步执行避免阻塞
