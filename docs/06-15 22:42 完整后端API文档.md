## 🔐 通用说明

### 响应格式
所有接口统一使用Result格式响应：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {...}
}
```

### 错误码说明
- `200`: 成功
- `400`: 请求参数错误
- `401`: 未授权/登录过期
- `403`: 权限不足
- `404`: 资源不存在
- `500`: 服务器内部错误

### 认证方式
本系统使用**JWT Token认证**，支持两种传递方式：

#### 方式一：Cookie (推荐)
- **Cookie名称**: `auth-token`
- **自动管理**: 登录后服务器自动设置Cookie，后续请求浏览器自动发送
- **安全设置**: HttpOnly、SameSite=Strict
- **有效期**: 7天

#### 方式二：请求头 (备用)
- **请求头**: `Authorization: Bearer <token>`
- **手动管理**: 需要前端手动在每个请求中添加

**优先级**: 系统优先从Cookie中提取Token，如果Cookie中没有Token，则从Authorization请求头中提取

## 🏠 认证管理接口 (AuthController)

### 1. 用户注册
**接口路径**: `POST /api/auth/register`
**接口描述**: 创建新用户账户，验证用户名和邮箱唯一性，密码加密存储，自动生成JWT Token并设置Cookie

**请求参数** (RegisterRequest):
| 参数名 | 类型 | 必填 | 验证规则 | 描述 |
|--------|------|------|----------|------|
| username | String | 是 | @NotBlank, @Size(min=3, max=50) | 用户名，长度3-50字符 |
| email | String | 是 | @NotBlank, @Email | 邮箱地址，必须符合邮箱格式 |
| password | String | 是 | @NotBlank, @Size(min=6) | 密码，最少6位字符 |

**请求示例**:
```json
{
  "username": "testuser",
  "email": "test@example.com",
  "password": "123456"
}
```

**响应数据** (Result<UserVO>):
| 字段名 | 类型 | 描述 |
|--------|------|------|
| code | Integer | 响应状态码 (200-成功, 400-参数错误) |
