## 📋 概述

本文档详细说明金语聊天系统的日志过期策略、空间管理机制和监控告警方案，确保系统在长期运行中保持稳定的日志管理。

## 🗂️ 日志文件分类和策略

### 1. 普通日志文件（jinyu-chat.log）

#### 📊 配置参数
- **当前日志文件**：`logs/jinyu-chat.log`
- **历史文件格式**：`logs/jinyu-chat-2025-07-16-0.log`
- **单文件大小限制**：50MB
- **保留天数**：15天
- **总大小限制**：1.5GB (1536MB)
- **滚动策略**：按大小和时间滚动

#### 🔄 滚动机制
```xml
<maxFileSize>50MB</maxFileSize>
<maxHistory>15</maxHistory>
<totalSizeCap>1536MB</totalSizeCap>
<cleanHistoryOnStart>true</cleanHistoryOnStart>
```

### 2. 错误日志文件（jinyu-chat-error.log）

#### 📊 配置参数
- **当前日志文件**：`logs/jinyu-chat-error.log`
- **历史文件格式**：`logs/jinyu-chat-error-2025-07-16-0.log`
- **单文件大小限制**：20MB
- **保留天数**：30天（错误日志保留更长时间）
- **总大小限制**：512MB
- **滚动策略**：按大小和时间滚动

#### 🔄 滚动机制
```xml
<maxFileSize>20MB</maxFileSize>
<maxHistory>30</maxHistory>
<totalSizeCap>512MB</totalSizeCap>
<cleanHistoryOnStart>true</cleanHistoryOnStart>
```

## 📈 空间管理策略

### 1. 总体空间限制

| 日志类型 | 单文件大小 | 保留天数 | 总大小限制 | 预估文件数 |
|----------|------------|----------|------------|------------|
| **普通日志** | 50MB | 15天 | 1.5GB | ~30个文件 |
| **错误日志** | 20MB | 30天 | 512MB | ~25个文件 |
| **总计** | - | - | **2GB** | ~55个文件 |

### 2. 自动清理机制

#### 🕐 定时清理
- **每日清理**：凌晨2点执行 (`0 0 2 * * ?`)
- **清理条件**：
  - 超过保留天数的文件
  - 总大小超过限制时删除最旧文件
  - 启动时清理过期文件

#### ⚡ 实时监控
- **每小时检查**：监控磁盘空间和日志大小
- **告警阈值**：
  - 磁盘使用率 > 80%：警告
  - 磁盘使用率 > 90%：严重告警
  - 日志总大小超过限制：自动清理

### 3. 紧急清理策略

#### 🚨 触发条件
- 磁盘使用率超过90%
- 可用空间不足1GB
- 日志总大小超过限制150%

#### 🔧 清理动作
- 删除最旧的50%历史日志文件
- 保留当前日志文件和最近3天的文件
- 记录清理操作和释放的空间

## 📊 监控和告警

### 1. 磁盘空间监控

#### 📈 监控指标
```yaml
# 配置参数
logging:
  management:
    disk-warning-threshold: 80    # 磁盘使用率告警阈值
    disk-critical-threshold: 90   # 磁盘使用率严重告警阈值
```

#### 🚨 告警级别
- **INFO**：磁盘使用率 < 80%
- **WARN**：磁盘使用率 80-90%
- **ERROR**：磁盘使用率 > 90%

### 2. 日志文件监控

#### 📊 监控内容
- 日志文件总数量
- 日志文件总大小
- 平均文件大小
- 最旧文件的时间

#### 📝 统计报告
```
【日志统计】文件数量：45，总大小：1800MB，平均大小：40MB
```

### 3. 自动化监控

#### ⏰ 监控频率
- **每小时**：检查磁盘空间和日志大小
- **每天**：生成日志统计报告
- **每周**：分析日志增长趋势

## 🚨 故障处理

### 1. 磁盘空间不足

#### 🔧 处理步骤
1. 立即执行紧急清理
2. 检查是否有异常日志产生
3. 临时调整日志级别为WARN
4. 扩容磁盘空间或清理其他文件

#### 📝 预防措施
- 设置合理的告警阈值
- 定期检查磁盘使用情况
- 建立自动化清理机制

### 2. 日志文件过多

#### 🔧 处理步骤
1. 检查清理任务是否正常运行
2. 手动执行清理操作
3. 调整保留天数配置
4. 检查是否有日志级别设置过低

### 3. 清理任务失败

#### 🔧 处理步骤
1. 检查日志目录权限
2. 查看清理任务的错误日志
3. 手动删除过期文件
4. 重启清理任务

## 📊 性能影响

### 1. 日志写入性能

#### ⚡ 优化措施
- 使用异步日志写入
- 合理设置队列大小
- 避免频繁的文件滚动

#### 📈 性能指标
- 异步队列大小：512（普通日志）、256（错误日志）
- 不丢弃任何级别的日志
- 文件滚动触发阈值：50MB

### 2. 清理操作性能

#### ⏰ 执行时间
- 正常清理：1-5秒
- 紧急清理：5-15秒
- 大量文件清理：30秒-2分钟

#### 🔧 优化建议
- 在低负载时间执行清理
- 分批删除大量文件
- 监控清理操作的执行时间

## 📋 策略总结

### 🎯 核心策略

| 策略类型 | 配置值 | 说明 |
|----------|--------|------|
| **普通日志** | 50MB/文件，15天，1.5GB总计 | 日常运行日志 |
| **错误日志** | 20MB/文件，30天，512MB总计 | 错误和异常日志 |
| **磁盘告警** | 80%警告，90%严重 | 自动监控和告警 |
| **自动清理** | 每日2点，超限实时 | 定时和触发清理 |
| **紧急清理** | 删除50%最旧文件 | 磁盘空间严重不足时 |

### ✅ 实施效果

1. **空间控制**：总日志大小限制在2GB以内
2. **自动管理**：无需人工干预的日志生命周期管理
3. **监控告警**：实时监控磁盘空间和日志大小
4. **性能优化**：异步写入，合理的滚动策略
5. **故障恢复**：紧急清理机制确保系统稳定运行

### 🔧 使用建议

1. **生产环境**：使用默认配置（2GB总限制，15天保留）
2. **开发环境**：可适当减少保留天数和总大小
3. **监控告警**：建议接入外部监控系统
4. **定期检查**：每周检查日志增长趋势
5. **容量规划**：根据业务增长调整存储空间

通过以上策略，系统能够有效管理日志文件的生命周期，确保在长期运行中保持稳定的性能和合理的存储空间使用。
