## 📋 需求概述

根据用户需求，将订单创建后的支付等待时间从2小时缩短为5分钟，超时后自动设置为超时状态。

## 🔧 技术实施

### 1. 订单创建超时时间修改

#### 1.1 OrderServiceImpl.createOrder 方法修改
**文件位置**: `src/main/java/com/instser/chat/service/serviceimpl/OrderServiceImpl.java`

**修改内容**:
```java
// 修改前
order.setExpireTime(LocalDateTime.now().plusHours(2)); // 2小时后过期

// 修改后  
order.setExpireTime(LocalDateTime.now().plusMinutes(5)); // 5分钟后过期
```

**影响范围**: 所有新创建的订单都将使用5分钟超时设置

### 2. 定时任务频率优化

#### 2.1 OptimizedScheduledTaskService 主要任务频率调整
**文件位置**: `src/main/java/com/instser/chat/service/OptimizedScheduledTaskService.java`

**修改内容**:
```java
// 修改前
@Scheduled(fixedRate = 600000) // 10分钟
public void mainScheduledTask()

// 修改后
@Scheduled(fixedRate = 120000) // 2分钟  
public void mainScheduledTask()
```

**调整原因**: 
- 原来10分钟的检查频率不适合5分钟的超时设置
- 调整为2分钟确保订单在超时后最多2分钟内被处理
- 避免用户等待过长时间才看到订单状态更新

### 3. 现有超时处理机制验证

#### 3.1 订单过期检查逻辑
**位置**: `OptimizedScheduledTaskService.isOrderExpired()`
```java
private boolean isOrderExpired(UserOrder order) {
    return order.getExpireTime() != null && 
           LocalDateTime.now().isAfter(order.getExpireTime()) &&
           order.getPaymentStatus() == 0;
}
```

#### 3.2 过期订单处理逻辑
**位置**: `OptimizedScheduledTaskService.cancelExpiredOrder()`
```java
private boolean cancelExpiredOrder(UserOrder order) {
    // 更新订单状态为已取消 (status = 2)
    boolean success = orderService.updatePaymentStatus(order.getOrderNo(), 2, null);
    
    // 记录审计日志
    paymentAuditService.recordStatusChangeAudit(
        order.getOrderNo(), 0, 2, "订单过期自动取消", details
    );
}
```

#### 3.3 数据库查询方法
**位置**: `UserOrderDao.selectExpiredOrders()`
```sql
SELECT * FROM t_user_order 
WHERE payment_status = 0 
  AND expire_time < NOW() 
  AND deleted = 0
```

## 📊 系统架构

### 1. 订单生命周期
```
订单创建 → 5分钟等待期 → 超时检查 → 自动取消
    ↓           ↓            ↓         ↓
 设置过期时间   用户支付    定时任务检查  状态更新为取消
```

### 2. 定时任务执行流程
```
每2分钟执行 → 查询过期订单 → 批量处理 → 状态更新 → 审计日志
     ↓            ↓           ↓         ↓         ↓
  主要定时任务   数据库查询   订单取消   状态变更   记录操作
```

### 3. 超时处理时间线
```
T+0分钟: 订单创建，设置5分钟过期时间
T+5分钟: 订单过期
T+5-7分钟: 定时任务检测到过期订单并处理
T+7分钟: 用户看到订单状态更新为"已取消"
```

## 🎯 功能特性

### 1. 快速超时机制
- **超时时间**: 5分钟（从2小时大幅缩短）
- **检查频率**: 每2分钟（从10分钟优化）
- **处理延迟**: 最多2分钟（大幅改善用户体验）

### 2. 自动状态管理
- **自动取消**: 超时订单自动设置为取消状态
- **状态同步**: 实时更新订单状态
- **审计记录**: 完整的操作日志记录

### 3. 异常处理
- **容错机制**: 单个订单处理失败不影响其他订单
- **日志记录**: 详细的错误日志和操作日志
- **事务安全**: 使用@Transactional确保数据一致性

## 📈 性能影响分析

### 1. 定时任务频率提升影响
- **数据库查询频率**: 从每10分钟1次 → 每2分钟1次
- **查询负载增加**: 约5倍，但查询本身很轻量
- **系统资源消耗**: 轻微增加，在可接受范围内

### 2. 用户体验改善
- **状态反馈速度**: 从最多10分钟 → 最多2分钟
- **支付时间压力**: 从2小时 → 5分钟（更紧迫，减少无效订单）
- **系统响应性**: 显著提升

- **系统清洁度**: 减少大量长期待支付订单
