# Redisson日志级别优化

**修改时间**: 2025-07-30 21:25  
**版本**: v1.0  
**修改人**: AI Assistant  

## 问题描述

在应用运行过程中，Redisson连接相关的日志频繁出现在INFO级别，产生大量如下日志：

```
2025-07-30 21:12:22.687 [redisson-netty-2-15] INFO  org.redisson.connection.DNSMonitor - Detected DNS change. Master redis://your-db-host.example.com:31122 has changed ip from 203.0.113.12 to 203.0.113.11
2025-07-30 21:12:22.800 [redisson-netty-2-4] INFO  o.r.c.p.MasterPubSubConnectionPool - 1 connections initialized for your-db-host.example.com/203.0.113.11:31122
2025-07-30 21:12:23.033 [redisson-netty-2-11] INFO  org.redisson.connection.SingleEntry - master your-db-host.example.com/203.0.113.12:31122 has changed to your-db-host.example.com/203.0.113.11:31122
2025-07-30 21:12:23.033 [redisson-netty-2-11] INFO  o.r.c.pool.MasterConnectionPool - 5 connections initialized for your-db-host.example.com/203.0.113.11:31122
```

这些日志虽然提供了连接状态信息，但在生产环境中频繁出现会影响日志的可读性。

## 解决方案

将Redisson相关的日志级别从INFO调整为DEBUG，减少生产环境中的日志输出量。

## 修改内容

### 1. 修改logback-spring.xml配置

**文件**: `src/main/resources/logback-spring.xml`  
**位置**: 第102-107行  

添加了Redisson相关的日志配置：

```xml
<!-- Redisson日志配置 - 将连接相关日志设置为DEBUG级别 -->
<logger name="org.redisson" level="DEBUG"/>
<logger name="org.redisson.connection" level="DEBUG"/>
<logger name="org.redisson.connection.DNSMonitor" level="DEBUG"/>
<logger name="org.redisson.connection.SingleEntry" level="DEBUG"/>
<logger name="org.redisson.connection.pool" level="DEBUG"/>
```

### 2. 更新LogLevelManager

**文件**: `src/main/java/com/instser/chat/util/LogLevelManager.java`  
**位置**: 第90-103行  

在主要Logger列表中添加了Redisson相关的Logger，以便通过管理界面进行动态调整：

## 影响分析

### 正面影响
1. **减少日志噪音**: 生产环境中不再频繁显示Redisson连接状态变化日志
2. **提高日志可读性**: 重要的业务日志更容易被发现和分析
3. **降低日志存储成本**: 减少日志文件大小，降低存储空间占用
4. **保持调试能力**: 开发环境可以通过调整日志级别为DEBUG来查看详细连接信息

### 潜在影响
1. **连接问题排查**: 生产环境中Redis连接问题的排查可能需要临时调整日志级别
2. **监控盲点**: 需要通过其他方式监控Redis连接状态

## 使用说明

### 开发环境查看Redisson详细日志

如果需要在开发环境中查看Redisson的详细连接日志，可以通过以下方式：

1. **通过application.yml配置**:
```yaml
logging:
  level:
    org.redisson: DEBUG
    org.redisson.connection: DEBUG
```

2. **通过日志管理API动态调整**:
```bash
# 设置Redisson日志为DEBUG级别
curl -X POST "http://localhost:8081/admin/logs/level" \
  -H "X-API-Key: your-api-key" \
  -H "Content-Type: application/json" \
  -d '{"loggerName": "org.redisson", "level": "DEBUG"}'
```

3. **通过LogLevelManager编程方式**:
```java
@Autowired
private LogLevelManager logLevelManager;

// 临时开启Redisson详细日志
logLevelManager.setLevel("org.redisson", "DEBUG");
logLevelManager.setLevel("org.redisson.connection", "DEBUG");
```

### 生产环境临时启用

如果生产环境需要临时查看Redisson连接日志进行问题排查：

```bash
# 临时启用DEBUG级别
curl -X POST "http://localhost:8081/admin/logs/level" \
  -H "X-API-Key: your-production-api-key" \
  -H "Content-Type: application/json" \
  -d '{"loggerName": "org.redisson.connection", "level": "INFO"}'

# 排查完成后恢复DEBUG级别
curl -X POST "http://localhost:8081/admin/logs/level" \
  -H "X-API-Key: your-production-api-key" \
  -H "Content-Type: application/json" \
  -d '{"loggerName": "org.redisson.connection", "level": "DEBUG"}'
```

## 验证方法

1. **重启应用**: 重启应用后，Redisson连接相关的日志应该不再在控制台和日志文件中以INFO级别显示
2. **检查日志级别**: 通过日志管理API查询当前Redisson的日志级别
3. **功能测试**: 确认Redis功能正常工作，缓存、会话等功能不受影响
