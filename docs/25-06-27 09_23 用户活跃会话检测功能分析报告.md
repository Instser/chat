## 📋 功能概述

本项目实现了一套完整的用户活跃会话检测和管理系统，主要用于聊天中断功能，但同时提供了强大的会话状态监控和管理能力。该系统能够实时跟踪每个用户的活跃聊天会话，支持会话中断、超时清理和状态统计等功能。

## 🏗️ 系统架构分析

### 1. 核心服务组件

#### ChatInterruptService 接口
- **位置**: `src/main/java/com/instser/chat/service/ChatInterruptService.java`
- **职责**: 定义会话管理的核心接口
- **主要方法**:
  - `registerActiveSession(String sessionId, Long userId)` - 注册活跃会话
  - `interruptChat(String sessionId, Long userId)` - 中断指定会话
  - `isInterrupted(String sessionId)` - 检查会话是否被中断
  - `markSessionCompleted(String sessionId)` - 标记会话完成并清理
  - `getActiveSessionCount()` - 获取活跃会话数量
  - `cleanupTimeoutSessions()` - 清理超时会话

#### ChatInterruptServiceImpl 实现类
- **位置**: `src/main/java/com/instser/chat/service/serviceimpl/ChatInterruptServiceImpl.java`
- **核心数据结构**:
  ```java
  // 活跃会话映射：sessionId -> 会话信息
  ConcurrentHashMap<String, SessionInfo> activeSessions
  
  // 中断标志映射：sessionId -> 是否中断
  ConcurrentHashMap<String, Boolean> interruptFlags
  ```

### 2. 会话信息管理

#### SessionInfo 内部类
```java
private static class SessionInfo {
    private final Long userId;           // 用户ID
    private final LocalDateTime startTime; // 开始时间
    
    public boolean isTimeout() {
        // 会话超时时间：30分钟
        return startTime.plusMinutes(30).isBefore(LocalDateTime.now());
    }
}
```

### 3. 定时清理机制

#### ChatInterruptConfig 配置类
- **位置**: `src/main/java/com/instser/chat/config/ChatInterruptConfig.java`
- **清理频率**: 每5分钟执行一次 (`@Scheduled(fixedRate = 300000)`)
- **超时时间**: 30分钟无活动自动清理
- **功能**: 防止内存泄漏，自动清理超时会话

## 🔄 会话生命周期管理

### 1. 会话注册流程
```
用户发起聊天请求
    ↓
调用 registerActiveSession(sessionId, userId)
    ↓
存储到 activeSessions Map
    ↓
初始化中断标志为 false
    ↓
记录会话开始时间
    ↓
输出活跃会话统计日志
```

### 2. 会话中断流程
```
用户点击停止按钮
    ↓
前端发送中断请求
    ↓
验证用户权限 (只能中断自己的会话)
    ↓
设置中断标志为 true
    ↓
流式处理检测到中断标志
    ↓
保存部分响应内容
    ↓
发送中断完成标记
    ↓
清理会话状态
```

### 3. 会话完成流程
```
AI响应正常完成 或 中断完成
    ↓
调用 markSessionCompleted(sessionId)
    ↓
从 activeSessions 中移除会话
    ↓
从 interruptFlags 中移除标志
    ↓
记录清理日志和剩余会话数
```

### 4. 超时清理流程
```
定时任务每5分钟执行
    ↓
遍历所有活跃会话
    ↓
检查会话是否超时 (30分钟)
    ↓
清理超时会话状态
    ↓
记录清理统计信息
```

## 🛡️ 安全机制分析

### 1. 用户权限验证
```java
// 验证用户只能中断自己的会话
if (!sessionInfo.getUserId().equals(userId)) {
    log.warn("中断聊天失败：用户权限不匹配，sessionId={}, requestUserId={}, sessionUserId={}", 
            sessionId, userId, sessionInfo.getUserId());
    return false;
}
```

### 2. 并发安全保障
- **数据结构**: 使用 `ConcurrentHashMap` 确保线程安全
- **原子操作**: 会话状态的读写操作具有原子性
- **竞态条件**: 避免多线程环境下的数据竞争

### 3. 内存管理策略
- **定时清理**: 每5分钟自动清理超时会话
- **超时机制**: 30分钟无活动自动过期
- **异常处理**: 清理失败不影响系统稳定性

## 📈 性能分析

### 1. 内存使用
- **单会话开销**: 约100-200字节 (SessionInfo对象)
- **1000活跃会话**: 约200KB内存占用
- **清理效率**: 定时清理确保内存不会无限增长

### 2. 响应时间
- **会话注册**: O(1) 时间复杂度，毫秒级响应
- **状态检查**: O(1) 时间复杂度，极快响应
- **清理操作**: O(n) 时间复杂度，但频率低影响小

### 3. 并发能力
- **线程安全**: ConcurrentHashMap支持高并发读写
- **无锁设计**: 大部分操作无需加锁，性能优异
- **扩展性**: 支持大量并发用户的会话管理
