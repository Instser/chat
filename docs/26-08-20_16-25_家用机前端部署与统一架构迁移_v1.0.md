[Service]
Type=simple

Environment=NODE_ENV=production
Environment=PORT=3001

WantedBy=multi-user.target

## 5. CDN 回源方案（家用机 9080 直接可达）

### 5.1 重大发现

家用机 `home.example.com`（120.82.48.3）的 **9080 端口从外网可达**（运营商只封 80/443，不封 9080）。

经实测，用 `Host: chat.instser.cn` 访问 `http://home.example.com:9080/` 全链路通：
- 首页 200（返回 ToUse.Chat）
- API `/api/models` 401（请求打到后端）
- 管理后台 `/admin/` 200

**不需要新公网机，不需要 frp 隧道。** 家用机 9080 端口直接对外暴露 Nginx 服务。

### 5.2 目标架构

```
用户浏览器
    │ HTTPS (443, 证书在CDN)
    ▼
阿里云CDN (chat.instser.cn)
    │ 回源 HTTP (9080端口)
    ▼
home.example.com:9080  ← 家用机公网入口(已验证可达)
    │
    ▼
家用机 Nginx :80
    ├─ /api/ → 后端 :8080 (SSE流式)
    ├─ /admin/ → 静态
    └─ / → Next.js :3001
```

### 5.3 阿里云 CDN 配置

| 配置项 | 值 | 说明 |
|---|---|---|
| 加速域名 | `chat.instser.cn` | |
| 加速类型 | 静态加速 | |
| **回源地址** | `home.example.com` | 或 IP `120.82.48.3` |
| **回源端口** | **`9080`** | 关键！自定义非标准端口 |
| **回源协议** | **HTTP** | 9080 是 HTTP（实测 HTTPS 不可用） |
| **回源 Host** | **`chat.instser.cn`** | 关键！否则 Nginx 返回 404 |
| HTTPS 证书 | 阿里云免费 SSL | 配在 CDN，用户走 443 |
| 加速区域 | 仅中国内地 | 已备案 |

### 5.4 缓存规则

| 路径 | 缓存策略 | 理由 |
|---|---|---|
| `/_next/static/` | 365 天 immutable | Next.js chunk |
| `/admin/`、`/assets/` | 30 天 | admin-web 静态 |
| `/api/**` | 不缓存透传 | SSE 流式，需实测兼容性 |
| `/`（HTML） | 短缓存或不缓存 | 可能含动态内容 |

### 5.5 SSE 流式兼容性（需实测）

`/api/chat` 是 SSE 流式响应。阿里云普通 CDN 对 `text/event-stream` 的处理需实测：
- 若 CDN buffer 导致流式变成"一次性吐完" → 切 DCDN 或独立 API 子域名
- 独立 API 子域名：`api.chat.instser.cn` → CDN 回源 9080，`/api/` 完全经 CDN 透传

### 5.6 DNS 切换

`chat.instser.cn` CNAME → 阿里云 CDN 分配的加速域名。

### 5.7 安全说明

CDN→源站这段是明文 HTTP（9080 端口无 SSL）。用户→CDN 是 HTTPS（加密）。明文回源的风险：
- CDN 节点到家用机这段走公网，Cookie JWT 明文传输
- 大多数场景可接受；若需加密，可在家用机 9080 配 SSL（回源 HTTPS），但增加复杂度

## 6. 联通验收清单（CDN 配置完成后）

```bash
# 1. HTTPS 首页
curl -sI https://chat.instser.cn/ | head -5

# 2. 静态资源命中CDN缓存

# 期望 X-Cache: HIT

# 3. API 连通(未登录 401,说明请求打到后端)
curl -s -o /dev/null -w "%{http_code}\n" https://chat.instser.cn/api/models
# 期望 401

# 4. 登录测试
curl -s -X POST https://chat.instser.cn/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"usernameOrEmail":"testuser","password":"123456"}'
# 期望 200

# 5. SSE 流式(关键!确认没被CDN buffer)
curl -N -X POST https://chat.instser.cn/api/chat \
  -H "Authorization: Bearer $TOKEN" \
  -H "Cookie: auth-token=$TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":"你好"}],"modelId":"1"}'
# 期望:逐字流式输出,不是等很久一次性吐出

# 6. 管理后台
curl -sI https://chat.instser.cn/admin/ | head -3
# 期望 200
```

## 9. SSE 兼容性与后续优化

由于新公网机 80/443 不可用，当前架构**必须使用 CDN**（CDN 提供标准 443 入口，回源到 frps 的 9080）。

**SSE 流式是最大风险点**，联通后必须第一时间实测：
- 若普通 CDN 对 SSE buffer → 切阿里云 DCDN（支持长连接）或独立 API 子域名
- 独立 API 子域名方案：`api.chat.instser.cn` 单独配 CDN，`/api/` 完全透传
