## 1. 三机架构总览

本系统由**三台机器**组成，务必区分清楚：

```
用户浏览器
    │ HTTPS (443, 证书在CDN)
    ▼
┌──────────────────────────────────────────┐
│ 阿里云 CDN (chat.instser.cn)             │
│  - SSL 证书配在 CDN（用户走 443）         │
│  - 回源 HTTP → frps 公网机:9080           │
└──────────────────────────────────────────┘
    │ 回源 HTTP (9080端口)
    ▼
┌──────────────────────────────────────────┐
│ frps 公网服务器                           │
│  - 域名：home.example.com（DDNS 动态指向） │
│  - 公网 IP：动态（DDNS home.example.com）  │
│  - 跑 frps，暴露端口：9080→家用机80       │
│  - SSH 9001 也是 frp 穿透到家用机         │
│  - 不放任何业务，只做 TCP 中转            │
│  - 80/443 不可用，只能用 9000-9100 端口   │
└──────────────────────────────────────────┘
    │ frp TCP 隧道（家用机 frpc 主动连出）
    ▼
┌──────────────────────────────────────────┐
│ 家用服务器                               │
│  - 内网 IP：192.168.1.2                  │
│  - 无公网 IP（运营商级 NAT）             │
│  - 跑 frpc → 连接 frps 公网机             │
│  - Nginx :80（反代）                      │
│    ├─ /api/ → 后端 :8080 (SSE流式)        │
│    ├─ /admin/ → 静态                      │
│    └─ / → Next.js :3001                   │
│  - Java 后端 :8080 (supervisor)          │
│  - Redis :6379 / MySQL :3306             │
│  - 宝塔面板 :18842                        │
└──────────────────────────────────────────┘
```

### 三个域名的关系

| 域名 | 指向 | 作用 |
|---|---|---|
| `chat.instser.cn` | 阿里云 CDN | 用户访问入口（HTTPS 443） |
| `home.example.com` | frps 公网机（DDNS 动态公网 IP） | frp 中转 + CDN 回源地址 |
| （家用机本身无域名） | 内网 192.168.1.2 | 通过 frp 穿透对外 |

### 关键点

- **`home.example.com` 不是家用机**，是 DDNS 动态指向 frps 公网机的域名
- **`home.example.com:端口` 全部是 frp 穿透**，包括 9080（Nginx）和 9001（SSH）
- 家用机无公网 IP（运营商级 NAT），frpc 主动连出到 frps 建立隧道
- CDN 回源到 `home.example.com:9080` → frps → frp 隧道 → 家用机 Nginx :80
- frps 公网机 80/443 不可用，只能用 9000-9100 范围端口

## 3. 前端部署详情

### 3.1 用户前端（Next.js standalone）

- 源码：`/Users/instser/Downloads/tousechat-main/frontend`
- 构建：本地 Node v22.14.0（nvm）+ `node node_modules/next/dist/bin/next build`
- standalone 补齐：`.next/static`、`public`、`.env.production`
- 打包：`tar --no-xattrs -czf`（去 macOS 扩展属性）
- 部署目录：`/opt/tousechat-frontend/`
- 运行方式：systemd 服务 `tousechat-frontend-pub.service`
- 监听端口：3001（绑定 127.0.0.1）
- Node 路径：`/www/server/nodejs/v22.14.0/bin/node`

**systemd 服务文件**（`/etc/systemd/system/tousechat-frontend-pub.service`）：
```ini
[Unit]
Description=ToUse.Chat Frontend (Next.js standalone)
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/tousechat-frontend
Environment=NODE_ENV=production
Environment=PORT=3001
Environment=HOSTNAME=127.0.0.1
ExecStart=/www/server/nodejs/v22.14.0/bin/node server.js
Restart=on-failure
RestartSec=5
StandardOutput=append:/var/log/tousechat-frontend.log
StandardError=append:/var/log/tousechat-frontend.log

[Install]
WantedBy=multi-user.target
```

### 3.2 管理员前端（admin-web）

- 源码：本仓库 `admin-web/`（Vue3 + Vite，`base: '/admin/'`）
- 构建：本地 `npm run build`
- 部署目录：`/opt/tousechat-admin/`

### 3.3 Nginx 配置

文件：`/www/server/panel/vhost/nginx/chat.instser.cn.conf`

```nginx
server {
    listen 80;
    server_name chat.instser.cn home.example.com;
    client_max_body_size 50m;

    # /api/ → 本机后端 8080（SSE 流式，不可 buffer）
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;
        proxy_cache off;
        proxy_set_header Connection '';
        chunked_transfer_encoding on;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
        proxy_connect_timeout 60s;
    }

    # 管理员后台 SPA
    location = /admin { return 302 /admin/; }
    location /admin/ {
        alias /opt/tousechat-admin/;
        index index.html;
        try_files $uri $uri/ /admin/index.html;
    }

    # Next.js 静态资源长缓存
    location /_next/static/ {
        proxy_pass http://127.0.0.1:3001;
        expires 365d;
        add_header Cache-Control "public, max-age=31536000, immutable";
    }

    # 用户前端
    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_buffering off;
        proxy_read_timeout 300s;
    }

    access_log /www/wwwlogs/chat.instser.cn.log;
    error_log /www/wwwlogs/chat.instser.cn.error.log;
}
```

`server_name` 包含 `home.example.com` 是为了方便直接访问 `home.example.com:9080` 验证（不经过 CDN）。

## 5. 踩坑记录

### 5.1 CDN 回源端口配成 80 → 504

**现象**：CDN 配好后首页能访问（缓存命中），但 `/api/` 和 `/manifest.json` 返回 504 Gateway Timeout（30 秒超时）。

**根因**：CDN 回源端口默认 80，但 `home.example.com:80` 不可达（frps 公网机 80/443 不可用，只能用 9000-9100 端口）。

**解决**：CDN 控制台 → 域名管理 → 回源配置 → 回源端口改成 `9080`。

### 5.2 直连 9080 返回 404

**现象**：浏览器直接访问 `home.example.com:9080` 返回 404。

**根因**：Nginx `server_name` 只匹配 `chat.instser.cn`，浏览器 Host 头是 `home.example.com:9080`，不匹配 → 走默认 server → 404。

**解决**：`server_name` 加上 `home.example.com`。但 `home.example.com:9080` 只是验证用，用户实际访问 `https://chat.instser.cn`（CDN 回源 Host 是 `chat.instser.cn`）。

### 5.3 home.example.com 不是家用机

**教训**：`home.example.com` 是 DDNS 动态指向 **frps 公网机**的域名，不是家用机本身。`home.example.com:端口` 全部是 frp 穿透到家用机。家用机本身无公网 IP（运营商级 NAT），内网 192.168.1.2。

## 8. SSE 流式与后续优化

`/api/chat` 是 SSE 流式响应。阿里云普通 CDN 对 `text/event-stream` 的处理：
- `/api/` 配置了"不缓存"，CDN 每次透传回源
- 若 CDN buffer 导致流式变成"一次性吐完" → 切 DCDN 或独立 API 子域名
- 独立 API 子域名方案：`api.chat.instser.cn` 单独配 CDN
