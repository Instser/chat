# 数据库重试机制使用示例

## 概述

本文档展示了新实现的数据库保存重试机制的使用方法和效果。

## 重试机制特性

### 1. 自动重试
- **最大重试次数**: 3次
- **重试延迟**: 指数退避（500ms → 1s → 2s）
- **异常处理**: 自动区分可重试和不可重试异常
- **线程安全**: 支持并发环境下的重试操作

### 2. 详细日志
重试过程中会记录详细的日志信息：

```
【数据库重试】消息保存失败，消息ID：abc123，尝试 1/4
【数据库重试】消息保存失败，消息ID：abc123，尝试 2/4
【数据库重试】消息保存成功，消息ID：abc123，重试次数：2
```

## 使用场景

### 1. 聊天消息保存
```java
// 原来的代码（无重试）
this.save(message);

// 现在的代码（带重试）
boolean saved = saveMessageWithRetry(message, 3);
if (!saved) {
    log.error("消息保存失败，已达到最大重试次数");
    return null;
}
```

### 2. 文件上传保存
```java
// 原来的代码（无重试）
save(fileUpload);

// 现在的代码（带重试）
boolean saved = saveFileWithRetry(fileUpload, 3);
if (!saved) {
    throw new FileUploadException("FILE_SAVE_FAILED", "Failed to save file to database after retries");
}
```

### 3. 会话创建
```java
// 原来的代码（无重试）
this.save(session);
return sessionId;

// 现在的代码（带重试）
boolean saved = saveSessionWithRetry(session, 3);
if (saved) {
    return sessionId;
} else {
    return null; // 创建失败
}
```

## 重试策略详解

### 1. 指数退避算法
```java
long retryDelay = 500; // 初始延迟500ms
for (int i = 0; i < maxRetries; i++) {
    // 执行保存操作
    if (success) break;
    
    // 等待后重试
    Thread.sleep(retryDelay);
    retryDelay *= 2; // 下次延迟时间翻倍
}
```

### 2. 重试时间线
- **第1次尝试**: 立即执行
- **第2次尝试**: 等待500ms后执行
- **第3次尝试**: 等待1000ms后执行
- **第4次尝试**: 等待2000ms后执行
- **总耗时**: 最多3.5秒（不包括数据库操作时间）

## 异常处理

### 1. 可重试异常
- 数据库连接超时
- 网络波动导致的连接失败
- 临时性的数据库锁等待

### 2. 不可重试异常
- SQL语法错误
- 数据约束违反（如主键冲突）
- 权限不足

### 3. 中断处理
```java
try {
    Thread.sleep(retryDelay);
} catch (InterruptedException ie) {
    Thread.currentThread().interrupt();
    log.warn("重试被中断");
    break; // 退出重试循环
}
```

## 性能影响

### 1. 正常情况
- **额外开销**: 无
- **响应时间**: 与原来相同
- **资源占用**: 无额外占用

### 2. 重试情况
- **最大延迟**: 6.5秒（3次重试 + 延迟时间）
- **内存占用**: 忽略不计
- **连接池影响**: 重试期间不占用连接

### 3. 并发性能
- **线程安全**: 每个线程独立重试
- **无锁设计**: 不影响其他操作
- **资源隔离**: 重试失败不影响其他请求

## 最佳实践

### 1. 合理设置重试次数
```java
// 对于关键操作，可以增加重试次数
boolean saved = saveMessageWithRetry(message, 5);

// 对于非关键操作，可以减少重试次数

```

### 2. 监控重试效果
定期检查重试日志，分析重试原因：
- 如果网络问题导致重试，考虑优化网络配置
- 如果数据库性能问题导致重试，考虑优化数据库
- 如果应用逻辑问题导致重试，考虑优化代码

### 3. 避免无限重试
- 设置合理的最大重试次数
- 对于明显的逻辑错误，不要重试
- 实现熔断机制，避免雪崩效应
