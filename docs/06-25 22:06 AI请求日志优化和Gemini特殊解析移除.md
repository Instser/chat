# AI请求日志优化和Gemini特殊解析移除

**📅 完成时间**: 2025-06-25 22:06:00  
**👤 开发人员**: Augment Agent  
**📊 文档版本**: v1.0  
**🔧 功能类型**: 系统优化

## 功能概述

优化AI请求的日志记录机制，在每次进行AI请求之前输出详细的请求信息，提示词保留前15和后15个字符。同时移除chat请求中对Google Gemini API的特殊格式解析逻辑，统一按照Vercel AI SDK格式解析。

## 修改内容

### 1. ChatServiceImpl 优化

**修改位置**: `src/main/java/com/instser/chat/service/serviceimpl/ChatServiceImpl.java`

#### 主要变更：
- 添加 `logAiRequestDetails` 方法，记录详细的AI请求信息
- 添加 `logAiTitleRequestDetails` 方法，记录AI标题生成请求信息
- 添加 `truncateContent` 方法，截取内容保留前15和后15个字符
- 移除 `isGeminiApi` 变量和相关的Gemini特殊处理逻辑
- 修改 `processCompleteJson` 方法，移除 `isGeminiApi` 参数

#### 新增日志功能：
```java
/**
 * 记录详细的AI请求信息
 */
private void logAiRequestDetails(List<Map<String, String>> messages, AiModel model, Long userId) {
    log.info("=== AI请求详细信息 ===");
    log.info("用户ID: {}", userId);
    log.info("模型: {} ({})", model.getModelCode(), model.getBaseUrl());
    log.info("消息总数: {}", messages.size());
    
    // 记录每条消息的详细信息，提示词截取显示
    for (int i = 0; i < messages.size(); i++) {
        Map<String, String> message = messages.get(i);
        String role = message.get("role");
        String content = message.get("content");
        
        if (content != null) {
            String truncatedContent = truncateContent(content);
            log.info("消息[{}] - 角色: {}, 内容: {}", i + 1, role, truncatedContent);
        }
    }
    
    log.info("=== AI请求信息结束 ===");
}
```

#### 内容截取功能：
```java
/**
 * 截取内容，保留前15和后15个字符
 */
private String truncateContent(String content) {
    if (content == null) {
        return "null";
    }
    
    if (content.length() <= 30) {
        return content;
    }
    
    String prefix = content.substring(0, 15);
    String suffix = content.substring(content.length() - 15);
    return prefix + "..." + suffix + " (总长度: " + content.length() + "字符)";
}
```

## 功能特点

### 1. 详细的请求日志
- 记录用户ID、模型信息、消息总数
- 显示每条消息的角色和内容摘要

- 简化代码逻辑，提高可维护性

### 4. 全面的日志覆盖
- 聊天请求的AI调用
- 标题生成的AI调用
- OpenAI服务的AI调用

## 技术细节

### 1. 日志级别
- 使用 `INFO` 级别记录请求概要信息
- 使用 `DEBUG` 级别记录响应处理详情
- 使用 `WARN` 级别记录日志记录失败

### 2. 性能考虑
- 日志记录方法包含异常处理，避免影响主流程
- 内容截取操作轻量级，性能影响微乎其微
- 只在请求前记录，不影响响应处理性能

### 3. 安全考虑
- 提示词内容截取显示，避免完整敏感信息泄露
- 保留足够信息用于调试和问题排查
- 记录总长度信息便于分析请求规模
