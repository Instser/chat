# 运维监控 AI 时间刻度 v1.0

- 时间：2026-08-06 15:06（北京时间）
- 范围：管理后台运维监控 AI 调用 / TTFT

## 原状说明

此前 AI 调用与 TTFT **不是「每日」图**，而是：

- 读 Micrometer 进程内累计 Counter/Timer
- 无时间轴、无 1d/7d/30d 过滤
- 进程重启即清零

用户看到的柱/饼是「当前 JVM 存活期间累计」，容易误解为日统计。

## 需求

页面可选时间刻度：近 1 日 / 近 7 日 / 近 30 日 / 长期（进程累计）。

## 实现

### 后端

1. 新增 `AiCallWindowStore`：按**小时桶**记录成功/失败/TTFT/总耗时，最长保留 30 天。
2. `AiCallMetrics.recordSuccess/Failure` 同步写入窗口桶。
3. `GET /api/admin/ops/monitoring?range=1d|7d|30d|all`
   - `1d/7d/30d`：窗口聚合 + timeline（1d 按小时，7d/30d 按日）
   - `all`：仍读 Micrometer 进程累计（无 timeline）
4. 支付窗口随 range 对齐（1/7/30 日；all 仍 7 日业务统计）。

### 前端

- 顶部 radio：近1日 / 近7日 / 近30日 / 进程累计
- 新增「AI 调用趋势」图
- 成功失败饼图、模型 TTFT 图标题显示当前刻度
- 文案标明数据来源（小时桶窗口 vs Micrometer 累计）

## 限制（需知悉）

- 窗口数据仍是**进程内**，重启后从 0 开始积累；不是 Prometheus/DB 长期时序。
- 发版重启后，近 7/30 日窗口在新进程里只会逐渐填满。
- 真·跨重启长期历史需接 Prometheus + Grafana，或落库事件表。

## 验收

- 接口：`range=1d/7d/30d/all` 均 200，返回 `ai.source` / `timeline`
- 页面：切换刻度会重新请求并刷新图
- 单测：`AiCallWindowStoreTest` + 相关 metrics 测试通过
