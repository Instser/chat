# 06-26 14:11 聊天中断功能完整设计方案

## 📋 功能概述

实现用户在AI流式响应过程中主动中断聊天，并将已接收的部分响应保存到数据库的完整功能。

## 🏗️ 系统架构

### 后端架构组件

#### 1. ChatInterruptService (会话中断服务)
- **职责**: 管理活跃会话状态，处理中断请求
- **核心功能**:
  - 注册活跃会话 (`registerActiveSession`)
  - 中断聊天会话 (`interruptChat`)
  - 检查中断状态 (`isInterrupted`)
  - 标记会话完成 (`markSessionCompleted`)
  - 清理超时会话 (`cleanupTimeoutSessions`)

#### 2. ChatApiController (中断接口)
- **接口**: `POST /chat/stop`
- **参数**: `{"sessionId": "会话ID"}`
- **功能**: 接收前端中断请求，验证用户权限，执行中断操作

#### 3. 流式响应中断机制
- **位置**: `ChatServiceImpl.streamChatWithAI`方法
- **实现**: 在WebClient的`doOnNext`回调中检查中断标志
- **处理**: 检测到中断时保存部分内容并发送中断完成标记

#### 4. 定时清理任务
- **配置**: `ChatInterruptConfig`类
- **频率**: 每5分钟执行一次
- **功能**: 清理超时会话（30分钟超时）

## 🔄 工作流程

### 1. 聊天开始流程
```
用户发送聊天请求 
    ↓
注册活跃会话 (registerActiveSession)
    ↓
开始流式AI响应处理
    ↓
在每个数据块处理时检查中断标志
```

### 2. 中断处理流程
```
用户点击停止按钮
    ↓
前端发送中断请求 (POST /chat/stop)
    ↓
验证用户权限和会话状态
    ↓
设置中断标志 (interruptFlags.put(sessionId, true))
    ↓
流式处理检测到中断标志
    ↓
保存已接收的部分内容 (savePartialAiResponse)
    ↓
发送中断完成标记给前端
    ↓
清理会话状态 (markSessionCompleted)
```

### 3. 正常完成流程
```
AI响应完成
    ↓
发送正常完成标记
    ↓
清理会话状态 (markSessionCompleted)
```

## 🛡️ 安全机制

### 1. 用户权限验证
- 验证会话是否属于当前用户
- 防止越权中断他人会话
- 认证失败时返回明确错误信息

### 2. 并发安全
- 使用`ConcurrentHashMap`确保线程安全
- 原子性操作避免竞态条件
- 会话状态的一致性保证

### 3. 内存管理
- 定时清理超时会话防止内存泄漏
- 会话超时时间设为30分钟
- 异常情况下的状态清理机制

### 4. 错误处理
- 中断失败不影响正常聊天功能
- 完善的异常处理和日志记录
- 优雅降级机制
