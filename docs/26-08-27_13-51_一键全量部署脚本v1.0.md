## 背景

此前后端/管理前端的每次部署都依赖手工敲一长串命令（构建 → scp → 备份替换 → supervisor 重启 → 健康检查），来自 `docs/26-08-26_12-42` 部署文档与 2026-08-27 VL 模型部署实战。现固化为项目内脚本 `scripts/deploy.sh`，实现一键部署 + 一键回滚 + 只读预检。

## 文件

- `scripts/deploy.sh`（可执行，bash，macOS 开发机 bash 3.2 兼容）

## 用法速查

```bash
./scripts/deploy.sh                    # 等价于 backend
./scripts/deploy.sh backend            # 仅后端（默认动作）
./scripts/deploy.sh admin              # 仅管理员前端
./scripts/deploy.sh frontend           # 仅用户前端（独立仓库 tousechat/frontend）
./scripts/deploy.sh all                # 后端 + 管理员前端
./scripts/deploy.sh all-with-frontend  # 后端 + 管理员前端 + 用户前端
./scripts/deploy.sh preflight          # 只读预检：本地工具链 + 远端服务器状态（不改任何东西）
./scripts/deploy.sh list-backups       # 查看远端现有备份清单（只读）
./scripts/deploy.sh rollback backend   # 回滚后端到最近一次备份
./scripts/deploy.sh rollback admin     # 回滚管理前端到最近一次备份
./scripts/deploy.sh rollback frontend  # 回滚用户前端到最近一次备份
# 可组合参数：--skip-build（复用现有产物） / --dry-run（只打印计划）/ --yes（跳过回滚确认）
```

## 用户前端（frontend 动作）要点

- 本地仓库：`/Users/instser/Sync/Instser-code/git/tousechat/frontend`（`DEPLOY_FRONTEND_DIR` 可覆盖）
- 构建：nvm Node v22.14.0 + `node node_modules/next/dist/bin/next build`；缺 next 时先 `corepack pnpm install --frozen-lockfile`
- standalone 补齐（按 Next 文档）：`.next/static`→standalone 内、`public`、`.env.production`
- 打包 `tar --no-xattrs`（去 macOS 扩展属性）+ 上传 MD5 校验
- 远端 `/opt/tousechat-frontend` 整目录替换（先 `systemctl stop` 防 ETXTBSY），替换后 `chown -R root:root`
- 服务：systemd `tousechat-frontend-pub.service`，监听 3001，日志 `/var/log/tousechat-frontend.log`
- 健康检查：服务 active + 本机 `127.0.0.1:3001`=200 + 公网首页=200
- 回滚：stop → 当前另存 `*.preroll.<ts>` → 恢复备份 → start → 同套健康检查

## 固化进脚本的实际部署经验

| 经验点 | 脚本内对应 |
|---|---|
| **scp 端口是大写 `-P`**（ssh 才是小写 `-p`）；v1.0 曾写错，frontend 首次真实部署才暴露 | 独立 `SCP_OPTS(-P $SSH_PORT ...)`，三处上传统一使用 |

| 经验点 | 脚本内对应 |
|---|---|
| 本机 JDK17 路径 `/Library/Java/JavaVirtualMachines/jdk-17.jdk`，mvn 用 homebrew | 构建段 `JAVA_HOME=$JAVA_HOME_17 $MVN_BIN clean package` |
| 后端单测编译有存量错误（测试类未同步 `OpenAiCompatibleChatClient` 新构造器），历次生产部署均跳过测试编译 | 固定 `-Dmaven.test.skip=true` |
| 宝塔 supervisor 不在 PATH，全路径 `/www/server/panel/pyenv/bin/supervisorctl` | `REMOTE_SUPCTL` 默认值 + preflight 校验存在性 |
| SSH 经 frps 公网机 DDNS：`ssh -p 9001 Instser@users.noreply.github.com`（key 认证） | `SSH_OPTS(-p 9001 -o BatchMode=yes)` |
| 112M jar 上传可能损坏（frp 链路）| 上传后本地 `md5 -q` 与远端 `md5sum` 比对，不一致即中止并清理 |
| 单个 jar 备份 112M，远端已积压 6 个（~670M，见 list-backups 实测） | 每次部署自动清理旧备份，仅保留最近 `BACKUP_KEEP=3` 份 |
| 替换后属主必须 `www:www / 644` | `install -o www -g www -m 644` |
| 必须严格 stop 并确认 8080 真正释放后再 start（防端口残留假启动） | 轮询 ≤15s `ss -tlnp` 确认释放，超时即失败退出 |
| 应用启动 ~18-20s 才可服务 | 健康检查最长 150s：8080 监听 + `GET /api/models` 应答 **401**；通过后再复核第二个接口 |
| 启动失败需要立刻看到原因 | 健康失败自动打印 error.log 最后 30 行，并提示回滚命令 |
| 需要"本次启动窗口"的 ERROR 统计而非全量日志 | stop 前记录 error.log 字节偏移，健康通过后对增量段计数（`ERROR_DELTA=N`）|
| 管理前端替换需保留权限且历史误删风险 | `cp -a` 整站备份 → 清空目录 → 解压 → `chown -R www:www`，备份同样保留 3 份 |
| 回滚时当前版本不能丢 | 回滚前先另存当前为 `*.preroll.<ts>` 再覆盖恢复，随后走同一套健康检查 |

## 关键设计

- **模板注入**：所有远端脚本以带引号 heredoc 书写（`$` 保持远端求值），本地配置经 `render_stdin()` 以 `__TOKEN__` 占位符替换后由管道送入 `remote_run` → `ssh 'bash -s' 位置参数`；避免引号嵌套地狱。
- **测试友好**：直接执行进入主流程；被 `source` 或 `export DEPLOY_LIB_MODE=1` 时只加载函数不派发，便于 mock 测试（macOS bash 3.2 管道子 shell 无法回传变量，mock 测试须用临时文件捕获）。
- **DRY-RUN**：`--dry-run` 全程零网络、零构建、零改动，打印每一步计划。
- **预检**：`preflight` 与 `list-backups` 为纯只读动作，可在任意时间安全执行。
- **环境变量全覆盖**：`DEPLOY_SSH_HOST/PORT/USER`、`DEPLOY_SUPCTL/BACKEND_DIR/LOG_DIR/ADMIN_DIR`、`DEPLOY_JAVA_HOME/MVN`、`DEPLOY_BACKUP_KEEP`、`DEPLOY_HEALTH_TIMEOUT` 等均可覆盖默认。
