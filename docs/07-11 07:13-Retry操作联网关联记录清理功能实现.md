## 需求背景

在retry操作中，如果用户没有开启联网搜索（`network=false`或`network=null`），但用户消息之前有联网关联记录，应该删除这些联网关联记录，确保数据的一致性。

### 场景描述
1. **用户首次发送消息**：启用了联网搜索，系统保存了联网查询结果
2. **用户进行retry操作**：没有启用联网搜索
3. **期望行为**：删除之前的联网关联记录，清理不再需要的数据

## 功能实现

### 1. 核心逻辑

在retry操作的联网搜索处理部分，添加了对未启用联网搜索情况的处理：

```java
// 处理联网搜索内容（如果启用）
List<TavilySearchResult> retrySearchResults = new ArrayList<>();
if (network != null && network) {
    // 启用联网搜索的处理逻辑...
} else {
    log.debug("重试请求没有启用联网搜索");
    
    // 如果没有启用联网搜索，检查用户消息是否有联网关联记录，如果有则删除
    if (lastUserMessage != null) {
        WebSearchContent existingWebSearch = webSearchContentService.getByMessageId(lastUserMessage.getMessageId());
        if (existingWebSearch != null) {
            // 删除联网关联记录
            boolean deleted = webSearchContentService.deleteByMessageId(lastUserMessage.getMessageId());
            if (deleted) {
                // 更新消息的联网标记为false
                chatMessageService.updateWebSearchFlag(lastUserMessage.getMessageId(), false);
            }
        }
    }
}
```

### 2. 实现细节

#### 2.1 检查现有联网关联
- 使用`webSearchContentService.getByMessageId()`检查用户消息是否有联网关联记录
- 只有存在联网关联记录时才进行删除操作

#### 2.2 删除联网关联记录
- 调用`webSearchContentService.deleteByMessageId()`删除联网内容记录
- 使用逻辑删除，数据可恢复

#### 2.3 更新消息标记
- 删除成功后，调用`chatMessageService.updateWebSearchFlag(messageId, false)`
- 将消息的`has_web_search`字段设置为0，表示不再使用联网查询

#### 2.4 日志记录
- 详细记录操作过程和结果
- 使用统一的`【联网存储】`前缀
- 区分INFO、WARN、ERROR级别

### 3. 错误处理

#### 3.1 异常隔离
- 所有操作都有独立的try-catch块
- 异常不会影响retry操作的主流程
- 记录详细的异常信息便于调试

#### 3.2 操作失败处理
- 删除失败时记录警告日志
- 标记更新失败时记录错误日志
- 不影响AI回复的生成
