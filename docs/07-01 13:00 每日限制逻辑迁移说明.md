# 每日限制逻辑迁移说明

**📅 迁移时间**: 2025-07-01 13:00:00  
**👤 迁移人员**: Augment Agent  
**📊 文档版本**: v1.0  
**🎯 迁移目标**: 从daily_chat_limit字段迁移到model_permissions配置

## 📋 迁移概述

系统的每日聊天限制逻辑已经从使用 `daily_chat_limit` 字段迁移到基于 `model_permissions` JSON配置的模型维度限制管理。

## 🔄 变更内容

### 1. 限制来源变更

#### 之前的逻辑
```java
// 从套餐表的 daily_chat_limit 字段获取限制
int dailyLimit = packageInfo.getDailyChatLimit();
```

#### 现在的逻辑
```java
// 从套餐表的 model_permissions JSON配置中获取特定模型的限制
Map<String, Package.ModelPermission> modelPermissions = packageInfo.getModelPermissionsMap();
Package.ModelPermission permission = modelPermissions.get("STANDARD");
int dailyLimit = permission != null ? permission.getDailyLimit() : 0;
```

### 2. 方法迁移

#### UserDailyUsageServiceImpl 变更

**canChatToday() 方法**
```java
// 旧实现：复杂的套餐验证逻辑
@Override
public boolean canChatToday(Long userId, Long packageId) {
    // 大量的套餐验证和限制检查代码...
}

// 新实现：委托给模型维度的方法
@Override
public boolean canChatToday(Long userId, Long packageId) {
    // 为了向后兼容，默认使用STANDARD模型
    return canChatWithModel(userId, packageId, "STANDARD");
}
```

**recordChatUsage() 方法**
```java
// 旧实现：使用 packageInfo.getDailyChatLimit()
@Override
@Transactional
public boolean recordChatUsage(Long userId, Long packageId) {
    // 使用 packageInfo.getDailyChatLimit() 的逻辑...
}

// 新实现：委托给模型维度的方法
@Override
@Transactional
public boolean recordChatUsage(Long userId, Long packageId) {
    // 为了向后兼容，默认使用STANDARD模型
    return recordModelChatUsage(userId, packageId, "STANDARD");
}
```

**getRemainingChatsToday() 方法**
```java
// 旧实现：使用 packageInfo.getDailyChatLimit()
@Override
public int getRemainingChatsToday(Long userId, Long packageId) {
    // 使用 packageInfo.getDailyChatLimit() 的逻辑...
}

// 新实现：委托给模型维度的方法
@Override
public int getRemainingChatsToday(Long userId, Long packageId) {
    // 为了向后兼容，默认使用STANDARD模型
    return getRemainingModelChats(userId, packageId, "STANDARD");

```

#### ChatLimitServiceImpl 变更

**validateDailyLimit() 方法**
```java
// 旧实现：使用 packageInfo.getDailyChatLimit()
private ChatLimitVO validateDailyLimit(Long userId, Long packageId, Package packageInfo, ChatLimitVO result) {
    // ...
    result.setDailyLimit(packageInfo.getDailyChatLimit());
    // ...
}

// 新实现：从模型权限配置获取
private ChatLimitVO validateDailyLimit(Long userId, Long packageId, Package packageInfo, ChatLimitVO result) {
    // 从模型权限配置中获取STANDARD模型的限制
    Map<String, Package.ModelPermission> modelPermissions = packageInfo.getModelPermissionsMap();
    Package.ModelPermission standardPermission = modelPermissions.get("STANDARD");
    int dailyLimit = standardPermission != null ? standardPermission.getDailyLimit() : 0;
    
    result.setDailyLimit(dailyLimit);
    // ...
}
```

## 🎯 向后兼容策略

### 1. 默认模型映射
- 所有原有的聊天限制检查都映射到 `STANDARD` 模型
- 保持现有API接口的行为不变
- 用户无感知的平滑迁移

### 2. 配置兼容
- 如果 `model_permissions` 为空或解析失败，使用默认配置
- 默认配置基于 `package_type` 字段生成

### 3. 数据库兼容
- `daily_chat_limit` 字段保留，但不再使用
- 新的限制完全来自 `model_permissions` JSON配置

## 📊 配置映射关系

### 套餐类型与STANDARD模型限制的映射

| 套餐类型 | daily_chat_limit (旧) | STANDARD模型限制 (新) |
|---------|----------------------|---------------------|
| basic   | 根据具体配置          | 300次/天            |
| medium  | 根据具体配置          | 500次/天            |
| high    | 根据具体配置          | 无限制 (-1)         |

### JSON配置示例
```json
{
  "STANDARD": {
    "daily_limit": 300,
    "description": "标准模型每日300次"
  },
  "PERFORMANCE": {
    "daily_limit": 20,
    "description": "性能模型每日20次"
  },
  "BETA_MODEL": {
    "daily_limit": 5,
    "description": "测试模型每日5次"
  }
}
```
