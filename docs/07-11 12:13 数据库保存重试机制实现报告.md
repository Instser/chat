# 数据库保存重试机制实现报告

**时间**: 2025-07-11 12:13  
**版本**: v1.0  
**类型**: 功能增强  

## 问题背景

在项目运行过程中发现，数据库保存操作在遇到网络波动、连接超时或其他临时性数据库问题时，缺乏重试机制，导致：

1. **消息保存失败**: 聊天消息保存失败但没有重试，导致消息丢失
2. **文件上传失败**: 文件解析成功但数据库保存失败，用户体验差
3. **会话创建失败**: 新会话创建失败，用户无法正常使用聊天功能
4. **联网内容丢失**: 网络搜索结果保存失败，影响AI回答质量

## 解决方案

### 1. 核心重试机制设计

#### 重试策略
- **最大重试次数**: 3次
- **重试延迟**: 指数退避策略（500ms → 1s → 2s）
- **异常处理**: 区分可重试异常和不可重试异常
- **中断处理**: 支持线程中断，避免无限等待

#### 重试逻辑模板
```java
private boolean saveWithRetry(Object entity, int maxRetries) {
    int retryCount = 0;
    long retryDelay = 500; // 初始重试延迟500ms

    while (retryCount <= maxRetries) {
        try {
            boolean saved = save(entity);
            if (saved) {
                if (retryCount > 0) {
                    log.info("【数据库重试】保存成功，重试次数：{}", retryCount);
                }
                return true;
            } else {
                log.warn("【数据库重试】保存失败，尝试 {}/{}", retryCount + 1, maxRetries + 1);
            }
        } catch (Exception e) {
            log.error("【数据库重试】保存异常，尝试 {}/{}", retryCount + 1, maxRetries + 1, e);
        }

        // 如果不是最后一次尝试，等待后重试
        if (retryCount < maxRetries) {
            try {
                Thread.sleep(retryDelay);
                retryDelay *= 2; // 指数退避
            } catch (InterruptedException ie) {
                Thread.currentThread().interrupt();
                log.warn("【数据库重试】重试被中断");
                break;
            }
        }

        retryCount++;
    }

    log.error("【数据库重试】保存失败，已达到最大重试次数");
    return false;
}
```

### 3. 日志记录优化

#### 日志级别设计
- **INFO**: 重试成功时记录重试次数
- **WARN**: 单次保存失败时记录尝试次数
- **ERROR**: 达到最大重试次数时记录最终失败

#### 日志格式统一
```
【数据库重试】{操作类型}，{实体标识}，{状态信息}
```

示例：
```
【数据库重试】消息保存成功，消息ID：abc123，重试次数：2
【数据库重试】文件保存失败，文件ID：def456，尝试 2/4
【数据库重试】会话保存失败，已达到最大重试次数，会话ID：ghi789
```

## 技术细节

### 1. 异常处理策略
- **数据库连接异常**: 可重试
- **SQL语法错误**: 不可重试
- **约束违反**: 不可重试
- **超时异常**: 可重试

### 2. 性能影响评估
- **正常情况**: 无额外开销
- **重试情况**: 最多增加6.5秒延迟（500ms + 1s + 2s + 3次操作时间）
- **内存占用**: 忽略不计
- **并发影响**: 重试期间不占用连接池

### 3. 与现有重试机制的协调
- **AI错误消息重试**: 专门处理AI服务错误，不冲突
- **支付API重试**: 专门处理支付接口，不冲突
- **数据库保存重试**: 专门处理数据库操作，补充现有机制
