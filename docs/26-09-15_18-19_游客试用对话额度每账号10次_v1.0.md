# 游客试用对话额度（每账号 10 次）v1.0

**日期**：2026-09-15 18:19（北京时间）
**状态**：已完成开发与编译验证，**待部署**
**变更范围**：仅后端，无 DB/依赖/前端变更

## 一、需求与语义（已与用户确认）

为游客试用增加对话额度限制，语义：

- **每个游客账号共 10 次对话额度，续登不重置**（携带 guestId 续登保留聊天记录的同时延续剩余额度），用完引导注册
- **AI 成功回复计 1 次**：失败/未产生真实 AI 回复的请求不扣额度，与现有套餐扣减时机一致（`AiResponseCompletionHandler` 完成副作用中 `isRealAiResponse` 时记录）
- 次数可配置：`TRIAL_CHAT_LIMIT`（默认 10）

## 二、设计

游客身份识别：`t_user.username` 以 `guest_` 前缀（`trial.username-prefix`）开头。额度计数独立于套餐体系——游客不再消耗套餐（ID=1 默认套餐）次数，只受固定额度约束，行为确定、不受套餐配置影响：

| 环节 | 改动 |
|---|---|
| 计数存储 | Redis `trial:chat:used:{userId}`（INCR 原子递增，首写设 7 天 TTL；游客 48h 未活跃软删，计数稍后自然过期） |
| 身份缓存 | Redis `trial:guest:flag:{userId}`（10 分钟，避免每请求查库） |
| 校验入口 | `ChatLimitServiceImpl.validateChatPermission` / `validateModelChatPermission` 游客分支优先于套餐校验 |
| 扣减入口 | `ChatLimitServiceImpl.recordChatUsage` / `recordModelChatUsage` 游客分支：只扣试用额度、跳过套餐扣减 |
| 前置旁路 | `ChatRateLimitServiceImpl.checkDailyChatLimit` 游客直接放行（该检查先于权限校验执行，不以套餐语义提前拦截，保证游客看到试用额度提示；频率/IP 限流对游客照常生效） |
| 降级策略 | Redis 异常全部放行（与现有试用 IP 限流同策略），仅记日志 |

额度耗尽提示（直接面向用户展示的中文消息）：
`游客试用额度已用完（共X次），注册账号即可继续畅聊`

额度校验通过时 `ChatLimitVO` 返回 `limitType=total`、`totalRemaining=剩余次数`、`packageName=游客试用`，前端如有剩余次数展示位可直接呈现。

## 四、边界与行为说明

1. **重试/编辑重发**：每次成功 AI 回复计 1 次（与套餐口径一致）；中断但已有真实内容落库的回复按现有逻辑同样计数（`recordModelUsage && isRealAiResponse`，与套餐用户一致）
2. **存量游客**：部署后计数从 0 开始，即获得完整 10 次
3. **新游客**：新账号 = 新 10 次；同一 IP 每日激活上限 `TRIAL_PER_IP_DAILY_LIMIT`（10 次）不变，理论单 IP 每日上限 100 次对话
4. **游客转注册**：游客账号不会被"转正"，额度提示引导其注册新账号；试用清理任务（48h 软删）不变
5. **管理后台**：游客在用户列表中显示套餐仍为默认套餐（绑定关系未动），但实际聊天只受试用额度约束
