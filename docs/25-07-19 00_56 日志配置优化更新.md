# 07-19 00:56 日志配置优化更新

## 更新时间
2025年7月19日 00:56 (北京时间)

## 更新内容
优化项目的日志记录设置，实现普通日志文件记录所有内容，错误日志文件单独记录ERROR级别内容。

## 主要修改

### 1. 日志文件结构调整
- **普通日志文件**: `jinyu-chat-all.log` - 记录所有控制台输出的内容，不进行级别过滤
- **错误日志文件**: `jinyu-chat-error.log` - 记录WARN和ERROR级别的日志内容

### 2. 配置文件修改 (`src/main/resources/logback-spring.xml`)

#### 普通日志文件配置 (ALL_FILE)
```xml
<!-- 普通日志文件输出 - 记录所有控制台输出的内容，不进行级别过滤 -->
<appender name="ALL_FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
    <file>${LOG_HOME}/${APP_NAME}-all.log</file>
    <!-- 不设置任何级别过滤器，记录所有通过日志级别控制的内容 -->
    <!-- 滚动策略: 100MB单文件，保留15天，总大小2GB -->
</appender>
```

#### 错误日志文件配置 (ERROR_FILE)
```xml
<!-- 错误日志单独输出 - 记录ERROR和WARN级别 -->
<appender name="ERROR_FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
    <file>${LOG_HOME}/${APP_NAME}-error.log</file>
    <!-- 记录WARN及以上级别的日志（WARN和ERROR） -->
    <filter class="ch.qos.logback.classic.filter.ThresholdFilter">
        <level>WARN</level>
    </filter>
    <!-- 滚动策略: 50MB单文件，保留30天，总大小1GB -->
</appender>
```

#### 异步日志配置
- **ASYNC_ALL_FILE**: 异步处理普通日志，队列大小1024
- **ASYNC_ERROR_FILE**: 异步处理错误日志，队列大小256
- 设置 `discardingThreshold=0` 确保不丢失任何日志

### 3. 日志级别配置
- **应用日志**: `com.instser.chat` 默认INFO级别
- **第三方库**: 适当调整日志级别，减少噪音
- **SQL日志**: 默认ERROR级别，可通过启动参数开启DEBUG

### 4. 文件命名规则
- 普通日志: `jinyu-chat-all-yyyy-MM-dd-i.log`
- 错误日志: `jinyu-chat-error-yyyy-MM-dd-i.log`

## 配置特点

### 1. 分离式日志记录
- 普通日志文件记录所有控制台输出的内容，不进行级别过滤
- 错误日志文件记录WARN和ERROR级别的日志
- 日志级别完全由启动参数控制，灵活性更高
- 便于问题排查和日志分析

### 2. 优化的存储策略
- 普通日志: 单文件100MB，保留15天，总大小2GB
- 错误日志: 单文件50MB，保留30天，总大小1GB
- 错误日志保留时间更长，便于问题追踪

### 3. 异步处理
- 使用异步appender提高性能
- 设置合适的队列大小
- 确保不丢失重要日志信息

### 4. 灵活的级别控制
- 支持通过启动参数动态调整日志级别
- 可以单独控制不同模块的日志级别
- 便于开发和生产环境的不同需求

## 使用说明

### 1. 日志文件位置
```
logs/
├── jinyu-chat-all.log          # 当前普通日志文件（所有控制台输出）
├── jinyu-chat-all-2025-07-19-0.log  # 历史普通日志文件
├── jinyu-chat-error.log        # 当前错误日志文件（WARN和ERROR级别）
└── jinyu-chat-error-2025-07-19-0.log # 历史错误日志文件
```

### 2. 动态调整日志级别
```bash
# 开启DEBUG级别日志 - 普通日志文件会记录所有DEBUG及以上级别的日志
--logging.level.com.instser.chat=DEBUG

# 开启SQL日志 - 普通日志文件会记录SQL执行日志
--logging.level.com.instser.chat.dao=DEBUG

# 调整根日志级别 - 控制整体日志输出级别
--logging.level.root=WARN

# 只看ERROR日志 - 普通日志文件只会记录ERROR级别日志
--logging.level.root=ERROR
```

### 3. 监控和维护
- 定期检查日志文件大小和磁盘空间
- 根据需要调整保留天数和文件大小限制
- 可通过Actuator端点动态调整日志级别
