## 🔧 问题修复详情

### 根本原因分析
通过详细分析后端日志和PayPal API响应，确定问题根源：

**位置**: `PayPalService.java:161`  
**问题**: 代码只接受HTTP状态码201 CREATED，但PayPal API在幂等性重复请求时返回200 OK

**原始代码**:
```java
if (response.getStatusCode() == HttpStatus.CREATED) {
    // 处理成功响应
} else {
    // 抛出异常，导致订单创建失败
    throw ExternalServiceException.paymentServiceError("paypal", errorMsg);
}
```

### 修复方案

**修复代码**:
```java
// PayPal在创建新订单时返回201 CREATED，在幂等性重复请求时返回200 OK
if (response.getStatusCode() == HttpStatus.CREATED || response.getStatusCode() == HttpStatus.OK) {
    Map<String, Object> orderResponse = objectMapper.readValue(
        response.getBody(), new TypeReference<Map<String, Object>>() {});
    // ... 处理成功响应
} else {
    String errorMsg = "创建PayPal订单失败，状态码: " + response.getStatusCode() + 
                    ", 响应: " + response.getBody();
    log.error(errorMsg);
    throw ExternalServiceException.paymentServiceError("paypal", errorMsg);
}
```

**修复说明**:
1. **API行为理解**: PayPal REST API遵循幂等性原则，相同的请求ID会返回已存在的订单
2. **状态码处理**: 新订单返回201，重复请求返回200，两者都是成功状态
3. **向后兼容**: 修复不影响现有功能，只是扩展了成功状态码的范围

## 🔍 技术洞察

### PayPal API行为理解
1. **幂等性设计**: PayPal使用`PayPal-Request-Id`头确保请求幂等性
2. **状态码语义**: 
   - 201 CREATED: 新订单创建成功
   - 200 OK: 重复请求返回已存在订单
3. **响应一致性**: 无论200还是201，响应体结构完全相同

### 最佳实践总结
1. **状态码处理**: 对于外部API，应理解其完整的状态码语义
2. **幂等性支持**: 正确处理重复请求是分布式系统的基本要求
3. **错误诊断**: 详细的日志记录是快速问题定位的关键
