# 06-30 17:09 用户订单逻辑优化实施报告

## 📋 优化需求
优化用户发起订单逻辑：如果同一个用户在拥有一个进行中订单时，再发起一个新的订单，则直接将旧的订单作废，创建新的订单，并且保留频率限制。

## 🎯 实施目标
1. **自动作废旧订单**：用户发起新订单时，自动取消所有进行中的订单
2. **保留频率限制**：维持现有的支付频率限制机制
3. **保证数据一致性**：确保订单状态变更的原子性
4. **记录操作日志**：详细记录订单取消和创建的过程

## 🔧 技术实现

### 1. 数据库层优化

#### 新增Dao方法
```java
// UserOrderDao.java
@Update("UPDATE t_user_order SET payment_status = 2, update_time = NOW() " +
        "WHERE user_id = #{userId} AND payment_status = 0 AND expire_time > NOW() AND deleted = 0")
int cancelUserPendingOrders(Long userId);
```

**说明**：
- 只取消状态为0（未支付）且未过期的订单
- 使用数据库级别的原子操作保证一致性
- 自动更新update_time字段

### 2. 服务层扩展

#### OrderService接口扩展
```java
/**
 * 取消用户的所有待支付订单
 *
 * @param userId 用户ID
 * @return 取消的订单数量
 */
int cancelUserPendingOrders(Long userId);
```

#### OrderServiceImpl实现
```java
@Override
public int cancelUserPendingOrders(Long userId) {
    try {
        int cancelledCount = baseMapper.cancelUserPendingOrders(userId);
        if (cancelledCount > 0) {
            log.info("取消用户{}的{}个待支付订单", userId, cancelledCount);
        }
        return cancelledCount;
    } catch (Exception e) {
        log.error("取消用户{}的待支付订单异常", userId, e);
        return 0;
    }
}
```

### 3. 订单创建逻辑优化

#### 修改createOrder方法
在原有的订单创建逻辑中，在创建新订单前增加取消旧订单的步骤：

```java
// 【新增】检查并取消用户的进行中订单
int cancelledCount = cancelUserPendingOrders(userId);
if (cancelledCount > 0) {
    log.info("用户{}发起新订单，已取消{}个进行中的订单", userId, cancelledCount);
}
```

## 📊 订单状态说明

| 状态码 | 状态名称 | 说明 |
|--------|----------|------|
| 0 | 未支付 | 新创建的订单，等待支付 |
| 1 | 已支付 | 支付成功的订单 |
| 2 | 已取消 | 被取消的订单（包括过期和主动取消） |
| 3 | 已退款 | 已退款的订单 |

## 🔄 业务流程

### 优化前流程
```
用户发起支付 → 频率限制检查 → 创建订单 → 返回支付信息
```

### 优化后流程
```
用户发起支付 → 频率限制检查 → 取消进行中订单 → 创建新订单 → 返回支付信息
```

## 🛡️ 安全保障

### 1. 频率限制保留
- 保持现有的Redis频率限制机制
- 10分钟内最多5次支付请求
- 防重放攻击机制不变

### 2. 数据一致性
- 使用数据库原子操作
- 异常情况下的回滚机制
- 详细的操作日志记录

### 3. 并发安全
- 利用数据库的行级锁保证并发安全
- WHERE条件确保只操作符合条件的订单
