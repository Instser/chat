## 检查概述

根据用户反馈，不支持的文件类型依然返回错误码5001而不是5003，需要全面检查所有错误码的实现和映射是否正确。

## 问题分析

### 1. 文件上传错误码问题

**问题现象**:
```
2025-06-29 15:11:24.317 [http-nio-8080-exec-1] DEBUG c.i.c.s.s.FileUploadServiceImpl - 魔数检测文件类型: application/zip
2025-06-29 15:11:24.319 [http-nio-8080-exec-1] ERROR c.i.c.s.s.FileUploadServiceImpl - 文件上传失败：计算机辅助考试组卷系统的设计与实现(开通权限学校学生的所有文档).zip - File type not supported: application/zip
com.instser.chat.common.exception.FileUploadException: File type not supported: application/zip
上传不支持的文件类型依然报错5001
```

**问题根因**: 异常处理顺序有问题，`FileUploadException`被放在了错误的位置。

### 2. 异常处理顺序问题

**修改前的异常处理顺序**:
```java
} catch (IllegalArgumentException e) {
    // 第109-121行：处理IllegalArgumentException
} catch (IOException e) {
    // 第122-125行：处理IOException
} catch (FileUploadException e) {
    // 第126-128行：处理FileUploadException - 问题在这里！
} catch (Exception e) {
    // 第129-136行：处理其他异常
}
```

**问题**: 当我们直接抛出`FileUploadException`时，它应该被最先捕获，但是由于顺序问题，可能被其他catch块处理了。

## 修复方案

### 1. 调整异常处理顺序

将`FileUploadException`的处理放在最前面：

**修改后的异常处理顺序**:

### 2. 确保异常类型正确
