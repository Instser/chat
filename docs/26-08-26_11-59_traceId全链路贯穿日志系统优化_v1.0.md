# traceId 全链路贯穿日志系统优化

- **时间**: 2026-08-26 11:59 (北京时间)
- **版本**: v1.0
- **变更类型**: 日志诊断能力优化（traceId 跨线程贯穿）

## 一、问题

项目已有 traceId 机制（`TraceIdFilter` 在 HTTP 请求线程 MDC 放入 traceId，logback pattern `[%X{traceId}]` 输出），但**覆盖不完整**：只有 HTTP 请求线程有 traceId，所有异步/定时/Reactor 线程的 MDC 为空，日志输出空 `[]`。

生产日志证据：
```
2026-08-26 11:10:29.393 [boundedElastic-4] [] ERROR ...  ← 空 traceId
2026-08-26 11:13:25.527 [boundedElastic-5] [] ERROR ...  ← 空 traceId
```

根因：全项目只有 `TraceIdFilter` 一处 `MDC.put`，没有任何异步线程的 MDC 传递机制。

## 二、方案：三层 MDC 传递

### 第1层：@Async 线程池 — TaskDecorator

新建 `MdcTaskDecorator`（实现 Spring `TaskDecorator`），在提交任务时（提交线程）捕获 MDC 快照，在执行任务时（执行线程）恢复 MDC，执行完清理。

为全部 4 个线程池配置类的所有 `ThreadPoolTaskExecutor` 加 `executor.setTaskDecorator(new MdcTaskDecorator())`：
- `AsyncSecurityConfig` — `baseAsyncExecutor`、`sseBypassExecutor`
- `PerformanceOptimizationConfig` — `optimizedAsyncExecutor`、`highConcurrencyExecutor`、`ioIntensiveExecutor`
- `PaymentAsyncConfig` — `paymentCallbackExecutor`、`stripeWebhookExecutor`
- `ContinuationConfig` — `continuationExecutor`

覆盖：`@Async` 方法、`@EventListener + @Async` 事件监听器（走 @Async 线程池）。

### 第2层：@Scheduled 定时任务 — AOP

新建 `TraceIdScheduledAop`（`@Aspect`），`@Around("@annotation(Scheduled)")` 拦截所有定时任务，执行前生成独立 traceId 放入 MDC（若已有则复用），执行完清理。

覆盖：`@Scheduled` 定时任务（无父请求线程，生成独立 traceId 便于按次执行聚合）。

### 第3层：Reactor 异步链 — 入口捕获 + 回调恢复

新建 `ReactorMdcUtils` 工具类，提供 `captureTraceId()` 和 `runWithTraceId(traceId, Runnable)`。

修改 `AiStreamProcessor`（项目唯一有 Reactor `publishOn(boundedElastic)` 的地方）：
- `buildLineFlux` 入口捕获 `traceId`
- `publishOn(boundedElastic())` 之后的 `doOnNext`/`doOnError`/`doOnComplete` 用 `runWithTraceId` 包裹
- `streamAsync` 入口捕获 `traceId`，`doOnCancel` 和 `subscribe` 的 error/complete 回调用 `runWithTraceId` 包裹

覆盖：AI 流式响应在 `boundedElastic` 线程的所有日志。

## 七、设计说明

### 为什么 @Scheduled 用 AOP 而非 TaskDecorator

定时任务没有父请求线程，无法"传递" traceId。TaskDecorator 只能复制父线程 MDC，对定时任务无效（父线程是调度线程，MDC 为空）。AOP 在每次执行时生成独立 traceId，便于按次执行聚合排查。

### 为什么 Reactor 不用 Reactor Context

Reactor Context（`contextWrite`）是更"纯正"的方案，但需要重构整条链路把 Context 传播到底，侵入性大。`runWithTraceId` 在回调边界恢复 MDC 的方式侵入性小、风险低，且与现有代码结构兼容。traceId 是 String，跨线程传递无内存泄漏风险（finally 清理）。

### MDC 清理安全

- `MdcTaskDecorator`：执行完 `MDC.clear()`，防止线程池线程复用后 MDC 残留
- `TraceIdScheduledAop`：只清理自己生成的 traceId（`createdHere` 标记），不误清已有 MDC
- `ReactorMdcUtils.runWithTraceId`：只清理自己恢复的 traceId（`restored` 标记），不误清已有 MDC
