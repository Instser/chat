## 📋 需求背景

在当前项目中，需要高效率地判定一个用户是否未充值过套餐，以便：
- 为新用户提供个性化的充值引导
- 实现基于用户状态的功能权限控制
- 支持营销活动的精准用户定位
- 优化用户体验和转化率

## 🎯 解决方案概述

### 核心判定逻辑
基于项目现有的数据库结构，用户充值状态判定主要依据：

1. **t_user_order表** - 用户订单记录，payment_status=1表示已支付
2. **t_user_account表** - 用户账户信息，package_id字段记录当前套餐
3. **默认套餐机制** - 新用户注册时自动绑定ID=1的免费套餐

### 用户状态分类
- **NEVER_PAID**: 从未充值过任何套餐
- **FREE_ONLY**: 只使用过免费套餐（ID=1）
- **ACTIVE_PAID**: 当前使用付费套餐且未过期
- **INACTIVE_PAID**: 曾经充值但当前套餐已过期或使用免费套餐

## 🔧 技术实现

### 1. 服务层设计

#### UserPaymentStatusService接口
```java
public interface UserPaymentStatusService {
    boolean hasNeverPaid(Long userId);           // 是否从未充值
    boolean isOnlyFreeUser(Long userId);         // 是否只使用免费套餐
    boolean isActivePaidUser(Long userId);       // 是否为活跃付费用户
    LocalDateTime getFirstPaymentTime(Long userId); // 首次充值时间
    BigDecimal getTotalPaidAmount(Long userId);  // 总充值金额
}
```

#### 核心实现逻辑
- **hasNeverPaid()**: 查询用户是否存在payment_status=1的订单
- **isOnlyFreeUser()**: 检查用户是否只购买过package_id=1的套餐
- **isActivePaidUser()**: 验证用户当前是否有有效的付费套餐

### 3. 数据库性能优化

#### 专用索引创建
```sql
-- 用户支付状态专用索引
CREATE INDEX idx_user_payment_status ON t_user_order 
(user_id, payment_status, deleted, package_id, payment_time, amount);

-- 用户套餐支付状态索引
CREATE INDEX idx_user_package_payment ON t_user_order 
(user_id, package_id, payment_status, deleted, payment_time);
```

#### 统计视图创建
```sql
CREATE OR REPLACE VIEW v_user_payment_status AS
SELECT 
    u.id as user_id,
    u.username,
    u.email,
    ua.package_id as current_package_id,
    CASE 
        WHEN order_stats.paid_orders = 0 THEN 'NEVER_PAID'
        WHEN order_stats.paid_orders > 0 AND order_stats.paid_non_free_orders = 0 THEN 'FREE_ONLY'
        WHEN ua.package_id IS NOT NULL AND ua.package_id != 1 AND ua.package_expire_time > NOW() THEN 'ACTIVE_PAID'
        ELSE 'INACTIVE_PAID'
    END as payment_status_category
FROM t_user u
LEFT JOIN t_user_account ua ON u.id = ua.user_id
LEFT JOIN (订单统计子查询) order_stats ON u.id = order_stats.user_id;
```
