## 需求背景

用户希望在保存附带文件的消息时，数据库中的content字段只保存用户的原始内容，而不附带文件内容，这样前端展示给用户的信息中才不会显示文件内容。同时为了保证检测消息附带文件的效率，需要为消息表添加附件携带字段。

## 解决方案

### 1. 数据库结构优化

#### 1.1 添加附件标识字段
在`t_chat_message`表中添加`has_attachments`字段：

```sql
ALTER TABLE t_chat_message 
ADD COLUMN has_attachments TINYINT(1) DEFAULT 0 
COMMENT '是否包含附件（0-无附件，1-有附件）' 
AFTER message_type;
```

#### 1.2 创建优化索引
```sql
-- 附件查询优化索引
CREATE INDEX idx_chat_msg_attachments ON t_chat_message (has_attachments, session_id, create_time);

-- 用户附件消息查询索引
CREATE INDEX idx_chat_msg_user_attachments ON t_chat_message (user_id, has_attachments, create_time);
```

### 4. 核心逻辑重构

#### 4.1 消息保存流程优化
**文件**: `src/main/java/com/instser/chat/service/serviceimpl/ChatServiceImpl.java`

**原始流程**:
1. 处理文件内容并附加到用户消息中
2. 保存包含文件内容的消息到数据库

**优化后流程**:
1. 检查是否有文件附件
2. 保存用户原始消息到数据库（不包含文件内容，但标记附件状态）
3. 处理文件内容并附加到用户消息中（仅用于AI处理）

**核心代码**:
```java
// 检查是否有文件附件
boolean hasAttachments = request.getFilesId() != null && !request.getFilesId().trim().isEmpty();

// 保存用户原始消息到数据库（不包含文件内容）
String userMessageId = null;
if (request.getSessionId() != null) {
    userMessageId = saveUserOriginalMessage(request.getMessages(), request.getSessionId(), request.getUserId(), model.getId(), hasAttachments);
}

// 处理文件内容并附加到用户消息中（仅用于AI处理）
List<Map<String, String>> processedMessages = processFilesContent(request.getMessages(), request.getFilesId(), request.getUserId());
request.setMessages(processedMessages);
```

## 实现效果

### 1. 数据库存储优化
- ✅ **原始内容保存**: 数据库中的content字段只保存用户的原始输入内容
- ✅ **附件标识**: has_attachments字段标识消息是否包含附件
- ✅ **查询效率**: 通过索引快速查询带附件的消息，避免关联查询

### 2. 前端展示优化
- ✅ **纯净展示**: 前端显示的消息内容不包含文件内容
- ✅ **附件提示**: 通过hasAttachments字段知道消息是否有附件
- ✅ **文件列表**: 通过filesName字段获取关联的文件名列表

### 3. AI处理保持
- ✅ **完整分析**: AI仍然能够访问到完整的文件内容进行分析
- ✅ **处理流程**: 文件内容在AI处理时动态附加，不影响AI功能

### 4. 性能优化
- ✅ **索引优化**: 新增索引提高附件消息查询效率
- ✅ **避免关联**: 不需要每次都关联t_file_upload表查询
- ✅ **数据一致性**: 自动更新现有数据的附件标识
