# 支付请求防重放攻击解决方案

**文档时间**: 2025年6月30日 12:01  
**版本**: v1.0  
**目标**: 补充支付请求端的防重放攻击机制

## 🚨 安全漏洞分析

### 当前问题
现有的Redis支付安全系统只实现了**支付回调的防重放攻击**，但缺少**支付请求的防重放攻击**防护。

### 风险场景

#### 1. 恶意重放攻击
```
攻击者场景：
1. 截获用户的支付请求数据
2. 重复发送相同的支付请求
3. 可能导致：
   - 重复创建订单
   - 重复扣减库存
   - 重复扣减用户余额
   - 系统资源浪费
```

#### 2. 网络重试攻击
```
网络异常场景：
1. 用户发起支付请求
2. 网络超时，前端自动重试
3. 服务端可能收到多个相同请求
4. 导致重复处理
```

#### 3. 用户误操作
```
用户行为场景：
1. 用户点击支付按钮
2. 页面响应慢，用户重复点击
3. 发送多个相同的支付请求
4. 可能创建多个订单
```

## 🛡️ 解决方案设计

### 1. 支付请求唯一标识生成

#### 1.1 请求ID生成策略
```java
/**
 * 生成支付请求唯一标识
 * 基于关键业务参数生成，确保相同业务请求有相同ID
 */
private String generatePaymentRequestId(PaymentRequestVO request) {
    // 关键参数：用户ID + 商品ID + 金额 + 时间戳（分钟级别）
    String source = request.getUserId() + 
                   request.getProductId() + 
                   request.getAmount().toString() + 
                   request.getPaymentType() +
                   // 使用分钟级时间戳，允许同一分钟内的重试
                   (System.currentTimeMillis() / (60 * 1000));
    
    try {
        MessageDigest md = MessageDigest.getInstance("MD5");
        byte[] digest = md.digest(source.getBytes());
        StringBuilder sb = new StringBuilder();
        for (byte b : digest) {
            sb.append(String.format("%02x", b));
        }
        return sb.toString();
    } catch (Exception e) {
        return source.hashCode() + "";
    }
}

/* 示例生成过程：
 * 用户ID: 12345
 * 商品ID: PROD001  
 * 金额: 99.00
 * 支付类型: ALIPAY
 * 时间窗口: 28662240 (分钟级)
 * 
 * source = "12345PROD00199.00ALIPAY28662240"
 * requestId = "a1b2c3d4e5f6789012345678901234ab"
 */
```

### 2. Redis防重放检查实现

#### 2.1 支付请求防重放服务
```java
/**
 * 检查支付请求是否已处理
 * @param requestId 支付请求唯一标识
 * @return true=已处理过(重放攻击), false=首次处理(允许)
 */
public boolean isPaymentRequestProcessed(String requestId) {
    if (requestId == null || requestId.trim().isEmpty()) {
        log.warn("支付请求ID为空，拒绝处理");
        return true; // 拒绝处理
    }

    try {
        String key = "payment:request:" + requestId;
        // 例如: "payment:request:a1b2c3d4e5f6789012345678901234ab"
        
        // 检查Redis中是否已存在该键
        Boolean exists = redisTemplate.hasKey(key);
        
        if (exists != null && exists) {
            // 检测到重放攻击！相同的支付请求被重复发送
            log.warn("检测到支付请求重放攻击，请求ID: {}", requestId);
            return true; // 返回true表示已处理过，拒绝重复处理
        }

        // 首次处理该支付请求，将其标记为已处理
        long processTime = System.currentTimeMillis();
        redisTemplate.opsForValue().set(key, processTime, Duration.ofMinutes(30));
        
        // 设置30分钟过期时间，平衡防重放效果和存储效率
        log.debug("支付请求ID: {} 标记为已处理", requestId);
        return false; // 返回false表示首次处理，允许继续处理

    } catch (Exception e) {
        log.error("支付请求防重放检查异常，请求ID: {}", requestId, e);
        return false; // 异常情况下允许处理，避免影响正常业务
    }
}

/* Redis数据示例：
 * Key: payment:request:a1b2c3d4e5f6789012345678901234ab
 * Value: 1719734400000 (处理时间戳)
 * TTL: 1800秒 (30分钟后过期)
 */
```

#### 2.2 集成到支付服务
```java
@Service
public class PaymentServiceImpl implements PaymentService {
    
    @Autowired
    private RedisPaymentSecurityService redisPaymentSecurityService;
    
    public PaymentResponseVO createPayment(PaymentRequestVO request) {
        // 1. 参数校验
        validatePaymentRequest(request);
        
        // 2. 生成支付请求ID（如果前端未提供）
        String requestId = request.getRequestId();
        if (requestId == null || requestId.trim().isEmpty()) {
            requestId = generatePaymentRequestId(request);
            request.setRequestId(requestId);
        }
        
        // 3. 【新增】支付请求防重放检查
        if (redisPaymentSecurityService.isPaymentRequestProcessed(requestId)) {
            throw new PaymentException("重复的支付请求，请勿重复提交");
        }
        
        // 4. 原有的安全检查
        if (!redisPaymentSecurityService.checkPaymentFrequency(request.getUserId())) {
            throw new PaymentException("支付频率过高，请稍后再试");
        }
        
        // 5. 支付会话管理
        if (!redisPaymentSecurityService.acquirePaymentSession(request.getUserId())) {
            throw new PaymentException("支付会话获取失败，请稍后再试");
        }
        
        try {
            // 6. 创建支付订单（受分布式锁保护）
            return distributedLockService.executeUserPaymentLock(request.getUserId(), () -> {
                return doCreatePayment(request);
            });
            
        } finally {
            // 7. 释放支付会话锁
            redisPaymentSecurityService.releasePaymentSession(request.getUserId());
        }
    }
}
```

### 3. 数据结构设计

#### 3.1 Redis键值设计
```
功能: 支付请求防重放
Key格式: payment:request:{requestId}
Value: 处理时间戳
TTL: 30分钟

示例:
Key: payment:request:a1b2c3d4e5f6789012345678901234ab
Value: "1719734400000"
TTL: 1800秒
```

#### 3.2 与现有防重放的区别
```
支付回调防重放:
Key: payment:callback:{callbackId}
TTL: 60分钟 (回调重试窗口较长)

支付请求防重放:
Key: payment:request:{requestId}  
TTL: 30分钟 (用户操作窗口较短)
```

```
用户端防重放 + 回调端防重放 = 完整防护

支付请求防重放:
- Key: payment:request:{requestId}
```

### 安全效果评估

#### 修复前风险
- ❌ 用户可以重复提交相同支付请求
- ❌ 恶意用户可以重放历史支付请求
- ❌ 网络异常可能导致重复订单创建
- ❌ 系统资源可能被恶意消耗

#### 修复后防护
- ✅ 30分钟内相同请求只能处理一次
- ✅ 自动检测和拒绝重放攻击
- ✅ 记录可疑行为用于风控分析
- ✅ 保护系统资源和数据一致性

### 性能影响
- **响应时间**: 增加<5ms（Redis操作）
- **内存使用**: 每个请求约100字节
- **存储清理**: 30分钟自动过期
- **并发性能**: 无影响，Redis原子操作

### 部署注意事项
1. **Redis可用性**: 确保Redis服务稳定运行
2. **时钟同步**: 多实例服务器时钟需要同步

4. **日志记录**: 完整记录安全事件日志
