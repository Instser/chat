## 问题回顾
根据测试报告检查发现，联网查询结果存储功能存在时序问题：虽然联网搜索功能正常工作，但搜索结果没有被正确保存到数据库，导致`hasWebSearch`字段未被设置。

## 问题根本原因
**时序问题**：联网内容保存逻辑在联网搜索处理**之前**被调用，导致保存时获取不到搜索结果。

### 具体调用顺序问题
1. **第127行** - `prepareSessionAndMessage(request, model, response)` - 调用了`saveWebSearchResultsIfNeeded`
2. **第135行** - `buildAiRequestMessages(request)` - 这里才进行联网搜索处理
3. **结果** - 保存时`request.getNetworkSearchResults()`为空，条件判断失败

## 修复方案
采用**直接修复调用时机**的方案，而不是创建新方法：

### 修复步骤
1. **移除错误位置的调用** - 从`prepareSessionAndMessage`方法中移除`saveWebSearchResultsIfNeeded`调用
2. **在正确时机调用** - 在`buildAiRequestMessages`方法中联网搜索处理完成后立即调用保存逻辑
3. **添加辅助方法** - 创建`getLatestUserMessageId`方法来获取最新用户消息ID

### 核心修改
```java
// 在联网搜索处理完成后立即保存
NetworkSearchResult networkResult = processNetworkContent(messages, userQuery);
messages = networkResult.getMessages();
request.setNetworkSearchResults(networkResult.getSearchResults());

// 立即保存联网查询结果到数据库（修复时序问题）
String userMessageId = getLatestUserMessageId(request.getSessionId(), request.getUserId());
if (userMessageId != null) {
    saveWebSearchResultsIfNeeded(request, userMessageId);
} else {
    log.error("【联网存储】无法获取用户消息ID，跳过联网内容保存");
}
```
