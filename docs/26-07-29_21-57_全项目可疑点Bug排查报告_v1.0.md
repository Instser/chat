## 1. P0 — 已证实、应尽快修

### 1.1 模型列表泄漏上游 API Key 与 baseUrl

- **证据**：`GET /api/chat/models`（登录后）返回实体 `AiModel` 全字段，含：
  - `apiKey` 明文前缀 `sk-...`（完整密钥在响应中）
  - `baseUrl` 上游地址
- **代码**：`ChatApiController.getModels()` → `aiModelService.getVisibleModels()` 直接返回 `List<AiModel>`，未走 `AiModelVO` 脱敏。
- **影响**：任意登录用户可拿走 DeepSeek 等上游密钥，盗刷配额/费用。
- **建议**：只返回前端需要的 VO（id/name/description/provider…），**禁止**序列化 `apiKey`/`baseUrl` 到用户端；DB 内密钥仅服务端调用使用。

### 1.2 横向越权（IDOR）：会话/消息/删除无归属校验

已用 `testuser` 实测：

| 操作 | 路径 | 结果 |
|---|---|---|
| 列任意用户会话 | `GET /chat/session/list?userId=1` | 200，返回 userId=1 的会话 |
| 给任意用户建会话 | `POST /chat/session/create?userId=1&modelId=1` | 200，创建成功 |
| 读任意会话消息 | `GET /chat/sessions/{sessionId}/messages`、`/chat/message/list/{id}` | 200，无 userId 校验 |
| 读最近消息 | `GET /chat/message/recent?userId=1` | 200，返回他方消息内容 |
| 删他方会话 | `DELETE /chat/sessions/{sessionId}` | 可删（服务层 `deleteSession` 只按 sessionId，不校验当前用户） |
| 管理支付画像 | `GET /user/status/admin/{userId}` | 200；代码注释 **TODO 管理员权限检查** 未实现 |

- **代码位置**：
  - `ChatController`：参数 `userId` 信任客户端
  - `ChatApiController.getSessionMessages` / `deleteSession`：无 `Authentication` 归属校验
  - `ChatSessionServiceImpl.deleteSession`：无 currentUser 比对
  - `UserPaymentStatusController.getPaymentStatusByAdmin`：TODO 未做角色校验
- **影响**：登录用户可读/删他人会话与消息，可查询他人支付状态，可污染他人会话数据。
- **建议**：所有会话/消息写读删以 **JWT 用户** 为准；路径/参数中的 userId 忽略或强制相等；admin 接口 `hasRole('ADMIN')`。

### 1.3 `POST /chat` 被配置为 permitAll（临时绕过）

- **代码**：`SecurityConfig`：
  ```text
  .requestMatchers(HttpMethod.POST, "/chat").permitAll()  // 临时允许SSE...
  ```
- **实测**：未登录 POST `/api/chat` 仍 HTTP 200 并进入流（业务层返回 `0:"用户未认证"` 后结束），**鉴权下沉到业务**，过滤器层未拦。
- **影响**：绕过统一安全模型；未来若业务漏判会直接裸奔；也增加匿名打接口成本（扫描/刷流量）。
- **建议**：改为 `authenticated()`；SSE/Emitter 鉴权用 Cookie JWT（现已支持），不必 permitAll。

### 1.4 配置文件默认密钥入库（高危配置）

`src/main/resources/application.yml` 含可运行的默认敏感值（部分带 `${ENV:default}` 的 default）：

- Redis 密码默认值
- MySQL 密码明文段
- JWT `secret` 默认值
- Stripe **live** secret / webhook secret 默认值
- PayPal client secret 默认值
- Google/GitHub OAuth client secret 默认值
- 缓存管理 admin 密码默认 `your-admin-password`
- Druid 监控 `admin/admin123`

- **影响**：仓库泄露 = 凭据泄露；即使生产用环境变量覆盖，默认值仍增加误部署风险。
- **建议**：默认改为空/占位；密钥只走环境变量或密钥管理；**轮换**已暴露过的 live key。

## 2. P1 — 高风险 / 明确缺陷

### 2.1 双控制器重复聊天 API，旧 `ChatController` 权限模型过时

- `ChatApiController`（现代入口）与 `ChatController`（`/chat/session/*`、`/chat/message/*`）并存。
- 旧控制器大量信任请求参数 `userId`，且与新 API 路径混在同一 `/chat` 前缀下。
- **建议**：废弃并鉴权收口到 `ChatApiController`；或全部加 ownership 校验后标 `@Deprecated`。

### 2.2 运维/管理入口 Security 层 permitAll，依赖二次鉴权

- `/ops/**`、`/admin/cache/**`、`/admin/logs/**`、`/admin/gemini/**` 在 `SecurityConfig` 为 `permitAll`。
- `/ops/version` 实测无 Key → 403（`ManagementApiKeyService` 生效）——二次鉴权 OK。
- 但 `ManagementApiKeyService` 在启用时会 **日志打印完整 masterApiKey**；禁用时 `validateApiKey` 直接 `return true`。
- **建议**：Security 层至少 `authenticated()` 或 IP allowlist + Key；禁止日志打印完整 Key。

### 2.3 内存态限流 / 中断 / 支付频控不跨实例

- `ChatInterruptServiceImpl`、`StreamSubscriptionRegistry`、`ChatRateLimitServiceImpl`、`PaymentSecurityUtil` 等多处 `ConcurrentHashMap`。
- **影响**：多实例部署时 stop 失效、限流可绕过、支付防重放弱化。
- **建议**：会话粘滞或 Redis 化（已知技术债，非新引入）。

### 2.4 stop 取消回调上的完成收尾可能跑在 stop 请求线程

- 日志曾出现 `StreamCompletionCoordinator thread=http-nio-*-exec-*` 在 cancel 路径。
- 功能正确，但会短时占用 Tomcat 线程做落库。
- **建议**：cancel 收尾 `publishOn/elastic` 或丢到 `continuationExecutor`。

### 2.5 续写路径仍 `blockLast` + `Thread.sleep`

- `ChatContinuationService` 单轮上游仍同步 block；重试 sleep。
- 主 chat async 已不 blockLast，但续写高峰仍可能占满弹性线程池。

## 3. P2 — 中风险 / 质量与一致性

| 项 | 说明 |
|---|---|
| `POST /chat` 匿名 200 流 | 业务拒绝但仍占异步通道；应 401 JSON 或直接拒连 |
| 会话删除失败返回 500 文案 | 实测 delete 失败时 message「会话删除失败」code 500，前端难区分「不存在/无权限」 |
| `ChatApiController` 与 `ApiController` 列表形态不一致 | `/chats` vs `/chat/sessions` 双轨 |
| 大量 `catch (Exception)` 吞栈 | 可观测性差，部分路径只记日志 |
| Writer 智能分块 sleep | 已改为 0；sync 路径仍保留分支 |
| ContentPolicy / 支付策略重试 sleep | 可接受的后台重试，需避免在请求线程长睡 |
| fastjson 仍在 WebSearch 使用 | 非 autoType 利用证据；长期建议统一 Jackson |
| 单元测试未覆盖鉴权/IDOR | 安全回归缺口 |
