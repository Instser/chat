# 07-31 02:44 订单重复创建逻辑修复报告

**时间**: 2025-07-31 02:44  
**版本**: v1.0.1

## 问题概述

修复了订单创建逻辑中的一个重要问题：当检测到用户有相同套餐的近期待支付订单时，系统错误地取消旧订单并创建新订单，这可能导致已支付但状态未及时更新的订单被错误取消。

## 问题分析

### 1. 原有逻辑问题

#### 1.1 错误的处理方式
```java
// 原有错误逻辑
for (UserOrder oldOrder : recentOrders) {
    if (oldOrder.getPaymentStatus() == 0) { // 仍然是待支付状态
        cancelOrder(oldOrder.getOrderNo());
        log.info("取消用户{}的旧订单: {}", userId, oldOrder.getOrderNo());
    }
}
```

#### 1.2 问题根因
- **时序问题**: 用户可能已经支付了旧订单，但支付回调还在处理中，数据库状态尚未更新
- **重复支付风险**: 取消已支付订单会导致用户重复支付
- **数据不一致**: 支付平台显示已支付，但系统中订单被取消

### 2. 业务场景分析

#### 2.1 正常场景
用户创建订单 → 支付 → 回调更新状态 → 订单完成

#### 2.2 问题场景
用户创建订单A → 支付A → 回调处理中 → 用户再次下单 → 系统取消A → 创建订单B → 用户重复支付

#### 2.3 期望场景
用户创建订单A → 支付A → 回调处理中 → 用户再次下单 → 系统返回订单A → 避免重复支付

## 修复方案

### 1. 核心逻辑修改

#### 1.1 修复后的逻辑
**文件**: `src/main/java/com/instser/chat/service/serviceimpl/OrderServiceImpl.java`  
**行号**: 55-79

```java
// 【新增】检查是否有相同套餐的近期待支付订单
List<UserOrder> recentOrders = getRecentPendingOrders(userId, packageId, 30);
if (!recentOrders.isEmpty()) {
    log.info("发现用户{}有{}个相同套餐的近期待支付订单，返回最新的待支付订单", userId, recentOrders.size());

    // 获取最新的待支付订单
    UserOrder latestOrder = recentOrders.get(0); // 查询结果已按创建时间倒序排列
    
    // 主动同步支付状态，确保返回的订单状态是最新的
    try {
        log.debug("同步订单{}的支付状态", latestOrder.getOrderNo());
        paymentStatusSyncService.syncOrderStatus(latestOrder.getOrderNo());
        
        // 重新获取订单信息，确保状态是最新的
        UserOrder updatedOrder = getOrderByOrderNo(latestOrder.getOrderNo());
        if (updatedOrder != null) {
            latestOrder = updatedOrder;
        }
    } catch (Exception e) {
        log.warn("同步订单{}状态异常，使用当前状态: {}", latestOrder.getOrderNo(), e.getMessage());
    }
    
    log.info("返回用户{}的现有订单: {}，状态: {}", userId, latestOrder.getOrderNo(), latestOrder.getPaymentStatus());
    return latestOrder;
}
```

#### 1.2 依赖注入增强
```java
// 添加PaymentStatusSyncService依赖
private final PaymentStatusSyncService paymentStatusSyncService;
```

### 2. 修复要点

#### 2.1 返回现有订单
- **不创建新订单**: 当发现相同套餐的待支付订单时，直接返回现有订单
- **避免重复支付**: 用户不会因为系统错误而被要求重复支付
- **保持数据一致性**: 维护订单状态的一致性

#### 2.2 状态同步机制
- **主动同步**: 在返回订单前主动同步支付状态
- **确保准确性**: 通过PaymentStatusSyncService获取最新的支付状态
- **异常处理**: 同步失败时使用当前状态，不影响业务流程

#### 2.3 日志增强
- **详细记录**: 记录订单查找、状态同步、返回等关键步骤
- **便于调试**: 提供足够的信息用于问题排查
- **状态跟踪**: 记录订单状态变化过程
