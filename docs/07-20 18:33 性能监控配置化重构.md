# 07-20 18:33 性能监控配置化重构

## 问题描述
PerformanceMonitor 类中存在大量硬编码的性能数据，包括：
- 固定的监控间隔时间（5分钟、1小时）
- 硬编码的告警阈值（CPU 80%、内存 85%、线程 500个、连接池 90%）
- 硬编码的服务器描述信息（"8核8G服务器"）
- 日志中的占位符文本（"计算中"）

## 解决方案

### 1. 创建配置类
新增 `PerformanceMonitorConfig.java` 配置类：
- 使用 `@ConfigurationProperties` 注解
- 分为三个配置组：interval（监控间隔）、threshold（告警阈值）、server（服务器信息）
- 提供合理的默认值

### 2. 重构 PerformanceMonitor 类
- 注入 `PerformanceMonitorConfig` 配置类
- 使用 `@Scheduled(fixedRateString = "#{@performanceMonitorConfig.interval.basic}")` 动态配置监控间隔
- 所有告警阈值改为从配置读取
- 添加 `getServerDescription()` 方法支持自动检测服务器信息

### 3. 配置文件更新
在 `application.yml` 中添加性能监控配置：
```yaml
performance:
  monitor:
    interval:
      basic: 300000      # 基础监控间隔（毫秒）
      detailed: 3600000  # 详细报告间隔（毫秒）
    threshold:
      cpu-usage: 80.0              # CPU使用率告警阈值
      heap-memory-usage: 85.0      # 堆内存使用率告警阈值
      thread-count: 500            # 线程数告警阈值
      connection-pool-usage: 90.0  # 连接池使用率告警阈值
    server:
      description: ""      # 服务器描述，为空时自动检测
      auto-detect: true    # 启用自动检测
```

## 改进效果

### 1. 配置灵活性
- 监控间隔可根据环境调整（开发环境可设置更短间隔）
- 告警阈值可根据服务器性能调整
- 支持不同环境使用不同配置

### 2. 自动化程度提升
- 自动检测服务器核心数和内存大小
- 动态生成服务器描述信息
- 减少手动维护成本

### 3. 代码质量提升
- 消除硬编码，提高代码可维护性
- 配置集中管理，便于统一调整
- 符合Spring Boot配置最佳实践

## 技术要点
- 使用 `@ConfigurationProperties` 实现类型安全的配置绑定
- 使用 SpEL 表达式动态配置定时任务间隔
- 使用 `ManagementFactory` 自动检测系统信息
- 保持向后兼容性，提供合理默认值
