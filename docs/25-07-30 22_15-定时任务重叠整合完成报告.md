## 🔧 具体修改内容

### 1. 超时会话清理任务整合

#### 问题描述
- `ChatInterruptConfig.cleanupTimeoutSessions()` (每5分钟)
- `OptimizedScheduledTaskService.lightweightTask()` (每5分钟)
- **重复执行**: 两个任务都调用 `chatInterruptService.cleanupTimeoutSessions()`

#### 解决方案
**修改文件**: `src/main/java/com/instser/chat/config/ChatInterruptConfig.java`

```java
// 添加条件注解，默认禁用
@ConditionalOnProperty(name = "app.scheduled.chat-interrupt.enabled", havingValue = "true", matchIfMissing = false)
public class ChatInterruptConfig {
    
    // 注释掉@Scheduled注解，保留方法供手动调用
    // @Scheduled(fixedRate = 300000)
    public void cleanupTimeoutSessions() {
        // 方法实现保持不变
    }
}
```

**结果**: 
- 默认情况下只有 `OptimizedScheduledTaskService.lightweightTask()` 执行清理
- 如需启用独立任务，设置 `app.scheduled.chat-interrupt.enabled=true`

### 2. 支付同步任务整合

#### 问题描述
- `PaymentStatusSyncServiceImpl.syncPendingOrdersStatus()` (每5分钟)
  - 处理5-30分钟前的订单
  - 有完整的业务逻辑实现
- `OptimizedScheduledTaskService.paymentSyncTask()` (每15分钟)
  - 处理30分钟内的订单
  - 只有空实现，无实际功能

#### 解决方案

**修改文件**: `src/main/java/com/instser/chat/service/OptimizedScheduledTaskService.java`

1. **替换原有任务**:
```java
// 原来的paymentSyncTask (每15分钟，空实现)
// 替换为：
@Scheduled(fixedDelay = 300000) // 每5分钟
public void unifiedPaymentSyncTask() {
    // 整合PaymentStatusSyncServiceImpl的完整逻辑
    List<UserOrder> pendingOrders = orderService.getPendingOrdersInTimeRange(5, 30);
    
    for (UserOrder order : pendingOrders) {
        paymentStatusSyncService.syncOrderStatus(order.getOrderNo());
        Thread.sleep(1000); // 防频繁请求
    }
}
```

2. **添加服务依赖**:
```java
private final PaymentStatusSyncService paymentStatusSyncService;
```

**修改文件**: `src/main/java/com/instser/chat/service/serviceimpl/PaymentStatusSyncServiceImpl.java`

```java
// 添加条件注解，默认禁用定时任务
@Scheduled(fixedDelay = 300000)
@ConditionalOnProperty(name = "app.scheduled.payment-status-sync.enabled", havingValue = "true", matchIfMissing = false)
public void syncPendingOrdersStatus() {
    // 方法实现保持不变，但默认不会被调度执行
}
```

**结果**:
- 默认情况下只有 `OptimizedScheduledTaskService.unifiedPaymentSyncTask()` 执行
- 保留了原有的完整业务逻辑和错误处理
- 如需启用独立任务，设置 `app.scheduled.payment-status-sync.enabled=true`

## 📊 优化效果

### 1. 资源使用优化
- **减少重复执行**: 消除了超时会话清理的重复调用
- **统一线程池**: 支付同步任务使用OptimizedScheduledTaskService的独立线程池
- **减少数据库查询**: 避免了重复的订单查询操作

### 2. 执行频率优化
| 任务类型 | 整合前 | 整合后 | 优化效果 |
|---------|--------|--------|---------|
| 超时会话清理 | 2个任务每5分钟 | 1个任务每5分钟 | 减少50%执行次数 |
| 支付订单同步 | 1个每5分钟 + 1个每15分钟(空) | 1个每5分钟 | 消除无效任务 |

### 3. 系统稳定性提升
- **错峰执行**: 所有任务在OptimizedScheduledTaskService中统一调度
- **异常隔离**: 使用独立线程池，避免任务间相互影响
- **配置灵活**: 支持按需启用独立任务，便于调试和特殊场景
