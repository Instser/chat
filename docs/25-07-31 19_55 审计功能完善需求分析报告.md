## 2. 缺失的审计功能

### 2.1 用户操作审计 ❌

**缺失内容**:
- 用户注册、登录、登出
- 密码修改、账户信息变更
- 用户权限变更、套餐激活
- 账户状态变更（启用/禁用）

**风险等级**: 🔴 高风险
**建议**: 新增 `t_user_operation_audit` 表

### 2.2 聊天内容审计 ❌

**缺失内容**:
- 敏感内容检测记录
- 聊天频率限制触发记录
- 异常聊天行为监控
- 聊天会话创建/删除审计

**风险等级**: 🟡 中风险
**建议**: 新增 `t_chat_audit` 表

### 2.3 文件操作审计 ❌

**缺失内容**:
- 文件上传、下载、删除操作
- 文件类型检测结果
- 恶意文件拦截记录
- 文件访问权限验证

**风险等级**: 🟡 中风险
**建议**: 新增 `t_file_operation_audit` 表

### 2.4 系统配置审计 ❌

**缺失内容**:
- AI模型配置变更
- 系统参数修改
- 缓存配置变更
- 定时任务执行记录

**风险等级**: 🟡 中风险
**建议**: 新增 `t_system_config_audit` 表

### 2.5 安全事件审计 ❌

**缺失内容**:
- 异常登录尝试
- API访问频率异常
- 可疑用户行为
- 系统攻击尝试

**风险等级**: 🔴 高风险
**建议**: 新增 `t_security_event_audit` 表

## 3. 推荐的审计表设计

### 3.1 用户操作审计表 (优先级: P0)

```sql
CREATE TABLE `t_user_operation_audit` (
    `id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    `user_id` bigint NOT NULL COMMENT '用户ID',
    `operation_type` varchar(50) NOT NULL COMMENT '操作类型',
    `operation_module` varchar(30) NOT NULL COMMENT '操作模块',
    `old_value` text COMMENT '原值(JSON格式)',
    `new_value` text COMMENT '新值(JSON格式)',
    `operation_result` varchar(20) DEFAULT 'SUCCESS' COMMENT '操作结果',
    `client_ip` varchar(45) COMMENT '客户端IP',
    `user_agent` varchar(500) COMMENT '用户代理',
    `session_id` varchar(100) COMMENT '会话ID',
    `operation_details` text COMMENT '操作详情(JSON格式)',
    `create_time` datetime DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    PRIMARY KEY (`id`),
    KEY `idx_user_operation` (`user_id`, `operation_type`),
    KEY `idx_operation_time` (`operation_type`, `create_time`),
    KEY `idx_client_ip` (`client_ip`, `create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户操作审计表';
```

### 3.2 安全事件审计表 (优先级: P0)

```sql
CREATE TABLE `t_security_event_audit` (
    `id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    `event_type` varchar(50) NOT NULL COMMENT '事件类型',
    `severity_level` varchar(20) NOT NULL COMMENT '严重程度',
    `user_id` bigint COMMENT '相关用户ID',
    `client_ip` varchar(45) COMMENT '客户端IP',
    `user_agent` varchar(500) COMMENT '用户代理',
    `event_source` varchar(50) COMMENT '事件来源',
    `event_description` text COMMENT '事件描述',
    `event_details` text COMMENT '事件详情(JSON格式)',
    `is_blocked` tinyint DEFAULT 0 COMMENT '是否已拦截',
    `handle_status` varchar(20) DEFAULT 'PENDING' COMMENT '处理状态',
    `handle_result` text COMMENT '处理结果',
    `create_time` datetime DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    PRIMARY KEY (`id`),
    KEY `idx_event_type` (`event_type`, `severity_level`),
    KEY `idx_user_security` (`user_id`, `create_time`),
    KEY `idx_ip_security` (`client_ip`, `create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='安全事件审计表';
```

## 4. 实施建议

### 4.1 分阶段实施策略

**第一阶段 (P0优先级)**:
1. 用户操作审计表 - 覆盖用户核心操作
2. 安全事件审计表 - 提升系统安全监控

**第二阶段 (P1优先级)**:
3. 聊天内容审计表 - 内容安全监控
4. 文件操作审计表 - 文件安全管理

**第三阶段 (P2优先级)**:
5. 系统配置审计表 - 配置变更追踪

### 4.2 技术实施要点

1. **异步记录**: 审计记录不影响主业务性能
2. **数据压缩**: 大量审计数据的存储优化
3. **定期清理**: 建立审计数据的生命周期管理
4. **索引优化**: 确保审计查询的高性能
5. **权限控制**: 审计数据的访问权限管理

**是否需要新增审计表**: ✅ **强烈建议**

1. 当前审计覆盖率仅40%，存在重大安全盲区
