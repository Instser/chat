# ID策略统一为雪花ID改造报告

**时间**: 2025年7月20日 21:39  
**版本**: v2.0.0  
**类型**: 架构重构

## 改造概述

本次改造解决了系统中ID生成策略不一致的问题，将所有表的AUTO_INCREMENT主键统一修改为雪花ID策略，实现了代码配置与数据库结构的完全一致。

## 问题背景

### 原有问题
1. **配置不一致**: 数据库使用AUTO_INCREMENT，代码配置使用ASSIGN_ID（雪花ID）
2. **策略混乱**: 不同实体类使用不同的ID生成方式
3. **潜在风险**: MyBatis-Plus可能尝试生成雪花ID但数据库期望自增ID
4. **扩展限制**: 自增ID不支持分布式部署和水平扩展

### 影响范围
- 所有数据库表的主键ID字段
- FileUpload和WebSearchContent实体类配置
- 系统的并发性能和扩展能力

## 改造方案

### 1. 数据库结构修改

**修改内容**:
- 移除所有表的AUTO_INCREMENT属性
- 保持主键字段为BIGINT NOT NULL
- 备份原有AUTO_INCREMENT值用于回滚

**涉及的表**:
```sql
-- 核心业务表
t_user, t_ai_model, t_chat_session, t_chat_message, t_file_upload
t_package, t_user_account, t_user_daily_usage, t_user_order
t_payment_audit, t_web_search_content

-- 系统管理表
t_system_setting, t_admin_user, t_admin_operation_log

-- OAuth2相关表
t_oauth2_state, t_oauth2_audit_log, t_user_oauth
```

### 2. 代码配置统一

**修改的实体类**:

#### FileUpload.java
```java
// 修改前
@TableId(value = "id", type = IdType.AUTO)
private Long id;

// 修改后
@TableId(value = "id", type = IdType.ASSIGN_ID)
private Long id;
```

#### WebSearchContent.java
```java
// 修改前
@TableId(value = "id", type = IdType.AUTO)
private Long id;

// 修改后
@TableId(value = "id", type = IdType.ASSIGN_ID)
private Long id;
```

**保持不变的配置**:
- 其他实体类已经使用IdType.ASSIGN_ID
- MyBatis-Plus全局配置保持id-type: ASSIGN_ID
- 业务ID（sessionId、messageId等）继续使用UUID，但统一格式为32位无连字符

### 3. UUID业务ID格式统一

**修改前的格式不一致问题**:
- sessionId：32位无连字符格式 `a1b2c3d4e5f6789012345678901234ab`
- messageId：36位带连字符格式 `a1b2c3d4-e5f6-7890-1234-5678901234ab`
- fileId：36位带连字符格式 `a1b2c3d4-e5f6-7890-1234-5678901234ab`

**修改后的统一格式**:
- 所有业务ID统一为32位无连字符格式
- 数据库中现有的带连字符ID自动转换为无连字符格式
- 新生成的ID直接使用无连字符格式

**修改的代码文件**:
- `ChatMessageServiceImpl.java`：messageId生成统一格式
- `FileUploadServiceImpl.java`：fileId生成统一格式
- `OAuth2SecurityUtil.java`：已经是无连字符格式，保持不变

## 双ID架构设计

### 架构原理
```
┌─────────────────┬─────────────────┬─────────────────┐
│   用途场景      │   主键ID        │   业务ID        │
├─────────────────┼─────────────────┼─────────────────┤
│ 数据库内部关联  │ 雪花ID (Long)   │ -               │
│ 外键关联查询    │ 雪花ID (Long)   │ -               │
│ 对外API接口     │ -               │ UUID (String)   │
│ 前端页面显示    │ -               │ UUID (String)   │
│ URL参数传递     │ -               │ UUID (String)   │
└─────────────────┴─────────────────┴─────────────────┘
```

### 职责分离
1. **主键ID（雪花ID）**:
   - 用途：数据库内部关联、性能优化
   - 特点：数字型、有序、高性能
   - 优势：支持分布式、无锁生成、查询高效

2. **业务ID（UUID）**:
   - 用途：对外API、业务逻辑、安全性
   - 特点：字符串、随机、不可预测
   - 优势：防枚举攻击、隐私保护、安全性高
