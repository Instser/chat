### 2. 频率限制服务

#### 设计特点
- 与聊天频率限制保持一致：10次/分钟
- Redis + 内存双重策略
- 自动故障恢复机制
- 定时缓存清理

#### 核心实现
```java
@Service
public class WebSearchRateLimitServiceImpl implements WebSearchRateLimitService {
    
    private final RedisTemplate<String, Object> redisTemplate;
    private final ConcurrentHashMap<String, ConcurrentHashMap<Long, Boolean>> fallbackCache;
    
    private static final int USER_RATE_LIMIT_PER_MINUTE = 10;
    private volatile boolean redisAvailable = true;
    
    @Override
    public boolean checkUserUpdateRateLimit(Long userId) {
        String key = "web_search_update:rate_limit:user:" + userId;
        
        if (redisAvailable) {
            try {
                return checkRateLimitWithRedis(key, USER_RATE_LIMIT_PER_MINUTE);
            } catch (Exception e) {
                redisAvailable = false;
                return checkRateLimitWithMemory(key, USER_RATE_LIMIT_PER_MINUTE);
            }
        } else {
            return checkRateLimitWithMemory(key, USER_RATE_LIMIT_PER_MINUTE);
        }
    }
}
```

### 3. 权限缓存服务

#### 设计特点
- Caffeine本地缓存
- 5分钟过期时间
- 最大1000个条目
- 自动缓存统计

#### 核心实现
```java
@Service
public class WebSearchCacheServiceImpl implements WebSearchCacheService {
    
    private final Cache<String, Boolean> permissionCache = Caffeine.newBuilder()
            .maximumSize(1000)
            .expireAfterWrite(5, TimeUnit.MINUTES)
            .build();
    
    @Override
    public boolean hasPermission(Long userId, String messageId) {
        String cacheKey = "perm:" + userId + ":" + messageId;
        
        Boolean cached = permissionCache.getIfPresent(cacheKey);
        if (cached != null) {
            return cached;
        }
        
        // 缓存未命中，查询数据库并缓存结果
        boolean hasPermission = checkUserPermission(userId, messageId);
        permissionCache.put(cacheKey, hasPermission);
        return hasPermission;
    }
}
```

@Aspect
@Component
public class WebSearchPerformanceAspect {
    
    @Around("@annotation(webSearchMonitoring)")
    public Object monitorPerformance(ProceedingJoinPoint joinPoint, 
                                   WebSearchMonitoring webSearchMonitoring) throws Throwable {
        Timer.Sample sample = webSearchMetrics.startTimer();
        
        try {
            Object result = joinPoint.proceed();
            webSearchMetrics.recordSuccess(sample);
            return result;
        } catch (WebSearchException e) {
            webSearchMetrics.recordError(sample, e.getErrorCode().name());
            throw e;
        }
    }
}

### 5. 业务逻辑实现

#### 7步完整流程
```java
@Override
@WebSearchMonitoring("updateContentByMessageId")
@Transactional(rollbackFor = Exception.class)
public boolean updateContentByMessageId(String messageId, List<Map<String, Object>> content, Long userId) {
    
    // 1. 预检查阶段 - 快速失败
    validateBasicParameters(messageId, content);
    
    // 2. 权限验证 - 使用缓存优化
    if (!webSearchCacheService.hasPermission(userId, messageId)) {
        throw new WebSearchException(WebSearchErrorCode.NO_MESSAGE_PERMISSION);
    }
    
    // 3. 频率限制检查 - 高性能Redis计数
    if (!webSearchRateLimitService.checkUserUpdateRateLimit(userId)) {
        webSearchMetrics.recordRateLimit();
        throw new WebSearchException(WebSearchErrorCode.RATE_LIMIT_EXCEEDED);
    }
    
    // 4. 并发控制 - 分布式锁
    String lockKey = "web_search_update_lock:" + messageId;
    boolean lockAcquired = redisTemplate.opsForValue()
            .setIfAbsent(lockKey, "1", 30, TimeUnit.SECONDS);
    
    if (!lockAcquired) {
        webSearchMetrics.recordConcurrentConflict();
        throw new WebSearchException(WebSearchErrorCode.CONCURRENT_MODIFICATION);
    }
    
    try {
        // 5. 数据库更新 - 批量操作
        String newContentJson = JSON.toJSONString(content);
        int updatedRows = webSearchContentDao.updateContentByMessageId(
                messageId, newContentJson, content.size());
        
        if (updatedRows == 0) {
            throw new WebSearchException(WebSearchErrorCode.WEB_SEARCH_CONTENT_NOT_FOUND);
        }
        
        // 6. 清除权限缓存
        webSearchCacheService.clearPermissionCache(userId, messageId);
        
        return true;
        
    } finally {
        // 7. 确保锁被释放
        redisTemplate.delete(lockKey);
    }
}
```

## 🔧 故障排查指南

### 1. 常见问题及解决方案

#### 问题1: 频率限制过于严格
```
症状: 用户反馈请求被频繁拒绝
排查: 检查Redis中的计数器
解决: 调整频率限制参数或检查Redis连接

# 检查Redis中的频率限制数据
redis-cli
> KEYS web_search_update:rate_limit:user:*
> GET web_search_update:rate_limit:user:123:1642694400
```

#### 问题2: 权限缓存失效
```
症状: 权限验证响应时间过长
排查: 检查Caffeine缓存统计
解决: 检查缓存配置或数据库查询性能

# 查看缓存统计日志
grep "权限缓存统计" logs/application.log
```

#### 问题3: 分布式锁死锁
```
症状: 请求长时间等待
排查: 检查Redis中的锁状态
解决: 清理过期锁或调整锁超时时间

# 检查Redis中的锁
redis-cli
> KEYS web_search_update_lock:*
> TTL web_search_update_lock:message-id
```

### 2. 日志分析
```bash
# 查看网络搜索修改相关日志
tail -f logs/application.log | grep -E "(网络搜索修改|WebSearch)"

# 查看错误日志
grep "WebSearchException" logs/application.log | tail -20

# 查看性能监控日志
grep "WebSearchMetrics" logs/application.log | tail -10

# 分析频率限制日志
grep "频率超限" logs/application.log | wc -l
```
