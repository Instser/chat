# 管理员后台日志查看页面

- **时间**: 2026-08-26 12:20 (北京时间)
- **版本**: v1.0
- **变更类型**: 新功能（后端日志查看接口 + 前端日志页面）

## 一、背景

管理员后台此前缺少应用日志/报错日志的查看接口，管理员看日志只能 SSH 上服务器 `tail` 或在运维中心的 AI 错误分析框里手动粘贴。本次新增日志查看页面，支持按 traceId 筛选、关键词搜索、级别过滤。

## 二、后端

### 接口（`/admin/log-viewer`）

路径选择 `/admin/log-viewer` 而非 `/admin/logs`，因为旧的 `LogManagementController`（`@Deprecated`）已占用 `/admin/logs/**` 且在 SecurityConfig 中 `permitAll`（API Key 鉴权）。新路径落到 `/admin/**` 规则，强制 JWT + ROLE_ADMIN 鉴权。

**新增**：
- `src/main/java/com/instser/chat/admin/controller/AdminLogController.java`
  - `GET /admin/log-viewer/files` — 列出可用日志文件及状态（文件名、是否存在、大小、最后修改时间）
  - `GET /admin/log-viewer/tail` — 读取日志尾部，参数：
    - `file`（默认 `jinyu-chat-all.log`，白名单校验）
    - `lines`（默认 500，上限 5000）
    - `traceId`（按 `[traceId]` 包含匹配）
    - `keyword`（忽略大小写包含匹配）
    - `level`（ERROR/WARN/INFO/DEBUG，匹配日志行中的级别标记）
- `src/main/java/com/instser/chat/admin/service/AdminLogService.java`
  - 文件白名单：`jinyu-chat-all.log`、`jinyu-chat-error.log`、`jinyu-chat-monitor.log`（防路径穿越）
  - 高效尾部读取：`RandomAccessFile` 从后向前按 4KB 块读取，收集尾部 N 行
  - 三级筛选：traceId（`[xxx]` 匹配）、keyword（忽略大小写）、level（` ERROR ` 标记匹配）

### 安全
- 文件名白名单校验，拒绝任意路径读取
- 强制 JWT + ROLE_ADMIN（`@PreAuthorize("hasRole('ADMIN')")` + SecurityConfig `/admin/**` 规则）
- 单行最大 20000 字节截断，防止超长行撑爆响应

## 三、前端

**新增**：
- `admin-web/src/views/LogsView.vue` — 日志查看页面
  - 文件选择（下拉，显示存在状态）
  - Trace ID 输入框（回车查询）
  - 关键词输入框（忽略大小写，回车查询）
  - 级别选择（全部/ERROR/WARN/INFO/DEBUG）
  - 行数选择（200/500/1000/3000）
  - 日志内容区（黑底等宽字体，最大高 600px 可滚动）
  - 统计信息（读取行数、筛选后行数）
  - 复制全部按钮

**修改**：
- `admin-web/src/api/admin.ts` — 新增 `listLogFiles`、`tailLog` API 函数 + `LogFile`/`LogTail` 类型导入
- `admin-web/src/types/api.ts` — 新增 `LogFile`、`LogTail` 接口
- `admin-web/src/router/index.ts` — 新增 `/logs` 路由
- `admin-web/src/layouts/AdminLayout.vue` — 菜单新增「日志查看」（运维中心之后）

## 五、与 traceId 全链路优化的配合

本次日志查看页面的 traceId 筛选功能，与上一轮「traceId 全链路贯穿日志系统优化」（`docs/26-08-26_11-59_traceId全链路贯穿日志系统优化_v1.0.md`）配合使用：
- traceId 优化确保所有线程（@Async/@Scheduled/Reactor）的日志都带 traceId
- 本日志页面支持按 traceId 筛选，管理员可输入一个 traceId 查看该请求的完整链路日志（含异步线程）
