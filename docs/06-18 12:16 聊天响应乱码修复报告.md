## 问题描述

### 问题现象
在进行聊天响应时，会错误地附带两个问号（??），影响用户体验。

### 问题原因分析
1. **字符编码转换问题**：从DataBuffer转换为字符串时，某些字节序列无法正确解码为UTF-8字符
2. **替换字符产生**：当遇到无效的字节序列时，Java会插入替换字符（\uFFFD），在某些情况下显示为问号
3. **控制字符干扰**：AI响应中可能包含控制字符或其他无效字符
4. **字符过滤缺失**：原有代码没有对接收到的字符进行有效性验证和清理

### 影响范围
- 所有聊天响应可能出现乱码字符
- 用户体验受到影响
- 前端显示异常

## 修复方案

### 🔧 核心修复

#### 1. DataBuffer字符编码优化
```java
// 修复前
String chunk = new String(bytes, StandardCharsets.UTF_8);

// 修复后
String chunk = new String(bytes, StandardCharsets.UTF_8);
// 过滤掉替换字符（问号）和其他无效字符

```

#### 2. 添加内容清理方法
```java
/**
 * 清理内容，移除无效字符和替换字符
 */
private String cleanContent(String content) {
    if (content == null) {
        return "";
    }
    
    // 移除替换字符（�）、控制字符和其他无效字符
    String cleaned = content.replaceAll("[\uFFFD\u0000-\u0008\u000B\u000C\u000E-\u001F\u007F-\u009F]", "");
    
    // 移除连续的多个空格，但保留单个空格和换行
    cleaned = cleaned.replaceAll(" {2,}", " ");
    
    return cleaned;
}
```

#### 3. 添加字符有效性验证
```java
/**
 * 验证字符是否有效
 */
private boolean isValidCharacter(char ch) {
    // 排除替换字符（�）
    if (ch == '\uFFFD') {
        return false;
    }
    
    // 排除大部分控制字符，但保留常用的空白字符
    if (ch >= '\u0000' && ch <= '\u001F') {
        // 保留制表符、换行符、回车符
        return ch == '\t' || ch == '\n' || ch == '\r';
    }
    
    // 排除扩展控制字符
    if (ch >= '\u007F' && ch <= '\u009F') {
        return false;
    }
    
    return true;
}
```
