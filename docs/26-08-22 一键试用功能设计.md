# 一键试用（2 小时临时会话）功能设计

> 创建日期：2026-08-22
> 目标场景：简历演示站。HR 打开登录页，点击「一键试用」即可进入系统体验，无需注册。

## 1. 核心原则

- **体验内容与普通用户完全一致**：不显示任何「试用模式」「剩余时间」等横幅或文案，前端只多一个「一键试用」按钮。
- **唯一区别是会话过期时间**：普通登录 JWT 为 7 天；试用 JWT/Cookie 为 2 小时。过期后行为与普通登录过期一致（401 → 回到登录页）。
- **复用现有认证体系**：体验用户就是 `t_user` 里的普通 `role=USER` 记录，`JwtAuthenticationFilter`、套餐、用量统计等既有逻辑零改动。
- **额度问题暂不处理**（后续单独讨论）：JWT claim 中已埋 `authType=trial` 钩子，后续可按用户/试用维度统计限额。

## 2. 交互流程

```
HR 点击「一键试用」
  → POST /api/auth/trial  { guestId? }
  → 后端：IP 限流检查 → 查找/创建体验用户 → 签发 2h JWT → Set-Cookie(auth-token)
  → 前端进入主页，体验与普通用户完全一致
2 小时后 JWT/Cookie 过期 → 401 → 回到登录页 → 可再次点击试用
（前端本地保存 guestId，48h 内重复试用复用同一体验用户，聊天记录保留）
```

## 3. 后端实现

| 文件 | 改动 |
|------|------|
| `config/TrialProperties.java` | 新增配置：开关 / 会话时长 2h / 用户保留 48h / IP 日限 10 次 / guest 前缀 |
| `util/JwtUtil.java` | 新增 `generateToken(user, ttl)`、`generateTrialToken(user, ttl)`（含 `authType=trial` claim）、`createAuthCookie(token, maxAge)` |
| `service/UserService.java` | 新增 `registerGuestUser`（与 OAuth2 注册共用 `createUserInternal`，自动绑定默认套餐） |
| `service/serviceimpl/TrialServiceImpl.java` | 核心逻辑：IP 限流（Redis，异常放行）→ 查找/复用或创建 guest → 签发短时效 JWT；`@Scheduled` 每天 03:10 清理超过保留时长的 guest（软删） |
| `controller/AuthController.java` | 新增 `POST /auth/trial`（permitAll），响应与 `/auth/login` 一致（返回 UserVO + 登录成功） |
| `config/SecurityConfig.java` | `/auth/trial` 加入公开接口 |
| `application.yml` | `trial.*` 配置块，均可用环境变量覆盖 |

## 5. 安全细节

- guest 用户密码为 32 字节随机串（BCrypt），不存在密码登录的可能；仅能通过 `/auth/trial` 获取会话。
- guest 为 `role=USER` + 默认套餐，无法访问 `/admin/**`。
- IP 维度每日限流（默认 10 次/天/IP），防脚本刷体验账号；Redis 异常时放行（保证可用性优先）。
- 体验用户 48h 未活跃后由定时任务软删除（`deleted=1`），历史聊天数据保留。
- 生产环境可通过 `TRIAL_ENABLED=false` 关闭该入口。

## 7. 配置项速查

|----------|--------|------|
