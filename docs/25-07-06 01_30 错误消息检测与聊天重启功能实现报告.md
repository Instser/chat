## 需求背景

### 用户反馈
用户要求增加对特定错误消息的检测：
```
Request blocked. Please reach out to support@example.com if you think this was a mistake.
```
检测到这个消息时应该直接重新开始聊天。

### 问题分析
- 这个错误消息表明请求被阻止，需要特殊处理
- 与普通的过滤内容不同，这种错误需要触发聊天重启
- 需要在所有聊天分支中检测这种错误消息

## 解决方案

### 🔧 实现错误消息检测与处理

#### 1. 新增错误消息检测方法
创建专门的方法来检测需要重新开始聊天的错误消息：

```java
/**
 * 检查内容是否包含需要重新开始聊天的错误消息
 * 检测到特定错误消息时应该重新开始聊天
 */
private boolean shouldRestartChat(String content) {
    if (content == null || content.trim().isEmpty()) {
        return false;
    }

    // 定义需要重新开始聊天的错误消息模式
    String[] restartPatterns = {
        "Request blocked. Please reach out to support@example.com if you think this was a mistake."
    };

    // 检查是否包含任何重新开始模式
    for (String pattern : restartPatterns) {
        if (content.contains(pattern)) {
            log.info("检测到需要重新开始聊天的错误消息: [{}]", pattern);
            return true;
        }
    }

    return false;
}
```

#### 2. 增强主要内容清理方法
在`cleanContentWithFilterInfo`方法中添加错误消息检测：

```java
private ContentCleanResult cleanContentWithFilterInfo(String content) {
    if (content == null) {
        return new ContentCleanResult("", false);
    }

    // 检查是否包含需要重新开始聊天的错误消息
    if (shouldRestartChat(content)) {
        log.warn("检测到需要重新开始聊天的错误消息，触发聊天重启");
        // 返回空字符串但标记为已过滤，表示这是真实的AI响应
        return new ContentCleanResult("", true);
    }

    // 检查是否包含需要过滤的内容
    if (shouldFilterContent(content)) {
        log.info("检测到需要过滤的AI响应内容，已阻止向前端发送");
        return new ContentCleanResult("", true);
    }

    // 基础清理：移除无效字符
    String cleaned = content.replaceAll("[\uFFFD\u0000]", "");
    cleaned = cleaned.replaceAll(" {2,}", " ");

    return new ContentCleanResult(cleaned, false);
}
```

## 技术实现细节

### 1. 检测覆盖范围
- **普通聊天**: 通过`processCompleteJson` → `cleanContentWithFilterInfo`路径
- **续写缓存清理**: 通过`cleanAllTagsOnce`方法
- **续写开始清理**: 通过`cleanContinuationContent`方法
- **续写后续内容**: 通过`processContinuationJson`中的直接检测
- **重试功能**: 通过主流程自动覆盖
- **编辑重发**: 通过主流程自动覆盖

### 2. 处理策略
- **错误消息检测**: 精确匹配特定的错误消息文本
- **日志记录**: 使用WARN级别记录错误消息检测
- **内容处理**: 返回空字符串，阻止向前端发送
- **状态保持**: 仍然累积到`aiResponseContent`中，保持业务逻辑完整性

### 3. 与过滤功能的区别
- **检测优先级**: 错误消息检测优先于普通过滤检测
- **日志级别**: 错误消息使用WARN级别，普通过滤使用INFO级别
- **处理方式**: 两者都返回空字符串，但日志消息不同

### 4. 扩展性设计
- **模式数组**: 使用数组存储错误消息模式，便于扩展
- **独立方法**: `shouldRestartChat`方法独立于过滤逻辑，便于维护
- **统一处理**: 在所有内容处理点都应用相同的检测逻辑
