## 重构概述

根据用户需求，对文件上传功能进行了全面的数据库结构重构，主要包括：删除file_url字段、增加messageId字段用于消息关联、增加content字段用于存储大量文件内容，并创建了完整的文件管理架构。

## 数据库结构变更

### 1. t_file_upload表结构修改

#### 删除的字段
- `file_url` - 不再需要URL访问方式

#### 新增的字段
- `message_id` varchar(64) - 关联的消息ID，支持文件与聊天消息的关联
- `content` longtext - 文件内容字段，用于存储文本文件或小文件的完整内容

#### 新增的索引
- `idx_message_id` - 消息ID索引，提升查询性能
- `idx_user_message_deleted` - 复合索引：用户ID + 消息ID + 删除标志
- `idx_session_message_time` - 复合索引：会话ID + 消息ID + 创建时间
- `idx_type_status_time` - 复合索引：文件类型 + 状态 + 创建时间

#### 新增的外键约束
- `fk_file_message` - message_id关联到t_chat_message表的message_id字段

### 2. 修改后的完整表结构

```sql
CREATE TABLE `t_file_upload` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `file_id` varchar(64) COLLATE utf8mb4_unicode_ci NOT NULL COMMENT '文件ID（UUID）',
  `user_id` bigint NOT NULL COMMENT '用户ID',
  `session_id` varchar(64) COLLATE utf8mb4_unicode_ci DEFAULT NULL COMMENT '关联的会话ID',
  `message_id` varchar(64) COLLATE utf8mb4_unicode_ci DEFAULT NULL COMMENT '关联的消息ID',
  `file_name` varchar(255) COLLATE utf8mb4_unicode_ci NOT NULL COMMENT '文件名',
  `file_type` varchar(100) COLLATE utf8mb4_unicode_ci NOT NULL COMMENT '文件类型（MIME类型）',
  `file_size` bigint NOT NULL COMMENT '文件大小（字节）',
  `storage_path` varchar(500) COLLATE utf8mb4_unicode_ci NOT NULL COMMENT '存储路径',
  `content` longtext COLLATE utf8mb4_unicode_ci DEFAULT NULL COMMENT '文件内容',
  `status` tinyint DEFAULT '0' COMMENT '状态（0-处理中，1-可用，2-失败）',
  `create_time` datetime DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` datetime DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted` tinyint DEFAULT '0' COMMENT '逻辑删除标志（0-未删除，1-已删除）',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_file_id` (`file_id`),
  KEY `idx_user_id` (`user_id`),
  KEY `idx_session_id` (`session_id`),
  KEY `idx_message_id` (`message_id`),
  KEY `idx_user_message_deleted` (`user_id`,`message_id`,`deleted`),
  KEY `idx_session_message_time` (`session_id`,`message_id`,`create_time`),
  KEY `idx_type_status_time` (`file_type`,`status`,`create_time`),
  CONSTRAINT `fk_file_user` FOREIGN KEY (`user_id`) REFERENCES `t_user` (`id`),
  CONSTRAINT `fk_file_session` FOREIGN KEY (`session_id`) REFERENCES `t_chat_session` (`session_id`),
  CONSTRAINT `fk_file_message` FOREIGN KEY (`message_id`) REFERENCES `t_chat_message` (`message_id`) ON DELETE SET NULL ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='文件上传表 - 支持文件内容存储和消息关联';
```
