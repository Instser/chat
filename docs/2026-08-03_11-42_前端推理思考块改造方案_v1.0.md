## 1. 目标与边界

### 1.1 目标

在不升级 AI SDK 主版本的前提下，让前端：

1. **实时**消费后端 AI SDK Data Stream v1 的 `g:` 思考增量  
2. **历史**回放后端消息字段 `reasoning`  
3. **统一**用同一套消息形态 + `ThinkingBlock` 渲染  
4. **复制**只复制正文 `content`，不把思考混进复制文本  
5. **继续**用现有产品开关 `isDeepThinking` → 请求体 `deepThinking`（不再加第二套开关）

### 1.2 不做

| 不做 | 原因 |
|------|------|
| 升级到 AI SDK v5/v6 | 4.3.16 已支持 `g:` / `message.reasoning` / parts |
| 把 reasoning 拼进 `content` | 污染正文与后续上下文 |
| 通用 message parts JSON 大重构 | 成本高、本阶段不需要 |
| 运维/配置级 reasoning 开关 | 后端已定稿：仅 `deepThinking` |
| 依赖 markdown 正则从正文抠 thinking 作为主路径 | 后端已平行下发 `g:` / `reasoning` |
| 修改后端 JDK / 新增依赖（前端侧） | 本阶段只改前端行为与锁定版本 |

### 1.3 与后端契约（前端只消费）

| 方向 | 约定 |
|------|------|
| 请求 | `deepThinking: true/false`（chat / retry / edit-resend 都已能传） |
| 流 | `g:"思考"` + `0:"正文"` + `u:{...}` + `d:{...}` |
| 历史 | `ChatMessageVO.reasoning`（可空） |
| 模型上下文 | 前端发消息时仍只发 `role` + `content`（后端也不回喂 reasoning） |

## 3. 目标消息模型（前后端统一认知）

前端 UI 消息（assistant）最终应具备：

```ts
type UiChatMessage = {
  id: string
  role: 'user' | 'assistant' | 'system' | 'data'
  content: string                 // 仅正文
  reasoning?: string              // 仅思考；可空
  parts?: Array<
    | { type: 'reasoning'; reasoning: string }
    | { type: 'text'; text: string }
    | { type: string; [k: string]: any }
  >
  // 既有扩展字段继续保留
  filesName?: string
  networkResult?: any
  createdAt?: Date
  updatedAt?: Date
}
```

### 3.1 归一化规则

统一入口：`lib/message-normalize.ts`

```ts
export function normalizeAssistantMessage(input: any): UiChatMessage {
  const reasoning =
    pickNonEmpty(input.reasoning) ??
    pickNonEmpty(extractReasoningFromParts(input.parts)) ??
    undefined

  const content =
    pickNonEmpty(input.content) ??
    pickNonEmpty(extractTextFromParts(input.parts)) ??
    ''

  const parts = [
    ...(reasoning ? [{ type: 'reasoning' as const, reasoning }] : []),
    ...(content ? [{ type: 'text' as const, text: content }] : []),
  ]

  return {
    ...input,
    content,
    reasoning,
    parts,
  }
}
```

规则：

1. **优先**显式字段 `reasoning` / `content`  
2. 其次从 SDK `parts` 提取  
3. **禁止**把 reasoning 写回 content  
4. 空 reasoning 不生成 reasoning part，避免空思考块  

使用点：

- 历史消息 `currentMessages → setMessages`  
- `useChat` `onFinish` / 必要时 messages 映射  
- retry/edit 手写流结束后的本地 assistant 消息  
- 任何从后端 DTO 转 UI 的适配层

## 4. 流协议处理改造

### 4.1 主聊天路径（`useAIChat` + 自定义 `fetch`）

现状：自定义 `fetch` 读流后按行过滤，把 `u:` 自己吃掉，把其余喂给 SDK。

**目标过滤规则（定稿）：**

```ts
if (line.startsWith('0:') || line.startsWith('g:') || line.startsWith('d:')) {
  filteredLines.push(line)          // 交给 AI SDK 4.3.16
} else if (line.startsWith('u:')) {
  handleNetwork(line)               // 前端自处理，不进 SDK
} else if (line.trim() === '') {
  filteredLines.push(line)
} else {
  filteredLines.push(line)          // 未知前缀默认透传，避免再次吞协议
}
```

注意：

1. **必须显式放行 `g:`**，不要依赖“掉进 else”  
2. 不要把 `g:` 拼进 content 再喂 SDK  
3. 保持响应头 `x-vercel-ai-data-stream: v1` 原样透传（后端已设）  
4. 请求体仍只发最新一条 `role+content`，并带 `deepThinking` / `sessionId` / `modelId` / `network` / `filesId`

### 4.2 手写流路径（retry / edit-resend：`handleStreamResponse`）

现状只处理：

- `0:` → 累加 content  
- `u:` → 联网  
- `d:` → 完成  

**目标双缓冲：**

```ts
let content = ''
let reasoning = ''

if (line.startsWith('g:')) {
  reasoning += JSON.parse(line.slice(2))
  upsertAssistantMessage({ content, reasoning })
} else if (line.startsWith('0:')) {
  content += JSON.parse(line.slice(2))
  upsertAssistantMessage({ content, reasoning })
} else if (line.startsWith('u:')) {
  // 既有联网逻辑
} else if (line.startsWith('d:')) {
  // 既有完成/标题逻辑
}
```

`upsertAssistantMessage` 写入的对象必须带 `reasoning`，并调用 `normalizeAssistantMessage`。

### 4.3 deepThinking 行为（前端侧）

| UI 开关 | 请求 | UI 期望 |
|---------|------|---------|
| 开 | `deepThinking: true` | 可能出现 `g:`；有则显示 ThinkingBlock |
| 关 | `deepThinking: false` | 不应出现有效思考；即使偶发 `g:` 也可显示，但后端会 drop（以前端不依赖偶发为准） |

前端**不**根据开关隐藏历史已有 reasoning：历史有就显示（用户回看）。

## 5. UI 渲染改造

### 5.1 迁入组件

从 `Downloads/tousechat-main/frontend/components/` 迁入权威仓库：

1. `thinking-effect.tsx`  
2. `thinking-block.tsx`  

要求：

- 无内容（`!content`）不渲染  
- 支持 `isThinking` / `autoCollapse`  
- 思考中：展开 + 动效  
- 思考结束：可自动折叠（`autoCollapse=true`）  
- 样式与现有 message-paper / 主题一致（迁入后按 chat-view 视觉微调，不重做设计系统）

### 5.2 assistant 渲染顺序（定稿）

```tsx
{m.role !== 'user' && (
  <>
    {reasoningText ? (
      <ThinkingBlock
        content={reasoningText}
        isThinking={isStreamingThisMessage && !contentSettled}
        autoCollapse
      />
    ) : null}
    {contentText ? (
      <MarkdownRenderer isGenerating={isStreamingThisMessage}>
        {contentText}
      </MarkdownRenderer>
    ) : null}
  </>
)}
```

`reasoningText` 取值优先级：

1. `m.reasoning`  
2. `parts` 中 `type==='reasoning'` 的拼接  
3. 无则不渲染块  

`contentText` 取值优先级：

1. `m.content`  
2. `parts` 中 text  

### 5.3 `isThinking` 判定

推荐：

```ts
const isThisLastAssistant = m.id === lastAssistantId
const isThinking =
  (isLoading || isStreaming) &&
  isThisLastAssistant &&
  !!reasoningText &&
  // 若已开始稳定输出正文，可仍保持折叠态由 autoCollapse 处理；
  // isThinking 更偏向“思考仍在增长”
  reasoningStillGrowing
```

落地时可简化为：

- 当前最后一条 assistant  
- 且 `isLoading || isStreaming`  
- 且存在 reasoning  

避免对历史消息错误显示“思考中”。

### 5.4 复制行为

| 动作 | 复制内容 |
|------|----------|
| 复制消息 | **仅 content** |
| 思考块内部（若后续加复制） | 仅 reasoning（可选，本阶段可不做） |

`handleCopyMessage` 入参继续传 `m.content`，不要传 `content + reasoning`。

### 5.5 与 markdown 旧 thinking 路径关系

`markdown-renderer.tsx` 内对 `<thinking>` / ` ```thinking ` 的正则：

- **本阶段保留**作降级兼容（旧数据/异常模型把思考写进正文）  
- **主路径不再依赖它**  
- 禁止为了新功能继续扩大正则分支  

若同一消息既有 `reasoning` 字段又有正文内 thinking 标签：

- 优先显示字段 `reasoning` 的 ThinkingBlock  
- MarkdownRenderer 仍可能从 content 再抠一层；实施时对“已有独立 reasoning 的消息”可选择给 MarkdownRenderer 增加 `disableInlineThinkingParse`，避免双份思考 UI（**推荐做**，小改动）

## 14. 附录：与后端字段对照

| 后端 | 前端 |
|------|------|
| 流 `g:{json string}` | SDK reasoning / 手写 `reasoning` 缓冲 |
| 流 `0:{json string}` | content |
| 流 `u:{json}` | network sidebar |
| 流 `d:{json}` | finish / title |
| DB/VO `reasoning` | `Message.reasoning` → ThinkingBlock |
| DB/VO `content` | `Message.content` → MarkdownRenderer |
| 请求 `deepThinking` | `isDeepThinking` 开关 |

---

**一句话**：前端只做三件事——**锁 SDK、放行并累计 `g:`、把历史 `reasoning` 与实时 reasoning 归一后交给 ThinkingBlock**；正文与思考永远分开，复制与回喂都只用 content。
