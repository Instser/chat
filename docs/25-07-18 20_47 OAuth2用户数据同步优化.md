# OAuth2用户数据同步优化

**时间**: 2025年07月18日 20:47  
**版本**: v1.3.0  
**修改类型**: 数据一致性优化

## 问题背景

在OAuth2登录系统中发现数据不一致问题：
- **User表** 和 **UserOAuth表** 都有 `last_login_time` 字段
- 原实现只更新OAuth表的登录时间，未同步更新User表
- 导致同一用户在两个表中的最后登录时间不一致
- 影响数据统计和用户行为分析的准确性

## 数据同步需求

### 需要同步的字段

| 字段名 | User表 | UserOAuth表 | 同步场景 |
|--------|--------|-------------|----------|
| `last_login_time` | ✅ | ✅ | 所有OAuth2登录场景 |
| `login_count` | ❌ | ✅ | OAuth表独有统计 |
| `avatar` | ✅ | ✅ | 用户信息变更时 |
| `email` | ✅ | ✅ | 用户信息变更时 |

### 同步场景分析

1. **已存在用户登录** (`EXISTING_USER`)
   - OAuth表：更新 `last_login_time`、`login_count`
   - User表：更新 `last_login_time`

2. **新用户注册** (`NEW_USER`)
   - User表：创建时设置 `last_login_time`
   - OAuth表：创建时设置 `last_login_time`

3. **新绑定登录** (`NEW_BINDING`)
   - OAuth表：创建时设置 `last_login_time`
   - User表：更新 `last_login_time`

## 解决方案

### 1. 优化已存在用户登录同步

**修改前**：
```java
private void updateOAuthLoginInfo(UserOAuth oauth, OAuth2UserInfo userInfo) {
    oauth.setLastLoginTime(LocalDateTime.now());
    oauth.setLoginCount(oauth.getLoginCount() + 1);
    // 只更新OAuth表
    userOAuthDao.updateById(oauth);
}
```

**修改后**：
```java
private void updateOAuthLoginInfo(UserOAuth oauth, OAuth2UserInfo userInfo) {
    LocalDateTime now = LocalDateTime.now();
    
    // 更新OAuth表的登录信息
    oauth.setLastLoginTime(now);
    oauth.setLoginCount(oauth.getLoginCount() + 1);
    userOAuthDao.updateById(oauth);
    
    // 同步更新User表的最后登录时间
    userService.updateLastLoginTime(oauth.getUserId());
    
    log.debug("【OAuth登录信息同步】已同步更新User表和OAuth表的最后登录时间，用户ID：{}", oauth.getUserId());
}
```

### 2. 优化新用户注册同步

**修改前**：
```java
// UserServiceImpl.registerUser()
User user = new User();
user.setUsername(username);
user.setEmail(email);
// 未设置 lastLoginTime
user.setCreatedTime(LocalDateTime.now());
```

**修改后**：
```java
// UserServiceImpl.registerUser()
LocalDateTime now = LocalDateTime.now();
User user = new User();
user.setUsername(username);
user.setEmail(email);
user.setLastLoginTime(now); // OAuth2注册即登录，设置最后登录时间
user.setCreatedTime(now);
```

### 3. 优化新绑定登录同步

**修改前**：
```java
// 邮箱已存在，绑定OAuth账号
UserOAuth newOAuth = createOAuthBinding(existingUser.getId(), userInfo);
userOAuthDao.insert(newOAuth);
// 未更新User表的登录时间
return OAuth2LoginResult.newBinding(existingUser);
```

**修改后**：
```java
// 邮箱已存在，绑定OAuth账号
UserOAuth newOAuth = createOAuthBinding(existingUser.getId(), userInfo);
userOAuthDao.insert(newOAuth);

// 更新User表的最后登录时间（新绑定也算登录）
userService.updateLastLoginTime(existingUser.getId());

return OAuth2LoginResult.newBinding(existingUser);
```

## 数据一致性保障

### 1. 时间同步策略
```java
// 使用统一的时间戳确保一致性
LocalDateTime now = LocalDateTime.now();
oauth.setLastLoginTime(now);
user.setLastLoginTime(now);
```

### 2. 事务保障
- 所有数据库操作在同一事务中执行
- 确保要么全部成功，要么全部回滚
- 避免部分更新导致的数据不一致

### 3. 日志追踪
```java
log.debug("【OAuth登录信息同步】已同步更新User表和OAuth表的最后登录时间，用户ID：{}", oauth.getUserId());
```

## 优势

### 1. 数据一致性
- ✅ User表和OAuth表的登录时间保持同步
- ✅ 避免数据分析时的混乱
- ✅ 提高数据质量和可信度

### 2. 业务准确性
- ✅ 用户最后登录时间统计准确
- ✅ 活跃用户分析更精确
- ✅ 用户行为追踪完整

### 3. 系统维护性
- ✅ 减少数据不一致导致的问题
- ✅ 简化数据查询和统计逻辑
- ✅ 提高系统可维护性

## 影响范围

### 1. 数据库表
- `t_user.last_login_time` - 所有OAuth2登录都会更新
- `t_user_oauth.last_login_time` - 保持原有更新逻辑

### 2. 业务逻辑
- OAuth2登录流程 - 增加User表同步更新
- 用户注册流程 - 新增登录时间设置
- 账号绑定流程 - 增加登录时间更新

### 3. 性能影响
- 每次OAuth2登录增加1次User表更新操作
- 影响微乎其微，可忽略不计

## 测试验证

### 验证步骤
1. OAuth2登录后检查两表的 `last_login_time` 是否一致
2. 新用户注册后检查登录时间是否正确设置
3. 新绑定后检查User表登录时间是否更新

### 预期结果
```sql
-- 验证数据一致性
SELECT 
    u.id,
    u.last_login_time as user_login_time,
    uo.last_login_time as oauth_login_time,
    ABS(TIMESTAMPDIFF(SECOND, u.last_login_time, uo.last_login_time)) as time_diff
FROM t_user u 
JOIN t_user_oauth uo ON u.id = uo.user_id 
WHERE ABS(TIMESTAMPDIFF(SECOND, u.last_login_time, uo.last_login_time)) > 1;
-- 应该返回空结果或时间差很小的记录
```
