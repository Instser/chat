## 需求分析

### 用户需求
- **免费套餐限制**：每天30次，总共100次
- **复合限制策略**：需要同时支持每日限制和总次数限制
- **灵活配置**：不同套餐可以有不同的限制策略

### 现有问题
1. **单一限制类型**：当前只支持每日限制或总次数限制，不支持复合限制
2. **字段命名不清晰**：`chat_count`和`daily_chat_limit`含义模糊
3. **限制策略单一**：`limit_type`只有daily和total两种，无法表达复合限制

## 解决方案

### 🔧 数据库结构优化

#### 1. 新增字段
```sql
-- 总聊天次数限制
ADD COLUMN `total_chat_limit` int(11) NOT NULL DEFAULT 1000 COMMENT '总聊天次数限制（-1表示无限制）'

-- 每日聊天次数限制（新）
ADD COLUMN `daily_chat_limit_new` int(11) NOT NULL DEFAULT 30 COMMENT '每日聊天次数限制（-1表示无限制）'

-- 限制策略
ADD COLUMN `limit_strategy` varchar(20) NOT NULL DEFAULT 'both' COMMENT '限制策略（daily-仅每日限制，total-仅总次数限制，both-双重限制，unlimited-无限制）'
```

#### 2. 限制策略说明
| 策略值 | 说明 | 限制逻辑 |
|--------|------|----------|
| `daily` | 仅每日限制 | 只检查每日使用次数，不限制总次数 |
| `total` | 仅总次数限制 | 只检查总使用次数，不限制每日次数 |
| `both` | 双重限制 | 同时检查每日和总次数，任一达到限制即停止 |
| `unlimited` | 无限制 | 不限制使用次数 |

### 📊 套餐配置方案

#### 免费套餐配置
```sql
UPDATE `t_package` SET 
    `total_chat_limit` = 100,        -- 总共100次
    `daily_chat_limit_new` = 30,     -- 每天30次
    `limit_strategy` = 'both'        -- 双重限制
WHERE `id` = 1;
```

## 技术实现

### 🎯 核心逻辑

#### 1. 限制检查逻辑
```java
public boolean checkChatLimit(Long userId, Package packageInfo) {
    String strategy = packageInfo.getLimitStrategy();
    
    switch (strategy) {
        case "daily":
            return checkDailyLimit(userId, packageInfo.getDailyLimitNew());
        case "total":
            return checkTotalLimit(userId, packageInfo.getTotalChatLimit());
        case "both":
            return checkDailyLimit(userId, packageInfo.getDailyLimitNew()) 
                && checkTotalLimit(userId, packageInfo.getTotalChatLimit());
        case "unlimited":
            return true;
        default:
            return false;
    }
}
```

#### 2. 双重限制验证
```java
private boolean checkBothLimits(Long userId, Package packageInfo) {
    // 检查每日限制
    boolean dailyOk = checkDailyLimit(userId, packageInfo.getDailyLimitNew());
    if (!dailyOk) {
        return false; // 每日限制已达到
    }
    
    // 检查总次数限制
    boolean totalOk = checkTotalLimit(userId, packageInfo.getTotalChatLimit());
    if (!totalOk) {
        return false; // 总次数限制已达到
    }
    
    return true; // 两个限制都未达到
}
```

### 🚀 新增功能

#### 1. 套餐限制视图
```sql
CREATE VIEW `v_package_limits` AS
SELECT 
    p.id,
    p.package_name,
    p.total_chat_limit,
    p.daily_chat_limit_new as daily_chat_limit,
    p.limit_strategy,
    CASE 
        WHEN p.limit_strategy = 'daily' THEN CONCAT('每日', p.daily_chat_limit_new, '次')
        WHEN p.limit_strategy = 'total' THEN CONCAT('总共', p.total_chat_limit, '次')
        WHEN p.limit_strategy = 'both' THEN CONCAT('每日', p.daily_chat_limit_new, '次，总共', p.total_chat_limit, '次')
        WHEN p.limit_strategy = 'unlimited' THEN '无限制'
    END as limit_description
FROM `t_package` p
WHERE p.deleted = 0;
```

#### 2. 性能优化
```sql
-- 添加索引提高查询性能
ALTER TABLE `t_package` ADD INDEX `idx_limit_strategy` (`limit_strategy`);
```

## 业务影响分析

### 🚀 正面影响

#### 1. 用户体验提升
- **更灵活的限制**：免费用户可以每天使用30次，不会因为一天用完就无法使用
- **公平的总量控制**：防止免费用户无限制使用资源
- **清晰的限制说明**：用户明确知道自己的使用限制

#### 2. 业务价值
- **资源控制**：有效控制免费用户的资源使用
- **付费转化**：合理的免费限制促进用户付费升级
- **成本控制**：避免免费用户过度使用导致成本失控

#### 3. 技术优势
- **配置灵活**：不同套餐可以配置不同的限制策略
- **扩展性强**：未来可以轻松添加新的限制策略
