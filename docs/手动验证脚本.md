# 每日限制逻辑修改手动验证脚本

## 📋 验证步骤

### 1. 启动应用程序
```bash
mvn spring-boot:run
```

### 2. 验证套餐配置

#### 查询套餐信息
```sql
-- 查看所有套餐的配置
SELECT 
    id,
    package_name,
    limit_type,
    model_permissions,
    chat_count,
    daily_chat_limit
FROM t_package 
WHERE deleted = 0
ORDER BY id;
```

#### 验证每日限制套餐
```sql
-- 查看每日限制套餐
SELECT 
    id,
    package_name,
    limit_type,
    model_permissions
FROM t_package 
WHERE limit_type = 'daily' AND deleted = 0;
```

### 3. 验证用户账户状态

#### 查看用户账户
```sql
-- 查看用户账户状态
SELECT 
    ua.id,
    ua.user_id,
    ua.package_id,
    ua.chat_count_remaining,
    p.package_name,
    p.limit_type
FROM t_user_account ua
JOIN t_package p ON ua.package_id = p.id
WHERE ua.deleted = 0 AND p.deleted = 0
ORDER BY ua.user_id;
```

#### 检查每日限制套餐用户
```sql
-- 检查使用每日限制套餐的用户
SELECT 
    ua.user_id,
    ua.chat_count_remaining,
    p.package_name,
    p.limit_type,
    CASE 
        WHEN ua.chat_count_remaining = -1 THEN '无限制(正确)'
        ELSE '有限制(需要修正)'
    END as status
FROM t_user_account ua
JOIN t_package p ON ua.package_id = p.id
WHERE p.limit_type = 'daily' 
  AND ua.deleted = 0 
  AND p.deleted = 0;
```

### 6. 数据库验证脚本

#### 执行验证查询
```sql
-- 1. 验证套餐配置完整性
SELECT 
    id,
    package_name,
    limit_type,
    CASE 
        WHEN model_permissions IS NULL OR model_permissions = '' THEN '缺少配置'
        WHEN JSON_VALID(model_permissions) = 0 THEN '配置格式错误'
        ELSE '配置正常'
    END as config_status,
    JSON_EXTRACT(model_permissions, '$.STANDARD.daily_limit') as standard_daily_limit
FROM t_package 
WHERE deleted = 0
ORDER BY id;

-- 2. 验证每日限制套餐用户状态
SELECT 
    '每日限制套餐用户状态' as description,
    COUNT(*) as total_users,
    SUM(CASE WHEN ua.chat_count_remaining = -1 THEN 1 ELSE 0 END) as unlimited_users,
    SUM(CASE WHEN ua.chat_count_remaining != -1 THEN 1 ELSE 0 END) as limited_users
FROM t_user_account ua
JOIN t_package p ON ua.package_id = p.id
WHERE p.limit_type = 'daily' 
  AND ua.deleted = 0 
  AND p.deleted = 0;

-- 3. 验证今日使用记录
SELECT 
    COUNT(*) as today_usage_records,
    COUNT(DISTINCT user_id) as active_users,
    SUM(chat_count_used) as total_chats_today
FROM t_user_daily_usage 
WHERE usage_date = CURDATE();
```

## 🔍 预期结果

### 1. 套餐配置验证
- 每日限制套餐的 `limit_type` 应为 `'daily'`
- `model_permissions` 应包含有效的JSON配置
- STANDARD模型应有正确的 `daily_limit` 值

### 2. 用户账户验证
- 使用每日限制套餐的用户，`chat_count_remaining` 应为 `-1`
- 其他类型套餐的用户保持原有的总次数限制

### 3. API响应验证
- 套餐信息API应正确返回计算后的总次数和每日限制
- 聊天限制API应正确显示每日限制套餐用户的无限总次数
- 聊天功能应正常工作，每日限制套餐用户不扣减总次数

### 4. 日志验证
- 套餐激活时应记录"为每日限制模式，总次数设置为无限制"
- 聊天使用时应记录"使用每日限制套餐，不扣减总次数"

```sql

UPDATE t_package 
SET model_permissions = '{"STANDARD":{"daily_limit":300,"description":"标准模型每日300次"}}'
WHERE id = ? AND (model_permissions IS NULL OR model_permissions = '');
```

```sql
-- 修复每日限制套餐用户的总次数
UPDATE t_user_account ua
JOIN t_package p ON ua.package_id = p.id
SET ua.chat_count_remaining = -1
WHERE p.limit_type = 'daily' 
  AND ua.chat_count_remaining != -1
  AND ua.deleted = 0 
  AND p.deleted = 0;
```
