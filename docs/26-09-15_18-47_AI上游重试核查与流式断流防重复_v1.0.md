# AI 上游重试机制核查与流式中途断流防重复修复 v1.0

**日期**：2026-09-15 18:47（北京时间）
**状态**：已完成开发与编译验证，**待部署**
**变更范围**：仅后端，无 DB/依赖/前端变更

## 一、核查结论（用户问题：三个等级模型共用同一 API，后端对 429/503 有正确重试吗？）

**有，且参数正是 20 次 × 500ms**（2026-08-26 上线的「AI 上游统一重试机制」）：

| 链路 | 覆盖范围 | 机制 |
|---|---|---|
| 流式对话（主链路） | chat / retry / edit-resend 三入口，所有模型等级共用 | `OpenAiCompatibleChatClient.stream()`：`Flux.defer` 重新建连 + `retryWhen`，任何上游错误（4xx/5xx/超时/连接失败）重试 |
| 同步 AI 调用 | 标题生成、Gemini 联网、管理端 AI 分析、图片解析 | `AiUpstreamRestTemplateInterceptor`（`aiRestTemplate` + Installer 挂载）：非 2xx/IO 异常重试 |
| 明确排除 | OAuth2 登录、模型可用性探测 | 不装拦截器，避免误伤 |

429/503 发生在 HTTP 响应状态阶段（流尚未输出任何内容），`retrieve()` 直接抛错 → 重新建连重试，**行为正确、无副作用**。此前配置类默认值即 20 次/500ms，但 application.yml 无显式配置段，本次已补显式配置（行为不变，仅提升可发现性与环境变量可调）。

## 二、核查中发现的两个隐患与修复

### 1. 流式中途断流会无条件重试 → 用户看到重复内容（本次修复）

原实现对流式任何阶段的错误都重试。若上游已输出部分 token 后连接断开/空闲超时（30s），重试会让上游**从头重新生成整段回复**，追加在已输出内容之后——用户看到重复文本。

修复：`stream()` 增加 `emitted` 标记（`doOnNext` 首个 DataBuffer 置位）：
- **未输出任何内容的失败**（429/503/连接拒绝/首包超时）→ 照常重试，安全
- **已输出内容的中途失败** → 透传原始错误，不重试，杜绝重复

附带：重试耗尽的异常现在以最后一次失败为 cause，保留根因链路。

### 2. 同步拦截器重试时不关闭上一次错误响应 → 连接泄漏（本次修复）

`AiUpstreamRestTemplateInterceptor` 每次拿到非 2xx 响应即覆盖 `lastResponse`，前一次的响应（429/503 带响应体）不关闭，HTTP 连接池连接被占住不放。修复：覆盖前关闭上一次响应，仅保留最后一次供耗尽时返回。

## 三、改动文件

- `service/ai/OpenAiCompatibleChatClient.java` — 流式重试加「未输出才重试」门控 + 耗尽异常带 cause
- `config/AiUpstreamRestTemplateInterceptor.java` — 重试循环中关闭上一次错误响应
- `application.yml` — 新增 `ai.upstream.retry` 显式配置段（`AI_UPSTREAM_RETRY_MAX_ATTEMPTS`/`AI_UPSTREAM_RETRY_FIXED_DELAY_MS`/`AI_UPSTREAM_RETRY_STREAM_ENABLED`/`AI_UPSTREAM_RETRY_SYNC_ENABLED`，默认 20/500/true/true，与原来代码默认值一致）
- `README-OPS.md` — 环境变量表追加两项
