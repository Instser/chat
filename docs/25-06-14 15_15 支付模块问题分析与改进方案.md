## 问题概述

经过深入分析支付模块代码，发现以下几个关键问题需要完善：

## 🚨 发现的问题

### 1. **过期订单处理缺失** ❌

**问题描述**：
- 订单设置了2小时过期时间，但没有自动处理过期订单的机制
- 过期订单仍然可以被支付，存在业务风险

**当前代码**：
```java
// OrderServiceImpl.java:69
order.setExpireTime(LocalDateTime.now().plusHours(2)); // 2小时后过期

// OrderServiceImpl.java:124-131
public boolean isOrderExpired(String orderNo) {
    // 只是检查，没有自动处理
}
```

**风险**：
- 过期订单占用系统资源
- 可能导致用户支付过期订单
- 数据库中积累大量无效订单

### 2. **重复支付验证不完善** ⚠️

**问题描述**：
- 支付回调处理时没有验证订单当前状态
- 可能导致已支付订单被重复处理

**当前代码**：
```java
// PaymentServiceImpl.java:256
boolean updated = orderService.updatePaymentStatus(order.getOrderNo(), newStatus, transactionId);
```

**风险**：
- 重复支付回调可能导致状态混乱
- 没有幂等性保证

### 3. **金额精度处理不规范** ⚠️

**问题描述**：
- 使用BigDecimal但没有统一的精度控制
- 货币转换时可能出现精度丢失

**当前代码**：
```java
// 数据库字段定义
`price_usd` decimal(10,2)
`amount` decimal(10,2)
```

**风险**：
- 金额计算可能出现精度误差
- 不同货币精度要求不同

### 4. **支付回调安全性不足** ⚠️

**问题描述**：
- 易支付回调没有充分的签名验证
- 缺少重放攻击防护

**当前代码**：
```java
// PaymentServiceImpl.java:295-343
// 易支付回调处理相对简单
```

### 5. **订单状态管理不完整** ⚠️

**问题描述**：
- 缺少订单状态流转控制
- 没有状态变更日志

**当前状态定义**：
- 0: 未支付
- 1: 已支付  
- 2: 已取消
- 3: 已退款

### 6. **定时任务缺失** ❌

**问题描述**：
- 没有定时清理过期订单的任务
- 没有订单状态同步任务

## 🔧 改进方案

### 1. 添加过期订单处理

**方案**：创建定时任务自动处理过期订单

### 2. 完善重复支付验证

**方案**：在支付回调中添加状态验证和幂等性控制

### 3. 规范金额精度处理

**方案**：统一金额处理工具类，确保精度一致性

### 4. 加强支付回调安全性

**方案**：完善签名验证，添加重放攻击防护

### 5. 完善订单状态管理

**方案**：添加状态流转控制和变更日志

### 6. 添加必要的定时任务

**方案**：创建订单清理和状态同步任务
