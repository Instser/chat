**监控指标**:
- SQL执行次数统计
- 平均执行时间分析
- 最大执行时间记录
- 慢查询SQL识别

### 2. **MySQL慢查询日志分析** 📊

**功能描述**: 直接查询MySQL的慢查询日志表获取详细的慢查询记录

**实现方法**:
```java
private void queryMysqlSlowLog() {
    // 1. 检查慢查询日志是否启用
    String checkSlowLogSql = "SHOW VARIABLES LIKE 'slow_query_log'";
    
    // 2. 查询最近1小时的慢查询记录
    String slowQuerySql = """
        SELECT start_time, query_time, lock_time, rows_sent, rows_examined, sql_text
        FROM mysql.slow_log 
        WHERE start_time >= DATE_SUB(NOW(), INTERVAL 1 HOUR)
        ORDER BY query_time DESC 
        LIMIT 10
        """;
}
```

**监控数据**:
- 查询执行时间 (`query_time`)
- 锁等待时间 (`lock_time`)
- 返回行数 (`rows_sent`)
- 扫描行数 (`rows_examined`)
- 完整SQL语句 (`sql_text`)

### 3. **慢查询趋势分析** 📈

**功能描述**: 分析数据库全局状态，计算慢查询比例和性能趋势

**实现方法**:
```java
private void analyzeSlowQueryTrends() {
    // 获取关键性能指标
    String statusSql = """
        SHOW GLOBAL STATUS WHERE Variable_name IN (
            'Slow_queries',     -- 慢查询总数
            'Questions',        -- 总查询数
            'Uptime',          -- 运行时间
            'Select_scan',     -- 全表扫描次数
            'Select_full_join' -- 全连接扫描次数
        )
        """;
}
```

**分析指标**:
- **慢查询比例**: `慢查询数 / 总查询数 * 100%`
- **平均QPS**: `总查询数 / 运行时间`
- **全表扫描统计**: 识别缺少索引的查询
- **性能趋势**: 长期性能变化分析

## 🚨 告警机制

### 1. **慢查询告警**
- **触发条件**: 单个查询执行时间 > 2秒
- **告警内容**: 执行时间、扫描行数、执行时间点
- **日志级别**: WARN

```
【慢查询告警】发现慢查询 - 执行时间: 3.45秒, 扫描行数: 50000, 时间: 2025-07-31 01:00:00
```

### 2. **慢查询比例告警**
- **触发条件**: 慢查询比例 > 1%
- **告警内容**: 当前慢查询比例和优化建议
- **日志级别**: WARN

```
【慢查询告警】慢查询比例过高: 1.25%，建议优化查询性能
```

### 3. **全表扫描告警**
- **触发条件**: 全表扫描次数 > 1000
- **告警内容**: 扫描次数和索引优化建议
- **日志级别**: WARN

```
【性能告警】全表扫描次数过多: 1500，建议检查索引
```

## 🔧 技术实现特点

### 1. **多数据源支持**
- **Druid数据源**: 使用内置统计API
- **MySQL数据库**: 直接查询系统表
- **兼容性检查**: 自动检测数据源类型

### 2. **容错机制**
- **异常处理**: 每个监控模块独立异常处理
- **降级策略**: 某个监控失败不影响其他监控
- **日志记录**: 详细的调试日志便于问题排查

### 3. **性能优化**
- **连接复用**: 使用现有数据源连接
- **查询限制**: 限制查询结果数量避免内存占用
- **时间窗口**: 只查询最近1小时的数据
