## 1. 支付频率限制

### 1.1 技术原理

支付频率限制使用**滑动窗口计数器**算法，基于Redis的原子操作实现分布式频率控制。

#### 核心思想
- 将时间分割为固定窗口（如10分钟）
- 每个用户在每个时间窗口内有最大支付次数限制
- 使用Redis INCR命令实现原子计数
- 自动过期清理，防止内存泄漏

#### 数据结构设计
```
Key格式: payment:freq:{userId}:{timeWindow}
Value: 当前时间窗口内的支付次数
TTL: 时间窗口长度（如600秒）
```

### 1.2 实现方案

#### 时间窗口计算
```java
// 计算当前时间窗口（10分钟为一个窗口）
long currentTimeMillis = System.currentTimeMillis(); // 例如: 1719734400000 (2024-06-30 12:00:00)
long timeWindowMinutes = 10; // 时间窗口长度：10分钟
// 将时间戳除以时间窗口毫秒数，得到时间窗口编号
// 例如: 1719734400000 / (10 * 60 * 1000) = 1719734400000 / 600000 = 2866224
String timeWindow = String.valueOf(currentTimeMillis / (timeWindowMinutes * 60 * 1000));

/* 时间窗口示例：
 * 12:00:00 - 12:09:59 → timeWindow = "2866224"
 * 12:10:00 - 12:19:59 → timeWindow = "2866225"
 * 12:20:00 - 12:29:59 → timeWindow = "2866226"
 * 这样确保同一时间窗口内的所有请求使用相同的Redis键
 */
```

#### Redis操作流程
```java
public boolean checkPaymentFrequency(Long userId) {
    // 构建Redis键的基础部分
    String key = "payment:freq:" + userId; // 例如: "payment:freq:12345"

    // 计算当前时间窗口编号
    String timeWindow = String.valueOf(System.currentTimeMillis() / (10 * 60 * 1000));

    // 完整的Redis键，包含用户ID和时间窗口
    String fullKey = key + ":" + timeWindow;
    // 例如: "payment:freq:12345:2866224"

    // 使用Redis INCR命令原子性地递增计数器
    // 如果键不存在，INCR会自动创建并设置为1
    // 如果键存在，INCR会将值加1并返回新值
    Long count = redisTemplate.opsForValue().increment(fullKey);

    // 首次创建键时（count=1），设置过期时间
    // 这确保时间窗口过期后自动清理，防止内存泄漏
    if (count == 1) {
        redisTemplate.expire(fullKey, Duration.ofMinutes(10));
        // 10分钟后Redis会自动删除这个键
    }

    // 检查当前计数是否超过最大允许次数
    // maxFrequencyCount通常配置为5，表示10分钟内最多5次支付
    return count <= maxFrequencyCount;

    /* 执行示例：
     * 第1次调用: count=1, 返回true (1 <= 5)
     * 第2次调用: count=2, 返回true (2 <= 5)
     * ...
     * 第5次调用: count=5, 返回true (5 <= 5)
     * 第6次调用: count=6, 返回false (6 > 5) - 被拒绝
     */
}
```

### 1.3 配置参数

```yaml

      max-count: 5        # 最大支付次数
      time-window: 10     # 时间窗口（分钟）
```

### 1.4 优势特点

- **精确控制**: 严格按时间窗口限制支付频率
- **分布式**: 多实例共享频率限制状态
- **高性能**: Redis原子操作，响应时间<1ms
- **自动清理**: TTL自动过期，无需手动清理

## 2. 防重放攻击

### 2.1 技术原理

防重放攻击通过为每个支付回调生成唯一标识，使用Redis的SET NX操作确保回调只被处理一次。

#### 核心思想
- 为每个回调生成唯一ID（基于关键参数的MD5哈希）
- 使用Redis SET NX操作检查ID是否已存在
- 已存在则为重放攻击，拒绝处理
- 设置合理的过期时间，平衡安全性和存储效率

#### 数据结构设计
```
Key格式: payment:callback:{callbackId}
Value: 处理时间戳
TTL: 60分钟（回调有效期）
```

### 2.2 实现方案

#### 回调ID生成
```java
private String generateCallbackId(String clientId, String requestTime, String signature) {
    // 组合关键参数生成唯一标识的源字符串
    // 使用多个参数确保唯一性，防止不同回调生成相同ID
    String source = (clientId != null ? clientId : "unknown") +
                   (requestTime != null ? requestTime : String.valueOf(System.currentTimeMillis())) +
                   (signature != null ? signature : "");

    /* 示例source字符串：
     * clientId="alipay_client_001" +
     * requestTime="1719734400000" +
     * signature="abc123def456..."
     * = "alipay_client_0011719734400000abc123def456..."
     */

    try {
        // 使用MD5算法生成32位十六进制哈希值
        MessageDigest md = MessageDigest.getInstance("MD5");
        byte[] digest = md.digest(source.getBytes()); // 计算MD5哈希

        // 将字节数组转换为十六进制字符串
        StringBuilder sb = new StringBuilder();
        for (byte b : digest) {
            sb.append(String.format("%02x", b)); // 每个字节转为2位十六进制
        }

        // 返回32位MD5哈希值，例如: "a1b2c3d4e5f6789012345678901234ab"
        return sb.toString();

    } catch (Exception e) {
        // MD5算法异常时的备选方案：使用Java hashCode
        // 虽然安全性较低，但确保系统可用性
        return source.hashCode() + ""; // 例如: "123456789"
    }

    /* 生成的callbackId示例：
     * 正常情况: "a1b2c3d4e5f6789012345678901234ab" (32位MD5)
     * 异常情况: "123456789" (hashCode备选)
     */
}
```

#### 重放检测
```java
public boolean isCallbackProcessed(String callbackId) {
    // 构建Redis键，用于存储已处理的回调ID
    String key = "payment:callback:" + callbackId;
    // 例如: "payment:callback:a1b2c3d4e5f6789012345678901234ab"

    // 检查Redis中是否已存在该键
    // 如果存在，说明这个回调ID已经被处理过了
    Boolean exists = redisTemplate.hasKey(key);
    if (exists != null && exists) {
        // 检测到重放攻击！同一个回调ID被重复发送
        log.warn("检测到重放攻击，回调ID: {}", callbackId);
        return true; // 返回true表示已处理过，拒绝重复处理
    }

    // 首次处理该回调ID，将其标记为已处理
    // 存储当前时间戳作为处理时间记录
    long processTime = System.currentTimeMillis(); // 例如: 1719734400000
    redisTemplate.opsForValue().set(key, processTime, Duration.ofMinutes(60));

    // 设置60分钟过期时间，过期后自动清理，节省存储空间
    // 60分钟的窗口期足够防止常见的重放攻击

    log.debug("回调ID首次处理，已标记: {}", callbackId);
    return false; // 返回false表示首次处理，允许继续处理

    /* 执行流程示例：
     * 第1次调用 callbackId="abc123":
     *   - Redis中不存在 → 创建键并返回false → 允许处理
     * 第2次调用 callbackId="abc123":
     *   - Redis中已存在 → 返回true → 拒绝处理（重放攻击）
     * 61分钟后:
     *   - Redis键自动过期删除 → 如果再次调用会被当作首次处理
     */
}
```

### 2.3 集成示例


- **时间窗口**: 60分钟过期时间，平衡安全性和存储
- **容错处理**: MD5失败时使用hashCode作为备选方案

## 3. 可疑行为记录

### 3.1 技术原理

可疑行为记录使用Redis List数据结构存储用户的可疑行为历史，支持时间序列分析和阈值监控。

#### 核心思想
- 使用List结构按时间顺序存储可疑行为
- 每条记录包含行为描述和时间戳
- 实时统计可疑行为次数
- 超过阈值时触发安全警告

#### 数据结构设计
```
Key格式: payment:suspicious:{userId}
Value: List["行为描述:时间戳", "行为描述:时间戳", ...]
TTL: 7天（可疑行为保存期）
```

### 3.2 实现方案

#### 记录可疑行为
```java
public void recordSuspiciousBehavior(Long userId, String reason) {
    // 构建Redis键，每个用户有独立的可疑行为记录
    String key = "payment:suspicious:" + userId;
    // 例如: "payment:suspicious:12345"

    // 构建记录值，包含行为描述和时间戳
    long timestamp = System.currentTimeMillis(); // 例如: 1719734400000
    String value = reason + ":" + timestamp;
    // 例如: "支付频率过高:1719734400000" 或 "重放攻击:1719734400000"

    // 使用Redis List数据结构存储可疑行为历史
    // leftPush将新记录添加到列表头部，保持时间倒序（最新的在前）
    redisTemplate.opsForList().leftPush(key, value);

    /* List结构示例（用户12345的可疑行为记录）：
     * Index 0: "重放攻击:1719734400000"     ← 最新记录
     * Index 1: "支付频率过高:1719734340000"  ← 较早记录
     * Index 2: "异常IP登录:1719734280000"   ← 更早记录
     */

    // 设置7天过期时间，过期后自动清理历史记录
    redisTemplate.expire(key, Duration.ofDays(7));

    // 检查可疑行为总次数是否超过安全阈值
    Long count = redisTemplate.opsForList().size(key);
    if (count != null && count >= suspiciousThreshold) {
        // suspiciousThreshold通常设置为3，表示7天内3次可疑行为
        log.error("用户{}可疑行为次数过多: {}, 建议加入黑名单", userId, count);

        // 可以触发进一步的安全措施：
        // 1. 发送安全告警邮件/短信
        // 2. 自动加入黑名单
        // 3. 冻结用户账户
        // 4. 通知风控团队人工审核
        triggerSecurityAlert(userId, count, reason);
    }

    /* 可疑行为阈值示例：
     * count=1: 记录但不采取行动
     * count=2: 记录并增加监控
     * count=3: 触发安全告警，可能限制功能
     * count>=5: 自动加入黑名单
     */
}
```

#### 检查可疑用户

## 4. 支付会话管理

### 4.1 技术原理

支付会话管理使用Redis的SET EX NX操作实现分布式互斥锁，防止用户同时发起多个支付请求。

#### 核心思想
- 每个用户同时只能有一个活跃的支付会话
- 使用Redis SET EX NX实现原子的获取锁操作
- 支付完成或超时后自动释放会话锁
- 防止并发支付导致的数据不一致

#### 数据结构设计
```
Key格式: payment:session:{userId}
Value: "locked"
TTL: 30分钟（支付会话超时时间）
```

### 4.2 实现方案

#### 获取支付会话
```java
public boolean acquirePaymentSession(Long userId) {
    // 构建用户专属的支付会话锁键
    String key = "payment:session:" + userId;
    // 例如: "payment:session:12345"

    // 使用Redis SET命令的原子操作：SET key value EX seconds NX
    // NX: 只有键不存在时才设置（Not eXists）
    // EX: 设置过期时间（EXpire）
    // 这个操作是原子性的，要么成功获取锁，要么失败
    Boolean acquired = redisTemplate.opsForValue().setIfAbsent(
        key,                        // Redis键
        "locked",                   // 锁的值（可以存储获取锁的时间戳或其他信息）
        Duration.ofMinutes(30)      // 30分钟后自动过期，防止死锁
    );

    if (acquired != null && acquired) {
        // acquired=true 表示成功获取锁（键之前不存在）
        log.debug("用户{}成功获取支付会话锁", userId);
        return true; // 允许用户进行支付

    } else {
        // acquired=false 表示锁获取失败（键已存在，说明用户已有活跃支付）
        log.warn("用户{}支付会话锁获取失败，可能存在并发支付", userId);

        // 记录可疑行为：尝试并发支付
        recordSuspiciousBehavior(userId, "尝试并发支付");

        return false; // 拒绝支付请求
    }

    /* 执行示例：
     * 用户12345第1次支付:
     *   - Redis中不存在 "payment:session:12345"
     *   - setIfAbsent 成功创建键，返回true
     *   - 用户可以继续支付流程
     *
     * 用户12345第2次支付（在第1次完成前）:
     *   - Redis中已存在 "payment:session:12345"
     *   - setIfAbsent 失败，返回false
     *   - 拒绝第2次支付，防止并发问题
     *
     * 30分钟后或支付完成后:
     *   - 键自动过期或被手动删除
     *   - 用户可以发起新的支付
     */
}
```

## 5. 分布式锁

### 5.1 技术原理

分布式锁基于Redisson实现，提供可重入、自动续期、公平锁等高级特性，用于保护关键业务操作。

#### 核心特性
- **可重入**: 同一线程可多次获取同一锁
- **自动续期**: 防止业务执行时间过长导致锁过期
- **公平锁**: 支持FIFO获取锁的顺序
- **阻塞/非阻塞**: 支持等待和立即返回两种模式

#### 应用场景
- 订单状态更新保护
- 用户余额变更保护
- 库存扣减保护
- 重要配置更新保护

### 5.2 实现方案

#### 基础分布式锁服务
```java
@Service
public class RedisDistributedLockService {

    @Autowired
    private RedissonClient redissonClient; // Redisson客户端，提供分布式锁功能

    /**
     * 通用分布式锁执行方法
     * @param lockKey 锁的唯一标识，例如: "order:lock:ORDER123456"
     * @param waitTime 等待获取锁的最大时间（秒），例如: 3秒
     * @param leaseTime 锁的持有时间（秒），例如: 10秒后自动释放
     * @param supplier 需要在锁保护下执行的业务逻辑
     * @return 业务逻辑的执行结果
     */
    public <T> T executeWithLock(String lockKey, long waitTime, long leaseTime, Supplier<T> supplier) {
        // 获取Redisson分布式锁对象
        RLock lock = redissonClient.getLock(lockKey);

        try {
            // 尝试获取锁，支持等待和自动过期
            // tryLock(等待时间, 持有时间, 时间单位)
            boolean acquired = lock.tryLock(waitTime, leaseTime, TimeUnit.SECONDS);

            if (!acquired) {
                // 在waitTime时间内未能获取到锁
                log.warn("获取分布式锁失败，锁键: {}, 等待时间: {}秒", lockKey, waitTime);
                return null; // 返回null表示操作失败
            }

            // 成功获取锁，执行业务逻辑
            log.debug("成功获取分布式锁，锁键: {}", lockKey);
            long startTime = System.currentTimeMillis();

            // 执行受保护的业务操作
            T result = supplier.get();

            long endTime = System.currentTimeMillis();
            log.debug("业务逻辑执行完成，耗时: {}ms", endTime - startTime);

            return result;

        } catch (InterruptedException e) {
            // 等待锁的过程中被中断
            log.error("等待分布式锁被中断，锁键: {}", lockKey, e);
            Thread.currentThread().interrupt(); // 恢复中断状态
            return null;

        } catch (Exception e) {
            // 业务逻辑执行异常
            log.error("分布式锁保护的业务逻辑执行异常，锁键: {}", lockKey, e);
            throw new RuntimeException("分布式锁操作失败", e);

        } finally {
            // 确保锁被正确释放
            if (lock.isHeldByCurrentThread()) {
                lock.unlock(); // 只有持有锁的线程才能释放锁
                log.debug("释放分布式锁，锁键: {}", lockKey);
            }
        }
    }

    /* 使用示例：
     *
     * // 示例1：订单状态更新
     * Boolean result = executeWithLock("order:lock:ORDER123", 3, 10, () -> {
     *     // 这里的代码在分布式锁保护下执行
     *     return orderService.updateStatus("ORDER123", "PAID");
     * });
     *
     * // 示例2：库存扣减
     * Integer newStock = executeWithLock("product:lock:PROD456", 5, 15, () -> {
     *     int currentStock = productService.getStock("PROD456");
     *     if (currentStock > 0) {
     *         return productService.decreaseStock("PROD456", 1);
     *     }
     *     throw new RuntimeException("库存不足");
     * });
     */
}
```

#### 订单状态更新锁
```java
public boolean updatePaymentStatus(String orderNo, Integer paymentStatus, String transactionId) {

    return distributedLockService.executeOrderLock(orderNo, () -> {

            int result = baseMapper.updatePaymentStatus(orderNo, paymentStatus, transactionId);
```

```java
    @Bean

        // 设置Redis连接工厂
        template.setConnectionFactory(factory);

        // 配置序列化器 - 关键配置，影响数据存储格式
        Jackson2JsonRedisSerializer<Object> serializer = new Jackson2JsonRedisSerializer<>(Object.class);

        template.setKeySerializer(new StringRedisSerializer());

        // 设置Hash Key序列化器
        template.setHashKeySerializer(new StringRedisSerializer());

        // 设置Hash Value序列化器

        // 初始化RedisTemplate

        return template;
    }
```

```java
     */
    public boolean checkPaymentFrequency(Long userId) {
        // 参数校验：用户ID不能为空
        if (userId == null) {
            log.warn("用户ID为空，拒绝支付请求");
            return false;
        }

        try {
            // 构建Redis键的基础部分
            String key = "payment:freq:" + userId; // 例如: "payment:freq:12345"

            // 计算当前时间窗口编号（10分钟为一个窗口）
            // 例如: 1719734400000 / (10 * 60 * 1000) = 2866224
            String timeWindow = String.valueOf(System.currentTimeMillis() / (frequencyTimeWindow * 60 * 1000));

            // 完整的Redis键，包含用户ID和时间窗口
            String fullKey = key + ":" + timeWindow; // 例如: "payment:freq:12345:2866224"

            // 使用Redis INCR命令原子性地递增计数器
            // 如果键不存在，INCR会自动创建并设置为1
            // 如果键存在，INCR会将值加1并返回新值
            Long count = redisTemplate.opsForValue().increment(fullKey);

            // 首次创建键时（count=1），设置过期时间
            // 这确保时间窗口过期后自动清理，防止内存泄漏
            if (count == 1) {
                redisTemplate.expire(fullKey, Duration.ofMinutes(frequencyTimeWindow));
                log.debug("为用户{}创建新的频率限制窗口，过期时间: {}分钟", userId, frequencyTimeWindow);
            }

            // 检查当前计数是否超过最大允许次数
            boolean allowed = count <= maxFrequencyCount;

            if (!allowed) {
                // 超过频率限制，记录警告日志并标记为可疑行为
                log.warn("用户{}支付频率过高，当前次数: {}, 最大允许: {}, 时间窗口: {}分钟",
                    userId, count, maxFrequencyCount, frequencyTimeWindow);

                // 记录可疑行为，用于后续风控分析
                recordSuspiciousBehavior(userId, "支付频率过高");

            } else {
                // 频率检查通过，记录调试日志
                log.debug("用户{}支付频率检查通过，当前次数: {}/{}, 时间窗口: {}分钟",
                    userId, count, maxFrequencyCount, frequencyTimeWindow);
            }

            return allowed;

        } catch (Exception e) {
            // 异常处理：Redis操作失败时的容错机制
            log.error("检查支付频率异常，用户ID: {}, 错误信息: {}", userId, e.getMessage(), e);

            // 异常情况下允许支付，避免影响正常业务
            // 但会记录错误日志，便于后续排查问题
            return true;
        }

        /* 执行示例：
         * 用户12345在时间窗口2866224内：
         * 第1次调用: count=1, 返回true (1 <= 5)
         * 第2次调用: count=2, 返回true (2 <= 5)
         * 第3次调用: count=3, 返回true (3 <= 5)
         * 第4次调用: count=4, 返回true (4 <= 5)
         * 第5次调用: count=5, 返回true (5 <= 5)
         * 第6次调用: count=6, 返回false (6 > 5) - 被拒绝并记录可疑行为
         *
         * 10分钟后进入新时间窗口2866225：
         * 第1次调用: count=1, 返回true - 重新开始计数
         */
    }

    /**
     * 防重放攻击检查
     * 基于回调ID的唯一性验证
     *
     * 防重放原理：
     * 1. 为每个支付回调生成唯一标识（基于关键参数的MD5哈希）
     * 2. 使用Redis检查ID是否已存在
     * 3. 已存在则为重放攻击，拒绝处理
     * 4. 设置合理的过期时间，平衡安全性和存储效率
     *
     * @param callbackId 回调唯一标识，例如: "a1b2c3d4e5f6789012345678901234ab"
     * @return true=已处理过(重放攻击), false=首次处理(允许)
     */
    public boolean isCallbackProcessed(String callbackId) {
        // 参数校验：回调ID不能为空
        if (callbackId == null || callbackId.trim().isEmpty()) {
            log.warn("回调ID为空，拒绝处理");
            return true; // 返回true表示拒绝处理
        }

        try {
            // 构建Redis键，用于存储已处理的回调ID
            String key = "payment:callback:" + callbackId;
            // 例如: "payment:callback:a1b2c3d4e5f6789012345678901234ab"

            // 检查Redis中是否已存在该键
            // 如果存在，说明这个回调ID已经被处理过了
            Boolean exists = redisTemplate.hasKey(key);

            if (exists != null && exists) {
                // 检测到重放攻击！同一个回调ID被重复发送
                log.warn("检测到重放攻击，回调ID: {}, 拒绝重复处理", callbackId);

                // 记录可疑行为，用于风控分析
                // 注意：这里需要从回调中提取用户ID，示例中使用固定值
                // 实际应用中应该从回调参数中解析出用户ID
                recordSuspiciousBehavior(0L, "重放攻击"); // 0L为示例，实际应传入真实用户ID

                return true; // 返回true表示已处理过，拒绝重复处理
            }

            // 首次处理该回调ID，将其标记为已处理
            // 存储当前时间戳作为处理时间记录，便于调试和审计
            long processTime = System.currentTimeMillis(); // 例如: 1719734400000
            redisTemplate.opsForValue().set(key, processTime, Duration.ofMinutes(callbackExpireTime));

            // 设置过期时间（默认60分钟），过期后自动清理，节省存储空间
            // 60分钟的窗口期足够防止常见的重放攻击
            log.debug("回调ID: {} 标记为已处理，过期时间: {}分钟", callbackId, callbackExpireTime);

            return false; // 返回false表示首次处理，允许继续处理

        } catch (Exception e) {
            // 异常处理：Redis操作失败时的容错机制
            log.error("防重放攻击检查异常，回调ID: {}, 错误信息: {}", callbackId, e.getMessage(), e);

            // 异常情况下允许处理，避免影响正常业务
            // 但会记录错误日志，便于后续排查问题
            return false;
        }

        /* 执行流程示例：
         *
         * 支付宝回调场景：
         * 1. 第1次回调 callbackId="abc123def456":
         *    - Redis中不存在该键
         *    - 创建键 "payment:callback:abc123def456" = 1719734400000
         *    - 设置60分钟过期时间
         *    - 返回false → 允许处理回调
         *
         * 2. 第2次回调 callbackId="abc123def456" (重放攻击):
         *    - Redis中已存在该键
         *    - 检测到重放攻击
         *    - 记录可疑行为
         *    - 返回true → 拒绝处理回调
         *
         * 3. 61分钟后:
         *    - Redis键自动过期删除
         *    - 如果再次收到相同callbackId会被当作首次处理
         *    - 这种情况极少发生，因为支付回调通常在几分钟内完成
         */
    }

    /**
     * 记录可疑支付行为
     * 使用List结构存储时间序列数据
     */
    public void recordSuspiciousBehavior(Long userId, String reason) {
        if (userId == null) {
            return;
        }

        try {
            String key = "payment:suspicious:" + userId;
            String value = reason + ":" + System.currentTimeMillis();

            // 使用List存储多次可疑行为
            redisTemplate.opsForList().leftPush(key, value);
            redisTemplate.expire(key, Duration.ofDays(suspiciousExpireDays));

            // 检查可疑行为次数
            Long count = redisTemplate.opsForList().size(key);
            log.warn("记录用户{}可疑行为: {}, 当前次数: {}", userId, reason, count);

            // 超过阈值时的处理
            if (count != null && count >= suspiciousThreshold) {
                log.error("用户{}可疑行为次数过多: {}, 建议加入黑名单", userId, count);
                // 可以触发进一步的安全措施
                triggerSecurityAlert(userId, count, reason);
            }

        } catch (Exception e) {
            log.error("记录可疑行为异常，用户ID: {}", userId, e);
        }
    }

    /**

     * 防止用户并发支付

    public boolean acquirePaymentSession(Long userId) {
        if (userId == null) {
            return false;
        }

        try {

                log.debug("用户{}成功获取支付会话锁", userId);
                return true;
            } else {

                recordSuspiciousBehavior(userId, "尝试并发支付");
                return false;
            }

        } catch (Exception e) {
            log.error("获取支付会话锁异常，用户ID: {}", userId, e);
            return true; // 异常情况下允许支付
        }
    }
```

```java
@Slf4j
@Service
public class RedisDistributedLockService {

    @Autowired
    private RedissonClient redissonClient;

    /**
     * 通用分布式锁执行方法
     */
    public <T> T executeWithLock(String lockKey, long waitTime, long leaseTime, Supplier<T> supplier) {
        RLock lock = redissonClient.getLock(lockKey);

        try {
            // 尝试获取锁
            boolean acquired = lock.tryLock(waitTime, leaseTime, TimeUnit.SECONDS);

            if (!acquired) {
                log.warn("获取分布式锁失败，锁键: {}, 等待时间: {}s", lockKey, waitTime);
                return null;
            }

            log.debug("成功获取分布式锁，锁键: {}", lockKey);

            // 执行业务操作
            long startTime = System.currentTimeMillis();
            T result = supplier.get();
            long endTime = System.currentTimeMillis();

            log.debug("分布式锁业务执行完成，锁键: {}, 执行时间: {}ms", lockKey, endTime - startTime);
            return result;

        } catch (InterruptedException e) {
            log.error("获取分布式锁被中断，锁键: {}", lockKey, e);
            Thread.currentThread().interrupt();
            return null;
        } catch (Exception e) {
            log.error("执行分布式锁操作异常，锁键: {}", lockKey, e);
            throw new RuntimeException("分布式锁操作失败", e);
        } finally {
            // 释放锁
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
                log.debug("释放分布式锁，锁键: {}", lockKey);
            }
        }
    }

    /**
     * 订单状态更新专用锁
     */
    public <T> T executeOrderLock(String orderNo, Supplier<T> supplier) {
        String lockKey = "order:lock:" + orderNo;
        return executeWithLock(lockKey, 3, 10, supplier);
    }

    /**
     * 用户支付专用锁
     */
    public <T> T executeUserPaymentLock(Long userId, Supplier<T> supplier) {
        String lockKey = "user:payment:lock:" + userId;
        return executeWithLock(lockKey, 5, 30, supplier);
    }

    /**
     * 库存扣减专用锁
     */
    public <T> T executeInventoryLock(String productId, Supplier<T> supplier) {
        String lockKey = "inventory:lock:" + productId;
        return executeWithLock(lockKey, 2, 5, supplier);
    }

    /**
     * 检查锁状态
     */
    public boolean isLocked(String lockKey) {
        try {
            RLock lock = redissonClient.getLock(lockKey);
            return lock.isLocked();
        } catch (Exception e) {
            log.error("检查锁状态异常，锁键: {}", lockKey, e);
            return false;
        }
    }

    /**
     * 强制释放锁（谨慎使用）
     */
    public boolean forceUnlock(String lockKey) {
        try {
            RLock lock = redissonClient.getLock(lockKey);
            if (lock.isLocked()) {
                lock.forceUnlock();
                log.warn("强制释放锁，锁键: {}", lockKey);
                return true;
            }
            return false;
        } catch (Exception e) {
            log.error("强制释放锁异常，锁键: {}", lockKey, e);
            return false;
        }
    }
}
```
