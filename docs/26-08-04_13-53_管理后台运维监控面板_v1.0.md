# 管理后台运维监控面板 v1.0

**时间**: 2026-08-04 13:53（北京时间）  
**版本**: v1.0  
**范围**: 管理后台内嵌 Grafana 风格轻量监控（路线 A）

## 目标

在 `admin-web` 增加运维监控页，覆盖 5 类图：

1. AI 调用（成功/失败、按模型耗时/TTFT）
2. HTTP 请求（Top 路径、状态码）
3. 系统资源（JVM 堆/线程/DB 池）
4. 支付/订单（近 7 日收入、订单状态）
5. 模型实时连通探测

## 实现

### 后端

- 新增 `GET /api/admin/ops/monitoring`（JWT + ROLE_ADMIN）
- `AdminOpsService.monitoring()` 聚合：
  - `system`：JVM / CPU / Druid 池 / resourceBars
  - `ai`：Micrometer `ai_*` 累计与 byModel
  - `http`：`api_requests_total` / `api_exceptions_total` / `http.server.requests`
  - `payment`：订单计数 + `PaymentAnalytics` 近 7 日
  - `models`：复用短超时并行模型探测（失败隔离）
  - `health`：组件健康

### 前端

- 依赖：`echarts@^6.1.0`
- 页面：`admin-web/src/views/MonitoringView.vue`
- 路由：`/admin/monitoring`
- 菜单：运维监控
- API：`getOpsMonitoring()`
- 默认 30s 自动刷新；无数据时空态提示

## 验收

- 后端编译 / package 成功
- admin-web build 成功（含 MonitoringView chunk）
- 现网：
  - `GET /api/admin/ops/monitoring` → 200
  - 返回 keys：`ai, http, system, payment, models, health`
  - `/admin/assets/MonitoringView-*.js` → 200
- 接口耗时受模型探测预算影响（约数秒），失败模型只影响 `models` 块

## 说明与限制

- 当前是**进程内快照**，不是 Prometheus 长期时序库
- AI/HTTP 指标随进程重启清零
- 后续若要真 Grafana：Prometheus 抓 `/actuator/prometheus` 即可，本面板可继续并存

## 入口

- 页面：`https://chat.instser.cn/admin/monitoring`
- API：`/api/admin/ops/monitoring`
