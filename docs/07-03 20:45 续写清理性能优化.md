# 07-03 20:45 续写清理性能优化

## 问题概述

用户反馈了续写清理的性能问题：

### 🚨 **核心问题：重复清理**
- **现象**：每个续写的JSON数据块都会执行thinking标签清理
- **问题**：thinking标签通常只出现在续写响应的开头，后续数据块不需要重复检测
- **影响**：不必要的性能消耗，重复的正则表达式匹配

### 🎯 **优化目标**
只在续写开头清理一次thinking标签，后续数据块只做基础清理。

## 问题分析

### ❌ **修复前的重复清理**

#### 1. **每个数据块都完整清理**
```java
// ❌ 问题：每个JSON数据块都执行完整清理
private String processContinuationJson(...) {
    if (content != null && !content.isEmpty()) {
        String cleanContent = cleanContinuationContent(content); // 每次都清理thinking标签
        
        if (!alignmentDone[0]) {
            // 第一次处理（对齐阶段）
        } else {
            // 后续处理（仍然在清理thinking标签）
        }
    }
}
```

#### 2. **不必要的性能消耗**
```java
// cleanContinuationContent方法包含复杂的正则表达式
private String cleanContinuationContent(String content) {
    // 1. 移除完整的 <thinking>...</thinking> 块
    cleaned = removeThinkingBlocks(cleaned);
    
    // 2. 移除开头的 <response> 标签
    cleaned = removeResponseTags(cleaned);
    
    // 3. 移除开头的代码块标记
    cleaned = removeCodeBlockMarkers(cleaned);
    
    // 4. 清理多余的空白行
    cleaned = cleanExtraWhitespace(cleaned);
}
```

**问题**：thinking标签通常只在续写开头出现，后续数据块重复执行这些正则匹配是浪费的。

### ✅ **优化后的智能清理**

#### 1. **分阶段清理策略**
```java
// ✅ 优化：根据阶段选择清理方式
if (content != null && !content.isEmpty()) {
    String cleanContent;
    if (!alignmentDone[0]) {
        // 第一次处理：完整清理（包括thinking标签）
        cleanContent = cleanContinuationContent(content);
        log.debug("续写JSON解析 - 首次完整清理后content: [{}]", cleanContent);
    } else {
        // 后续处理：只做基础清理
        cleanContent = cleanContent(content);
        log.debug("续写JSON解析 - 后续基础清理后content: [{}]", cleanContent);
    }
}
```

#### 2. **清理方法对比**

##### 完整清理（只在第一次）
```java
cleanContinuationContent(content):
- 移除thinking标签块
- 移除response标签
- 移除代码块标记
- 清理多余空白
```

##### 基础清理（后续使用）
```java
cleanContent(content):
- 过滤特定内容
- 移除无效字符
- 基础格式清理
```

## 解决方案

### 🔧 **实现智能清理策略**

#### 修改processContinuationJson方法

