# 07-06 16:43 - 联网搜索功能集成到聊天流程

## 更新时间
2025年7月6日 16:43 (北京时间)

## 版本标识
v1.4.0-websearch-chat-integration

## 功能概述
将searchAndExtract方法完整集成到聊天流程中，支持在chat、retry、edit-resend等场景下根据network参数启用联网搜索功能。

## 核心修改

### 1. ChatServiceImpl依赖注入扩展

#### 新增服务依赖
```java
private final WebSearchExtractService webSearchExtractService;
```

### 2. 联网内容处理方法

#### processNetworkContent方法
```java
/**
 * 处理联网搜索内容并附加到用户消息中
 *
 * @param messages 消息列表
 * @param query 搜索查询内容（从用户消息中提取）
 * @return 处理后的消息列表
 */
private List<Map<String, String>> processNetworkContent(List<Map<String, String>> messages, String query)
```

**核心功能**:
- 调用webSearchExtractService.searchAndExtract()进行联网搜索
- 将搜索结果格式化为JSON格式：`{"url":"content"}`
- 附加到最后一条用户消息中，格式：`原始内容。以下是联网搜索结果：[...]`

#### extractUserQuery方法
```java
/**
 * 从消息列表中提取用户查询内容
 *
 * @param messages 消息列表
 * @return 用户查询内容
 */
private String extractUserQuery(List<Map<String, String>> messages)
```

**核心功能**:
- 从最后一条用户消息中提取查询内容
- 智能处理包含文件附件的消息，提取原始用户查询
- 支持文件附件格式的内容分离

### 3. 聊天流程集成

#### buildAiRequestMessages方法扩展
```java
// 处理联网搜索内容并附加到用户消息中（仅用于AI处理）
if (request.getNetwork() != null && request.getNetwork()) {
    // 提取用户查询内容（从最后一条用户消息中获取）
    String userQuery = extractUserQuery(messages);
    if (userQuery != null && !userQuery.trim().isEmpty()) {
        log.info("正常聊天检测到联网搜索请求，开始处理联网内容，查询：{}", userQuery);
        List<Map<String, String>> processedMessages = processNetworkContent(messages, userQuery);
        messages = processedMessages;
        log.info("正常聊天联网内容处理完成");
    } else {
        log.warn("联网搜索请求但无法提取用户查询内容");
    }
} else {
    log.debug("正常聊天没有启用联网搜索");
}
```

### 4. 内容拼接顺序

#### 完整的内容处理流程
1. **用户原始内容**: 用户输入的原始消息
2. **文件内容拼接**: 如果有filesId参数，附加文件内容
3. **联网内容拼接**: 如果network参数为true，附加联网搜索结果

#### 最终消息格式
```
用户原始内容。以下是文件内容：[{"fileName":"fileContent"}]。以下是联网搜索结果：[{"url":"content"}]
```

### 5. 各场景支持情况

#### 正常聊天 (chat)
- ✅ **完全支持**: 根据network参数启用联网搜索
- ✅ **内容拼接**: 用户内容 + 文件内容 + 联网内容
- ✅ **查询提取**: 智能提取用户查询内容

#### 重新生成 (retry)
- ⚠️ **默认禁用**: retryRequest.setNetwork(false)
- 📝 **扩展预留**: 保留了扩展接口，可修改为动态值
- 💡 **设计考虑**: 重试通常基于原有上下文，不需要新的联网搜索

#### 编辑重发 (edit-resend)
- ⚠️ **默认禁用**: editResendRequest.setNetwork(false)
- 📝 **扩展预留**: 保留了扩展接口，可修改为动态值
- 💡 **设计考虑**: 编辑重发通常是修正内容，不需要新的联网搜索

#### 续写 (continuation)
- ✅ **继承设置**: continuationRequest.setNetwork(request.getNetwork())
- 💡 **设计考虑**: 续写基于已有对话上下文，继承原始请求的网络设置

## 技术特点

### 智能查询提取
- **原始内容优先**: 优先提取用户的原始查询内容
- **文件内容分离**: 自动分离文件附件内容，提取纯净查询
- **容错处理**: 无法提取查询时优雅降级

### 内容格式化
- **JSON结构**: 统一使用JSON格式存储搜索结果
- **URL标识**: 每个搜索结果包含来源URL
- **内容转义**: 正确处理JSON特殊字符转义

### 错误处理
- **服务异常**: 联网搜索失败时不影响正常聊天流程
- **空结果处理**: 搜索无结果时优雅处理
- **参数验证**: 完整的参数有效性检查

### 性能考虑
- **按需调用**: 仅在network=true时调用联网搜索
- **异步处理**: 联网搜索不阻塞主流程
- **缓存友好**: 搜索结果可被AI模型有效利用

- **场景适配**: 不同聊天场景的差异化处理

- **透明处理**: 联网搜索对用户透明，无需额外操作
- **内容丰富**: 为AI提供更丰富的上下文信息
- **响应及时**: 联网搜索不显著影响响应时间

### 系统稳定性
- **优雅降级**: 联网搜索失败不影响基础聊天功能
- **资源控制**: 合理控制联网搜索的调用频率
- **日志完整**: 完整的操作日志便于问题排查

## 注意事项

1. **API配额**: 联网搜索会消耗Tavily API配额，需要合理控制使用
2. **响应时间**: 联网搜索会增加总体响应时间，需要用户理解
3. **内容质量**: 搜索结果质量依赖于Tavily服务和网络内容质量
4. **隐私考虑**: 用户查询会发送到Tavily服务，需要注意隐私保护
5. **错误处理**: 需要完善的错误处理机制确保服务稳定性
