# 06-30 22:40 支付模块订单逻辑修复与优化

## 问题描述
用户反馈支付模块存在逻辑问题：同一个用户在同一时间应该只有一个待支付订单，新建订单时应该关闭旧的订单，但目前的实现是限制用户创建新的订单而不是关闭旧订单。

## 问题分析
通过代码检查发现，在 `PaymentServiceImpl.validateUserPermissions()` 方法中：

**原有逻辑：**
```java
// 检查用户是否有未完成的支付订单
List<UserOrder> pendingOrders = orderService.getPendingOrdersByUserId(userId);
if (pendingOrders != null && pendingOrders.size() >= 3) {
    log.warn("用户有过多未完成的支付订单，用户ID: {}, 未完成订单数: {}", userId, pendingOrders.size());
    throw new PaymentException("您有过多未完成的支付订单，请先完成或取消现有订单");
}
```

这个逻辑会在用户有超过3个待支付订单时抛出异常，阻止用户创建新订单，但不会自动取消旧订单。

## 解决方案
修改 `PaymentServiceImpl.validateUserPermissions()` 方法，改为自动取消用户的所有待支付订单：

**修改后逻辑1（数据库层面）：**
```java
// 检查用户是否有未完成的支付订单，如果有则自动取消旧订单
List<UserOrder> pendingOrders = orderService.getPendingOrdersByUserId(userId);
if (pendingOrders != null && !pendingOrders.isEmpty()) {
    log.info("用户有未完成的支付订单，将自动取消旧订单，用户ID: {}, 未完成订单数: {}", userId, pendingOrders.size());

    // 自动取消所有待支付订单
    for (UserOrder pendingOrder : pendingOrders) {
        try {
            boolean cancelResult = orderService.cancelOrder(pendingOrder.getOrderNo());
            if (cancelResult) {
                log.info("自动取消旧订单成功，订单号: {}, 用户ID: {}", pendingOrder.getOrderNo(), userId);
            } else {
                log.warn("自动取消旧订单失败，订单号: {}, 用户ID: {}", pendingOrder.getOrderNo(), userId);
            }
        } catch (Exception e) {
            log.error("自动取消旧订单异常，订单号: {}, 用户ID: {}", pendingOrder.getOrderNo(), userId, e);
        }
    }
}
```

**修改后逻辑2（Redis层面）：**
```java
// 检查用户是否有活跃的支付会话，如果有则自动释放旧会话
if (redisPaymentSecurityService.hasActivePaymentSession(userId)) {
    log.info("用户{}有活跃的支付会话，将自动释放旧会话以创建新订单", userId);
    redisPaymentSecurityService.releasePaymentSession(userId);
}

// 获取支付会话锁
if (!redisPaymentSecurityService.acquirePaymentSession(userId)) {
    throw new PaymentException("支付会话获取失败，请稍后再试");
}
```

## 功能改进
1. **Redis会话自动释放：** 当检测到用户有活跃的支付会话时，自动释放旧会话以允许创建新订单
2. **性能优化：** 移除数据库层重复检查，统一使用Redis会话管理，提升响应速度
3. **简化架构：** 避免双重检查的复杂性，使用单一的Redis会话锁机制
4. **30分钟会话保护：** Redis会话锁30分钟自动过期，有效防止长时间占用
5. **详细日志记录：** 记录Redis会话释放的详细过程，便于问题排查
6. **用户体验提升：** 用户不再需要手动取消旧订单或等待会话过期，可以直接创建新的支付订单

## 架构优化说明
- **移除冗余**：原本数据库和Redis双重检查存在功能重叠，现在统一使用Redis管理
- **性能提升**：避免每次支付都查询数据库中的待支付订单，减少数据库压力
- **逻辑简化**：单一的会话管理机制更容易理解和维护
- **历史订单处理**：如需清理历史待支付订单，可通过定时任务或管理接口处理
