# 模型管理允许代码重复与凭据编辑去 reason

- **时间**: 2026-08-20 18:49 (北京时间)
- **版本**: v1.0
- **变更类型**: 后端业务逻辑调整 + 前端交互优化

## 一、需求来源

管理员后台「模型管理」页面存在两点体验问题：

1. **模型代码不允许重复**：新增/编辑模型时，后端对 `modelCode` 做了唯一性拦截，导致同一模型代码无法配置多套凭据/端点（例如同一 `modelCode` 接不同上游渠道做容灾或多 key 轮换场景受限）。用户希望允许重复。
2. **凭据编辑强制 reason**：在「凭据」弹窗里修改 baseUrl / API Key 时，`reason`（操作原因）字段被后端 `@NotBlank` 强制必填，不填就无法提交。用户认为修改 url 和 key 是常规运维操作，不应强制 reason。

## 二、方案

### 2.1 允许模型代码重复

- 后端 `AdminModelService.create` 移除 `aiModelService.getModelByCode(code) != null` 的存在性拦截。
- 后端 `AdminModelService.update` 移除「同 code 且不同 id 冲突」校验。
- `AdminErrorCodes.MODEL_CONFLICT` 常量保留（其他模块仍用同类的 `*_CONFLICT` 常量），仅 `AdminModelService` 不再 import 与使用。

**安全性确认**：核心查询 `AiModelDao.selectByModelCode` 的 SQL 已带 `LIMIT 1`（见 `mapper/AiModelMapper.xml`），即使存在重复 `model_code`，`getModelByCode` 也只返回首条，不会抛 `TooManyResultsException`。`ChatApiController` 创建会话时按 `modelCode` 取模型，重复场景下取创建时间最早的一条，行为可预期且可控。

### 2.2 凭据编辑 reason 改为可选

- 后端 `AdminModelCredentialRequest.reason` 由 `@NotBlank` 改为 `@Size(max = 500)`（可空）。
- 后端 `AdminModelService.updateCredential` 审计日志对空 reason 兜底为 `"N/A"`，保持审计记录格式统一。
- 顺带把 `create` / `update` 审计日志里的 reason 也做了空值兜底（原本为 null 会拼成字面量 `null`）。
- 前端 `ModelsView.vue` 凭据弹窗移除「原因」表单项，`cred` reactive 对象移除 `reason` 字段。
- 前端 `api/admin.ts` 的 `updateModelCredential` 类型签名 `reason` 由必填改为可选。

## 三、变更文件清单

### 后端
- `src/main/java/com/instser/chat/admin/service/AdminModelService.java`
  - 移除 `create` 的模型代码重复拦截
  - 移除 `update` 的模型代码冲突校验
  - 移除未使用的 `AdminErrorCodes` import
  - `create` / `update` / `updateCredential` 审计日志 reason 空值兜底 `"N/A"`
- `src/main/java/com/instser/chat/admin/dto/AdminModelCredentialRequest.java`
  - `reason` 注解由 `@NotBlank + @Size(max=500)` 改为 `@Size(max=500)`（可空）

### 前端
- `admin-web/src/views/ModelsView.vue`
  - 凭据弹窗移除「原因」`el-form-item`
  - `cred` reactive 对象移除 `reason`
  - `openCredential` 不再赋值 `reason`
- `admin-web/src/api/admin.ts`
  - `updateModelCredential` 参数类型 `reason: string` → `reason?: string`

## 四、验证

- 后端：`JAVA_HOME=$(jdk17) mvn -DskipTests compile` BUILD SUCCESS；`mvn -Dtest='AiModelTest,ModelChatProbeSupportTest' test` 通过（无针对 AdminModelService 的直接单测，改动为纯校验移除/注解调整，回归面小）。
- 前端：`vue-tsc --noEmit` 类型检查通过。

## 五、影响与兼容性

- **向后兼容**：前端不再发送 `reason`（凭据场景），后端 reason 可空，旧版前端继续发送 reason 仍被接受。新增/编辑模型的 reason 本就是可选，不受影响。
- **数据一致性**：数据库 `t_ai_model.model_code` 无唯一约束（原唯一性靠应用层拦截），移除拦截后不涉及 DDL 变更。
- **聊天链路**：`ChatApiController` 按 `modelCode` 取模型走 `LIMIT 1`，允许重复后取首条，不影响现有会话创建。
- **审计**：reason 留空时记录 `N/A`，审计链路格式不变，可追溯。

## 六、后续建议（非本次实施）

- 若未来需要对「同 modelCode 多配置」做更精细的调用选择（如按权重/优先级路由），需在 `AiModelService.getModelByCode` 层面引入选择策略，本次保持取首条的简单语义。
- 新增/编辑模型弹窗的「原因」字段当前仍保留（后端可选）。如需进一步精简管理员操作，可后续评估是否一并移除。
