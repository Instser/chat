## 系统概览

### 技术架构
- **框架**: Spring Boot 3.1.12 + JDK 17
- **数据库**: MySQL 8.0 (your-db-host.example.com:45266)
- **缓存**: Redis (your-db-host.example.com:31122)
- **连接池**: Druid 1.2.23
- **分布式锁**: Redisson 3.24.3

### 核心模块
- **用户认证**: JWT + OAuth2 (Google/GitHub)
- **AI聊天**: 多模型支持 + 流式响应
- **文件管理**: 多格式解析 + 安全检测
- **支付系统**: 易支付 + 支付宝
- **联网搜索**: Gemini联网AI模块
- **缓存管理**: 三级缓存架构 (L1+L2+L3)

### 关键端口
- **应用端口**: 8080 (主服务)
- **管理端口**: 8081 (缓存管理API)

## 常见故障分类

### 1. 服务启动故障
- **症状**: 应用无法启动或启动失败
- **常见原因**: 配置错误、依赖冲突、端口占用、数据库连接失败

### 2. 数据库连接故障
- **症状**: 数据库操作失败、连接超时
- **常见原因**: 连接池耗尽、网络问题、数据库服务异常

### 3. Redis缓存故障
- **症状**: 缓存操作失败、性能下降
- **常见原因**: Redis服务异常、网络延迟、内存不足

### 4. AI聊天故障
- **症状**: 聊天响应异常、流式传输中断
- **常见原因**: AI服务异常、网络超时、令牌限制

### 5. 文件上传故障
- **症状**: 文件上传失败、解析错误
- **常见原因**: 文件大小超限、格式不支持、存储空间不足

### 6. 支付系统故障
- **症状**: 支付失败、回调异常
- **常见原因**: 支付接口异常、签名验证失败、订单状态错误

### 7. OAuth2登录故障
- **症状**: 第三方登录失败、授权异常
- **常见原因**: OAuth配置错误、状态验证失败、令牌过期

### 8. 性能问题
- **症状**: 响应缓慢、内存泄漏、CPU占用高
- **常见原因**: 数据库慢查询、缓存失效、线程池耗尽

## 故障排查流程

### 第一步：快速诊断
1. **检查服务状态**
   ```bash
   # 检查应用进程
   ps aux | grep java
   
   # 检查端口占用
   netstat -tlnp | grep 8080
   netstat -tlnp | grep 8081
   ```

2. **检查日志文件**
   ```bash
   # 查看最新错误日志
   tail -f logs/jinyu-chat-error.log
   
   # 查看完整日志
   tail -f logs/jinyu-chat-all.log
   ```

3. **检查系统资源**
   ```bash
   # 内存使用情况
   free -h
   
   # CPU使用情况
   top -p $(pgrep java)
   
   # 磁盘空间
   df -h
   ```

### 第二步：定位问题模块
1. **查看启动日志**
   - 检查Spring Boot启动过程
   - 确认Bean初始化状态

2. **检查外部依赖**
   - MySQL数据库连接
   - Redis缓存连接
   - 第三方API服务

3. **分析错误堆栈**
   - 定位异常发生位置
   - 分析异常传播路径
   - 确认根本原因

### 第三步：深入分析
1. **数据库分析**
   - 检查连接池状态
   - 分析慢查询日志
   - 验证数据完整性

2. **缓存分析**
   - 检查Redis连接状态
   - 分析缓存命中率
   - 验证缓存数据

3. **业务逻辑分析**
   - 检查业务流程
   - 验证数据状态
   - 分析用户行为

## 具体故障排查指南

### 服务启动故障

#### 1. 端口占用问题
**症状**: 启动时报错 "Port 8080 was already in use"

**排查步骤**:
```bash
# 查找占用端口的进程
lsof -i :8080
netstat -tlnp | grep 8080

# 终止占用进程
kill -9 <PID>
```

**解决方案**:
- 终止占用进程
- 修改应用端口配置
- 使用不同的端口启动

#### 2. 数据库连接失败
**症状**: 启动时报错 "Could not create connection to database server"

**排查步骤**:
```bash
# 测试数据库连接
mysql -h your-db-host.example.com -P 45266 -u <username> -p

# 检查网络连通性
ping your-db-host.example.com
telnet your-db-host.example.com 45266
```

**解决方案**:
- 验证数据库配置
- 检查网络连接
- 确认数据库服务状态
- 检查防火墙设置

#### 3. Redis连接失败
**症状**: 启动时报错 "Unable to connect to Redis"

**排查步骤**:
```bash
# 测试Redis连接
redis-cli -h your-db-host.example.com -p 31122 -a pt7tv2k4

# 检查Redis服务状态
redis-cli -h your-db-host.example.com -p 31122 -a pt7tv2k4 ping
```

**解决方案**:
- 验证Redis配置
- 检查认证信息
- 确认Redis服务状态
- 启用Redis降级模式

### AI聊天故障

#### 1. 流式响应中断
**症状**: 聊天过程中突然中断，前端显示连接断开

**排查步骤**:
1. 检查聊天日志
   ```bash
   grep "Chat session" logs/jinyu-chat-all.log | tail -20
   grep "Stream interrupted" logs/jinyu-chat-error.log
   ```

2. 检查AI服务状态
   ```bash
   # 查看AI请求日志
   grep "AI request" logs/jinyu-chat-all.log | tail -10
   ```

3. 检查网络连接
   ```bash
   # 测试AI服务连通性
   curl -I https://api.openai.com/v1/models
   ```

**解决方案**:
- 重试AI请求
- 检查API密钥有效性
- 验证网络连接稳定性
- 启用错误重试机制

#### 2. 聊天权限异常
**症状**: 用户无法发起聊天，提示权限不足

**排查步骤**:
1. 检查用户套餐状态
   ```sql
   SELECT * FROM t_user_account WHERE user_id = <user_id>;
   SELECT * FROM t_user_package WHERE user_id = <user_id> AND status = 1;
   ```

2. 检查每日使用限制
   ```sql
   SELECT * FROM t_user_daily_usage WHERE user_id = <user_id> AND usage_date = CURDATE();
   ```

3. 检查模型权限
   ```sql
   SELECT * FROM t_ai_model WHERE id = <model_id> AND visible = 1;
   ```

**解决方案**:
- 验证用户套餐状态
- 检查每日使用次数
- 确认模型可用性
- 重置用户权限缓存

### 文件上传故障

#### 1. 文件大小超限
**症状**: 文件上传失败，提示文件过大

**排查步骤**:
1. 检查文件大小配置
   ```yaml
   # application.yml
   spring:
     servlet:
       multipart:
         max-file-size: 50MB
         max-request-size: 50MB
   ```

2. 检查上传日志
   ```bash
   grep "File upload" logs/jinyu-chat-all.log | tail -10
   grep "FileSizeLimitExceededException" logs/jinyu-chat-error.log
   ```

**解决方案**:
- 调整文件大小限制
- 优化文件压缩
- 分片上传大文件
- 提示用户文件大小限制

#### 2. 文件格式不支持
**症状**: 文件上传成功但解析失败

**排查步骤**:
1. 检查文件魔数检测
   ```bash
   grep "Magic number detection" logs/jinyu-chat-all.log | tail -5
   ```

2. 检查解析器工厂
   ```bash
   grep "DocumentParserFactory" logs/jinyu-chat-all.log | tail -5
   ```

**解决方案**:
- 验证文件格式支持
- 更新文件类型白名单
- 增强文件格式检测
- 提供格式转换建议

### 支付系统故障

#### 1. 支付回调失败
**症状**: 支付完成但订单状态未更新

**排查步骤**:
1. 检查回调日志
   ```bash
   grep "Payment callback" logs/jinyu-chat-all.log | tail -10
   grep "Signature verification" logs/jinyu-chat-all.log | tail -5
   ```

2. 检查订单状态
   ```sql
   SELECT * FROM t_user_order WHERE order_id = '<order_id>';
   ```

3. 检查支付安全记录
   ```bash
   # 检查Redis中的支付安全数据
   redis-cli -h your-db-host.example.com -p 31122 -a pt7tv2k4
   keys payment:*
   ```

**解决方案**:
- 验证回调签名
- 手动更新订单状态
- 重新处理回调请求
- 检查支付配置

#### 2. 订单重复创建
**症状**: 同一用户创建多个相同订单

**排查步骤**:
1. 检查分布式锁
   ```bash
   grep "Payment lock" logs/jinyu-chat-all.log | tail -10
   ```

2. 检查订单创建逻辑
   ```sql
   SELECT * FROM t_user_order WHERE user_id = <user_id> AND status = 0 ORDER BY create_time DESC;
   ```

**解决方案**:
- 启用支付会话锁
- 清理重复订单
- 优化订单创建逻辑
- 增强前端防重复提交

## 应急处理方案

### 1. 服务不可用

#### 快速重启
```bash
# 停止服务
pkill -f "chat-0.0.1-SNAPSHOT.jar"

# 清理临时文件
rm -rf /tmp/tomcat*
rm -rf logs/*.log.tmp

# 重启服务
nohup java -jar chat-0.0.1-SNAPSHOT.jar > /dev/null 2>&1 &
```

#### 降级模式
- **禁用非核心功能**: 文件上传、联网搜索
- **启用缓存降级**: Redis故障时使用本地缓存
- **简化AI响应**: 使用备用模型或预设回复

### 2. 数据库故障

#### 只读模式
```sql
-- 设置数据库为只读
SET GLOBAL read_only = ON;

-- 停止写入操作
-- 只允许查询操作
```

#### 数据恢复
```bash
# 从备份恢复
mysql -h host -u user -p database < backup.sql

# 检查数据完整性
mysqlcheck -h host -u user -p --check --all-databases
```

### 3. 缓存故障

#### Redis降级
```yaml
# 临时禁用Redis
spring:
  redis:
    enabled: false
```

#### 本地缓存模式
- **启用Caffeine缓存**: 使用本地内存缓存
- **减少缓存依赖**: 直接查询数据库
- **定期同步数据**: 手动刷新关键数据

### 4. 监控告警

#### 紧急联系流程
