# 推理模型流式响应 nullnull 修复总结

> **时间**: 2026年7月22日 18:54（北京时间）
> **版本**: v1.0
> **范围**: 后端聊天流式解析 / CORS 部署适配
> **状态**: 代码已落到工作区，待提交与部署验证

## 1. 背景

部署/联调过程中，调用 `/api/chat`（`modelId=1`，DeepSeek-V4-Flash 等推理模型）时，前端流式响应会出现一长串：

```text
0:"null"
0:"null"
0:"null"
...
```

现象与思考时长正相关：模型思考越久，`null` 串越长；正式中文回答可能被淹没或延后。

同期还发现：部署到 `chat.instser.xyz` 后浏览器登录被 Spring Security 以 `403 Invalid CORS request` 拒绝，因为 CORS 白名单硬编码在 Java 中，不含新域名。

## 2. 根因

### 2.1 nullnull

推理模型在思考阶段会发送类似：

```json
{
  "choices": [
    {
      "delta": {
        "content": null,
        "reasoning_content": "..."
      }
    }
  ]
}
```

正式回答阶段才把真实文本放回 `delta.content`。

旧逻辑：

```java
if (delta != null && delta.has("content")) {
    String content = delta.get("content").asText();
    if (content != null && !content.isEmpty()) {
        // 发送给前端
    }
}
```

问题点：

1. `delta.has("content")` 在字段存在且值为 JSON `null` 时仍为 `true`
2. Jackson `JsonNode.asText()` 对 JSON null 节点返回字符串 `"null"`（**非 Java null、非空串**）
3. `!content.isEmpty()` 无法拦截
4. 每个思考 chunk 都被当成内容 `"null"` 发给前端 → 前端渲染成 `nullnull...`

### 2.2 CORS 403

`SecurityConfig` / `WebConfig` 中允许源是 Java 硬编码数组，默认不含 `chat.instser.xyz`。只改 `application.yml` 无效，必须改代码并重编译。

## 3. 修复方案

### 3.1 nullnull：`isTextual()` 守卫

文件：`src/main/java/com/instser/chat/service/serviceimpl/ChatServiceImpl.java`

两处对称修改：

1. `processContinuationJson`（续写流）
2. `processCompleteJson`（主聊天流）

核心改法：

```java
if (delta != null && delta.has("content")) {
    // 跳过 JSON null content（推理模型思考阶段）
    // Jackson asText() 对 JSON null 返回 "null"，会被误当内容发给前端
    JsonNode contentNode = delta.get("content");
    if (contentNode != null && contentNode.isTextual()) {
        String content = contentNode.asText();
        if (content != null && !content.isEmpty()) {
            // 原有业务逻辑不变
        }
    } else {
        log.debug("...content为JSON null（推理阶段），跳过");
    }
}
```

原理：`isTextual()` 仅对真实文本节点返回 `true`；JSON null 节点返回 `false`，直接跳过。

### 3.2 CORS：配置化

| 文件 | 改动 |
|------|------|
| `SecurityConfig.java` | 新增 `@Value` 读取 `app.cors.*`，`corsConfigurationSource()` 改为配置驱动 |
| `WebConfig.java` | `addCorsMappings()` 同样改为读配置 |
| `application.yml` | 默认允许源中的 `chat.example.com` 替换为 `chat.instser.xyz` |

配置项：

- `app.cors.allowed-origins`
- `app.cors.allowed-methods`
- `app.cors.allowed-headers`
- `app.cors.allow-credentials`
- `app.cors.max-age`

支持环境变量覆盖：`CORS_ALLOWED_ORIGINS` 等。

## 7. 影响与风险

| 项 | 说明 |
|----|------|
| 依赖/JDK | 无变更，JDK17 不变 |
| 数据库 | 无变更 |
| 兼容性 | 对普通非推理模型无影响（content 本就是文本节点） |
| 风险 | 若未来模型用非 text 节点承载内容（极少见），会被跳过；当前 OpenAI 兼容流式协议下 content 应为字符串或 null |
| 待办 | 部署后按第 5 节验证；工作区尚未正式 commit |
