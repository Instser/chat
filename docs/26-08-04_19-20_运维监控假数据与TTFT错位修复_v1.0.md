# 运维监控假数据与 TTFT 错位修复 v1.0

- 时间：2026-08-04 19:20（北京时间）
- 范围：管理后台运维监控面板 `/admin/monitoring`

## 问题

1. **近 7 日支付成功显示 120**：并非真实订单量。
2. **AI 按模型 TTFT 图模型名视觉错位**：柱/线与 x 轴模型名不易对应。

## 根因

### 1. 支付 120 来自硬编码模拟数据

`PaymentAnalyticsServiceImpl` 历史占位实现：

- `getSuccessfulOrderCount()` 固定返回 `120L`
- `getTotalOrderCount()` 固定 `150L`
- `getDailyRevenueStats()` 每日固定 `1000.00`
- `getPaymentMethodStats()` 固定 `alipay=100 / yipay=50`

监控接口 `AdminOpsService.buildPaymentMetrics()` 直接调用 `paymentAnalyticsService.getPaymentOverview(start, end)`，因此卡片「近7日支付成功」读到的是上述假数。

对照：同接口里 `payment.orders` 走 `orderService.count(...)` 为真实值（现网约 total=58, paid=3）。

### 2. TTFT 图错位

- 调用次数（个位数）与 TTFT/总耗时（上千 ms）共用**单一 Y 轴**，柱几乎不可见、折线主导，视觉上像“对不上模型”。
- 前端用并行 `map` 分别生成 `names` / series data，虽多数情况对齐，但不如 dataset 行式绑定稳妥；`unknown` 脏序列也会污染 x 轴。

## 修复

1. **重写** `PaymentAnalyticsServiceImpl`：全部基于 `t_user_order` 查询  
   - 成功单：`payment_status=1`，时间取 `COALESCE(payment_time, create_time)`  
   - 日收入 / 支付方式 / 套餐销量 / 时段分布均由实表聚合  
   - 删除所有硬编码返回值
2. **AI modelBars**：过滤 `unknown` 空模型名
3. **MonitoringView**：TTFT 图改为 **dataset + 双 Y 轴**（左次数 / 右 ms），支付图去掉与日期轴混用的假支付方式柱

## 验收要点

- 近 7 日支付成功应接近真实已支付订单数（现网全量 paid≈3，近 7 日可能为 0）
- 日收入折线不再是每天 1000 的平台直线
- AI 图每个模型类目下：柱=调用次数，折线=TTFT/总耗时，tooltip 与模型名一致
