# AI聊天排除status为3的错误响应消息实施方案

**时间：** 2025-09-04 06:56  
**版本标识：** v1.0  
**目标：** 在所有AI聊天场景中，拼接上下文时排除status为3的错误响应信息

## 问题分析

### 现状描述
当前系统在AI聊天时，会调用`ChatMessageService.getSessionMessages()`获取会话的所有历史消息来构建上下文。这包括了status为3的错误响应消息，会将错误信息传递给AI模型，影响对话质量。

### 涉及的核心代码位置
1. **数据库查询层：** `ChatMessageMapper.xml - selectBySessionId`
2. **服务层：** `ChatMessageServiceImpl.getSessionMessages()`  
3. **业务逻辑层：** `ChatServiceImpl.buildAiRequestMessages()`
4. **错误消息创建：** `ChatMessageServiceImpl.sendErrorResponseMessage()` 设置status=3

### 消息状态定义
- `status = 0`: 发送中
- `status = 1`: 成功
- `status = 2`: 失败
- `status = 3`: 错误响应（实际使用中的错误状态）

## 实施方案

### 方案选择：新增专用AI上下文查询方法（推荐）

**选择理由：**
- ✅ 不影响现有功能和其他业务逻辑
- ✅ 专门为AI场景优化，职责清晰
- ✅ 易于维护和后续扩展
- ✅ 性能优化，从数据库层面过滤

### 详细实施步骤

#### 1. 修改数据访问层 (DAO)

**文件：** `ChatMessageDao.java`
```java
/**
 * 根据会话ID查询消息列表（用于AI上下文，排除错误响应）
 *
 * @param sessionId 会话ID
 * @return 消息列表（排除status=3的错误响应）
 */
List<ChatMessage> selectBySessionIdForAiContext(@Param("sessionId") String sessionId);
```

**文件：** `ChatMessageMapper.xml`
```xml
<!-- 根据会话ID查询消息列表（用于AI上下文，排除错误响应） -->
<select id="selectBySessionIdForAiContext" resultMap="BaseResultMap">
    SELECT <include refid="Base_Column_List" />
    FROM t_chat_message
    WHERE session_id = #{sessionId}
      AND deleted = 0
      AND status != 3
    ORDER BY create_time ASC
</select>
```

#### 2. 修改服务层 (Service)

**文件：** `ChatMessageService.java`
```java
/**
 * 获取会话消息列表（用于AI上下文）
 *
 * @param sessionId 会话ID
 * @return 消息列表（排除status=3的错误响应）
 */
List<ChatMessage> getSessionMessagesForAi(String sessionId);
```

**文件：** `ChatMessageServiceImpl.java`
```java
@Override
public List<ChatMessage> getSessionMessagesForAi(String sessionId) {
    return baseMapper.selectBySessionIdForAiContext(sessionId);
}
```

#### 3. 修改业务逻辑层

**文件：** `ChatServiceImpl.java`
```java
private List<Map<String, String>> buildAiRequestMessages(ChatRequestDTO request) {
    try {

        if (historyMessages.isEmpty()) {
            return null;
        }
        
        // 其余逻辑保持不变...
    }
    // ...
}
```

### 影响范围评估

#### 直接影响

#### 无影响区域
- 前端消息列表显示 - 继续使用原有查询方法
- 消息删除功能 - 使用原有查询方法
- 其他非AI相关的消息查询功能
