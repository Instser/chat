# 缓存智能TTL -1值处理修复报告

**时间：** 2025-09-04 03:10  
**版本标识：** v1.4.4-unlimited-cache-fix  

## 问题概述

### 发现问题
用户反馈日志显示：
```
2025-09-04 03:01:51.432 [http-nio-8080-exec-15] DEBUG c.i.c.s.cache.CachedUsageService - 智能TTL: 剩余次数较少(-1次)，使用短TTL: 10分钟 + 4分钟随机本项目中的-1是无限制的意思
```

**问题：** 系统把 `-1`（无限制）错误地判断为"剩余次数较少"，导致：
1. 无限制套餐使用短TTL缓存，影响缓存效率
2. 权限验证逻辑可能不正确处理无限制情况

## 根因分析

### 1. 智能TTL逻辑错误
**文件：** `CachedUsageService.java:294`

```java
// 错误的逻辑
if (remaining != null && remaining <= SHORT_TTL_THRESHOLD) {
    // -1 被错误地认为是"剩余次数较少"
    baseTtl = SHORT_TTL;
}
```

### 2. 权限检查逻辑不完整
**文件：** `CachedUsageService.java:57, 73`

```java
// 原有逻辑只检查 > 0，没有考虑 -1 的情况
return remaining > 0; // 错误：-1 会被拒绝
```

### 3. 使用记录逻辑缺失
对于无限制套餐（-1），不应该进行缓存递减操作，应该直接记录使用。

## 修复方案

### 1. 修正智能TTL逻辑
**文件：** `CachedUsageService.java:295`

```java
// 修复前
if (remaining != null && remaining <= SHORT_TTL_THRESHOLD) {

// 修复后  
if (remaining != null && remaining > 0 && remaining <= SHORT_TTL_THRESHOLD) {
    // 只有正数且小于阈值才使用短TTL
    baseTtl = SHORT_TTL;
} else {
    // 正常情况使用标准TTL (包括无限制的-1情况)
    baseTtl = CACHE_TTL;
    if (remaining != null && remaining == -1) {
        log.debug("智能TTL: 无限制套餐(-1次)，使用标准TTL: {}分钟", baseTtl.toMinutes());
    }
}
```

### 2. 修正权限检查逻辑
**文件：** `CachedUsageService.java:58, 73`

```java
// 修复前
return remaining > 0;

// 修复后
return remaining == -1 || remaining > 0;
// -1 表示无限制，可以使用；> 0 表示有剩余次数，可以使用
```

### 3. 修正使用记录逻辑
**文件：** `CachedUsageService.java:108-113`

```java
// 新增无限制套餐处理
if (remaining == -1) {
    boolean dbSuccess = userDailyUsageService.recordModelChatUsage(userId, packageId, modelId);
    LogUtils.logUserDebug(log, userId, "无限制套餐", "模型{}无限制套餐，直接记录使用: {}", modelId, dbSuccess);
    return dbSuccess;
}
```

### 4. 修正缓存未命中处理
**文件：** `CachedUsageService.java:192-200`

```java
// 新增无限制处理
if (dbRemaining == -1) {
    boolean dbSuccess = userDailyUsageService.recordModelChatUsage(userId, packageId, modelId);
    if (dbSuccess) {
        cacheRemainingCount(cacheKey, -1); // 缓存无限制状态
    }
    return dbSuccess;
}
```

### 3. 缓存操作逻辑优化

- ✅ **有限制套餐**：正常递减缓存计数

## 技术实现细节

### 1. -1值的语义
在项目中，`-1` 表示无限制：
- 无限制聊天次数
- 不需要扣减计数
- 应该使用较长的缓存TTL

### 2. 缓存策略调整
```java
// 缓存TTL策略

>3 (正常): 标准TTL (30分钟 + 0-10分钟随机)
```
