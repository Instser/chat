# 07-12 18:53 - 联网模块重构方案

## 更新时间
2025年7月12日 18:53 (北京时间)

## 版本标识
v2.0.0-network-module-refactor

## 重构目标
将现有的两步式联网模块（Tavily搜索 + Tavily提取）重构为单步式联网AI模块，通过向专门的联网AI发送一次请求获取结构化的联网响应。

## 现状分析

### 当前架构问题
1. **复杂的两步流程**：先调用Tavily搜索API获取URL列表，再调用Tavily提取API获取详细内容
2. **多次网络请求**：每次联网查询需要2次外部API调用，增加延迟和失败风险
3. **数据处理复杂**：需要合并搜索结果和提取结果，逻辑复杂
4. **存储逻辑繁琐**：需要处理两种不同格式的响应数据

### 当前实现组件
- `WebSearchService` - Tavily搜索API调用
- `WebSearchExtractService` - 搜索+提取综合服务
- `WebContentCompressionService` - 内容压缩服务
- `WebSearchContentService` - 联网内容存储服务
- 相关实体类：`TavilySearchRequest/Response`、`TavilyExtractRequest/Response`等

## 重构方案设计

### 新架构概述
```
用户查询 → 联网AI请求 → 结构化JSON响应 → 数据处理 → 存储&响应
```

### 核心变更

#### 1. 新增联网AI服务
```java
@Service
public class NetworkAiService {
    /**
     * 向联网AI发送查询请求，获取结构化响应
     * @param userContext 用户有效上下文（原始对话内容，不添加提示词）
     * @return 联网查询结果
     */
    NetworkAiResponse queryWithNetwork(String userContext);

    /**
     * 获取配置的联网AI模型
     * @return 联网AI模型配置
     */
    AiModel getNetworkAiModel();
}
```

#### 2. 联网AI响应格式
```json
{
  "results": [
    {
      "url": "https://example.com",
      "title": "页面标题",
      "content": "用于前端显示的摘要内容（最多500字符）",
      "favicon": "https://example.com/favicon.ico",
      "raw_content": "完整的页面内容，用于拼接到AI请求中"
    }
  ]
}
```

#### 3. 数据映射策略
- **保持现有数据结构不变**：数据库存储格式仍为 `url`、`title`、`content`、`favicon`
- **保持现有逻辑不变**：所有数据处理、存储、响应逻辑完全不变
- **只改变数据来源**：从联网AI响应中提取这5个字段值，替代原来的Tavily API数据来源
- **字段映射关系**：
  - `url` ← 联网AI响应的 `url`
  - `title` ← 联网AI响应的 `title`
  - `content` ← 联网AI响应的 `content`
  - `favicon` ← 联网AI响应的 `favicon`
  - `raw_content` ← 联网AI响应的 `raw_content`（用于拼接到聊天AI请求中）

### 实现步骤

#### 阶段1：新服务实现
1. **创建NetworkAiService**
   - 实现联网AI调用逻辑
   - 处理非流式JSON响应解析
   - 添加错误处理和重试机制

2. **创建新实体类**
   - `NetworkAiResponse` - 联网AI响应
   - `NetworkSearchResult` - 统一搜索结果
   - `NetworkAiRequest` - 联网AI请求

3. **配置联网AI模型**
   - 在数据库中添加专门的联网AI模型配置
   - 设置专用的API端点和参数
   - 联网AI模型应配置为支持JSON格式输出

#### 阶段2：集成新服务
1. **修改ChatServiceImpl**
   - 仅替换`processNetworkContent`方法中的数据获取部分
   - 使用`NetworkAiService`替代`WebSearchExtractService`调用
   - **保持所有其他逻辑完全不变**：数据处理、存储、响应逻辑等

2. **重命名和数据适配**
   - 将`TavilySearchResult`重命名为`WebSearchResult`（去除Tavily字样）
   - 创建适配器将联网AI响应转换为`WebSearchResult`格式
   - **不修改任何现有的数据存储逻辑**
   - **不修改数据库表结构和JSON格式**

#### 阶段3：清理和重命名
1. **清除Tavily相关代码**
   - 移除`WebSearchService`和`WebSearchServiceImpl`（Tavily API调用）
   - 移除`WebSearchExtractService`和`WebSearchExtractServiceImpl`
   - 移除所有Tavily相关实体类：`TavilySearchRequest/Response`、`TavilyExtractRequest/Response`等
   - 移除`WebContentCompressionService`（功能集成到联网AI中）

2. **重命名去除Tavily字样**
   - `TavilySearchResult` → `WebSearchResult`
   - `TavilyExtractResult` → `WebExtractResult`（如果还需要）
   - `TavilyAutoParameters` → `WebSearchParameters`（如果还需要）
   - 更新所有引用这些类的代码

3. **配置清理**
   - 移除Tavily API相关配置（API密钥、URL等）
   - 添加联网AI模型配置

### 技术实现细节

#### 联网AI模型选择
- 使用专门配置的联网AI模型，该模型具备联网搜索能力
- 模型需要支持JSON格式输出，确保响应结构化
- 建议使用具备实时信息获取能力的AI模型

#### 联网AI请求格式
```java
// 直接发送用户的有效上下文，不添加系统提示词
List<Map<String, String>> messages = Arrays.asList(
    Map.of("role", "user", "content", userContext)
);

// 请求参数
Map<String, Object> requestBody = Map.of(
    "model", networkModel.getModelCode(),
    "messages", messages,
    "stream", false,  // 非流式响应
    "response_format", Map.of("type", "json_object")
);
```

#### 响应处理逻辑
```java
// 解析联网AI的JSON响应
NetworkAiResponse networkResponse = objectMapper.readValue(responseBody, NetworkAiResponse.class);

// 转换为通用的WebSearchResult格式，保持现有逻辑不变
List<WebSearchResult> searchResults = networkResponse.getResults().stream()
    .filter(result -> isValidResult(result))
    .limit(20)
    .map(this::convertToWebSearchResult)  // 数据格式转换
    .collect(Collectors.toList());

// 转换方法示例
private WebSearchResult convertToWebSearchResult(NetworkSearchResult networkResult) {
    WebSearchResult result = new WebSearchResult();
    result.setUrl(networkResult.getUrl());
    result.setTitle(networkResult.getTitle());
    result.setContent(networkResult.getContent());
    result.setFavicon(networkResult.getFavicon());
    result.setRawContent(networkResult.getRawContent());  // 用于AI请求拼接
    return result;
}
```

### 优势分析

#### 性能提升
- **减少网络请求**：从2次API调用减少到1次
- **降低延迟**：消除中间步骤的等待时间
- **提高成功率**：减少因多步骤导致的失败概率

#### 代码简化
- **简化数据获取**：从两步API调用简化为一步
- **简化错误处理**：只需处理一个API的错误情况
- **保持现有逻辑**：所有数据处理、存储、响应逻辑完全不变

#### 功能增强
- **智能内容筛选**：联网AI可以智能选择最相关的内容
- **自动内容压缩**：AI可以自动生成合适长度的摘要
- **更好的相关性**：AI理解查询意图，返回更精准的结果

### 风险评估

#### 技术风险
- **联网AI稳定性**：需要确保联网AI服务的可靠性
- **响应格式一致性**：需要严格的JSON格式验证
- **性能监控**：需要监控新服务的响应时间和成功率

#### 迁移风险
- **数据兼容性**：通过适配器确保数据格式完全兼容
- **功能回退**：保留旧代码直到新功能完全稳定
- **用户体验**：由于只改变数据来源，不会影响前端显示效果

## 总结
此重构方案的核心理念是**最小化改动，最大化收益**：
- **只改变数据来源**：从Tavily API改为联网AI
- **保持所有现有逻辑**：数据处理、存储、响应逻辑完全不变
- **通过适配器确保兼容性**：新数据源完美适配现有数据结构
- **显著提升性能**：从两步API调用简化为一步，减少延迟和失败风险

这种渐进式重构方式风险最小，同时能够获得联网AI的智能化优势。
