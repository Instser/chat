# OAuth2配置外部化重构

**时间**: 2025年07月18日 01:58  
**版本**: v1.1.0  
**修改类型**: 架构优化

## 问题描述

OAuth2ServiceImpl中存在大量硬编码的URL，包括：
- Google和GitHub的token交换URL
- 用户信息获取URL
- 授权URL
- redirect_uri

这些硬编码的URL不利于：
- 不同环境的部署（开发、测试、生产）
- 配置的灵活性和可维护性
- 第三方服务URL的变更适应

## 解决方案

### 1. 新增配置属性

在OAuth2ServiceImpl中添加了完整的配置属性注入：

```java
// Google配置
@Value("${oauth2.providers.google.client-id:}")
private String googleClientId;

@Value("${oauth2.providers.google.client-secret:}")
private String googleClientSecret;

@Value("${oauth2.providers.google.token-uri:https://oauth2.googleapis.com/token}")
private String googleTokenUri;

@Value("${oauth2.providers.google.user-info-uri:https://www.googleapis.com/oauth2/v3/userinfo}")
private String googleUserInfoUri;

@Value("${oauth2.providers.google.redirect-uri:http://localhost:3000/auth/google/callback}")
private String googleRedirectUri;

@Value("${oauth2.providers.google.authorization-uri:https://accounts.google.com/o/oauth2/v2/auth}")
private String googleAuthorizationUri;

@Value("${oauth2.providers.google.scope:openid,email,profile}")
private String googleScope;

// GitHub配置
@Value("${oauth2.providers.github.client-id:}")
private String githubClientId;

@Value("${oauth2.providers.github.client-secret:}")
private String githubClientSecret;

@Value("${oauth2.providers.github.token-uri:https://github.com/login/oauth/access_token}")
private String githubTokenUri;

@Value("${oauth2.providers.github.user-info-uri:https://api.github.com/user}")
private String githubUserInfoUri;

@Value("${oauth2.providers.github.redirect-uri:http://localhost:3000/auth/github/callback}")
private String githubRedirectUri;

@Value("${oauth2.providers.github.authorization-uri:https://github.com/login/oauth/authorize}")
private String githubAuthorizationUri;

@Value("${oauth2.providers.github.scope:user:email}")
private String githubScope;
```

### 2. 更新application.yml配置

```yaml
oauth2:
  providers:
    google:
      name: "Google"
      icon: "google"
      enabled: true
      client-id: ${GOOGLE_CLIENT_ID:334016856445-jlpdr73dr7jr0mrtdn0iu4082rh987gm.apps.googleusercontent.com}
      client-secret: ${GOOGLE_CLIENT_SECRET:your-google-client-secret}
      authorization-uri: ${GOOGLE_AUTHORIZATION_URI:https://accounts.google.com/o/oauth2/v2/auth}
      token-uri: ${GOOGLE_TOKEN_URI:https://oauth2.googleapis.com/token}
      user-info-uri: ${GOOGLE_USER_INFO_URI:https://www.googleapis.com/oauth2/v3/userinfo}
      scope: ${GOOGLE_SCOPE:openid,email,profile}
      redirect-uri: ${GOOGLE_REDIRECT_URI:http://localhost:3000/auth/google/callback}
    github:
      name: "GitHub"
      icon: "github"
      enabled: true
      client-id: ${GITHUB_CLIENT_ID:Ov23li7fEzHfvRyIT53F}
      client-secret: ${GITHUB_CLIENT_SECRET:your-github-oauth-client-secret}
      authorization-uri: ${GITHUB_AUTHORIZATION_URI:https://github.com/login/oauth/authorize}
      token-uri: ${GITHUB_TOKEN_URI:https://github.com/login/oauth/access_token}
      user-info-uri: ${GITHUB_USER_INFO_URI:https://api.github.com/user}
      scope: ${GITHUB_SCOPE:user:email}
      redirect-uri: ${GITHUB_REDIRECT_URI:http://localhost:3000/auth/github/callback}
```

### 3. 修改的方法

#### 3.1 Token交换方法
- `exchangeGoogleCodeForToken()` - 使用 `googleTokenUri` 和 `googleRedirectUri`
- `exchangeGithubCodeForToken()` - 使用 `githubTokenUri` 和 `githubRedirectUri`

#### 3.2 用户信息获取方法
- `getGoogleUserInfoByToken()` - 使用 `googleUserInfoUri`
- `getGithubUserInfoByToken()` - 使用 `githubUserInfoUri`
- `getGithubUserEmail()` - 动态构建邮箱API URL

#### 3.3 授权URL构建方法
- `buildGoogleAuthUrl()` - 使用 `googleAuthorizationUri`、`googleRedirectUri`、`googleScope`
- `buildGithubAuthUrl()` - 使用 `githubAuthorizationUri`、`githubRedirectUri`、`githubScope`

## 优势

### 1. 环境配置灵活性
```bash
# 开发环境
export GOOGLE_REDIRECT_URI="http://localhost:3000/auth/google/callback"

# 测试环境
export GOOGLE_REDIRECT_URI="https://test.example.com/auth/google/callback"

# 生产环境
export GOOGLE_REDIRECT_URI="https://app.example.com/auth/google/callback"
```

### 2. 第三方服务适应性
- 可以轻松切换到不同的OAuth2提供商
- 支持API版本升级（如Google OAuth2 v2 -> v3）
- 支持自定义scope权限

### 3. 维护性提升
- 所有URL配置集中在application.yml
- 支持环境变量覆盖
- 减少代码中的魔法字符串

## 向后兼容性

- 所有配置都有默认值，确保现有部署不受影响
- 环境变量名称保持一致
- API接口和行为完全不变
