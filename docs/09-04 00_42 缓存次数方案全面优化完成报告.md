### 🔴 P0优化：解决数据不一致风险

#### 核心改进：双阶段提交机制 + 智能降级
**原问题**：Redis递减 → 数据库写入，存在不一致风险
**优化方案**：数据库写入 → Redis递减，确保数据一致性

```java
// 改进的双阶段提交流程
// 阶段1：尝试数据库写入（带预检查）
boolean dbSuccess = userDailyUsageService.recordModelChatUsage(userId, packageId, modelId);
if (!dbSuccess) {
    return false; // 数据库失败，直接返回
}

// 阶段2：数据库成功后，尝试递减Redis
try {
    Long newRemaining = redisTemplate.opsForValue().decrement(cacheKey);
    if (newRemaining == null) {
        // Redis失败，清除缓存，降级到数据库模式
        redisTemplate.delete(cacheKey);
        return true; // ✅ 数据库已成功，返回成功
    }
} catch (Exception redisEx) {
    // Redis完全失联，清除缓存，降级到数据库模式
    redisTemplate.delete(cacheKey);
    return true; // ✅ 数据库已成功，返回成功
}
```

#### 🎯 关键修正：Redis故障时的智能降级
**修正前的错误逻辑**：
- Redis失败时整个操作失败，尝试回滚数据库
- 导致用户操作失败，影响业务连续性

**修正后的正确逻辑**：
- 数据库成功 = 用户操作成功
- Redis故障时自动清除缓存，降级到纯数据库模式
- 保证功能连续性，不因缓存问题影响用户体验

// 智能TTL策略
private static final Duration CACHE_TTL = Duration.ofMinutes(30); // 标准TTL
private static final Duration SHORT_TTL = Duration.ofMinutes(10); // 低剩余次数短TTL

private Duration getCacheExpireTime(Integer remaining) {
    if (remaining != null && remaining <= SHORT_TTL_THRESHOLD) {
        // 剩余次数很少时使用短TTL

    } else {
        // 正常情况使用标准TTL
        return CACHE_TTL.plusMinutes(random.nextInt(10));
    }
}
