## 安全与敏感信息风险

### 高风险：配置文件存在硬编码敏感默认值

- `src/main/resources/application.yml` 中存在 Redis、MySQL、PayPal、Stripe、OAuth2、JWT、管理 API Key、管理密码等敏感配置默认值。
- 本报告不记录任何真实密钥内容，仅记录风险位置：`application.yml:36`、`application.yml:58`、`application.yml:222`、`application.yml:249`、`application.yml:251`、`application.yml:292`、`application.yml:325`、`application.yml:335`、`application.yml:550`、`application.yml:553`。

影响：源码泄露会导致数据库、缓存、支付、OAuth 或管理接口被攻击。

建议：生产环境必须只允许环境变量注入；默认值应为空或使用占位符；历史提交中的真实密钥需要轮换。

### 中高风险：管理和 Actuator 安全边界依赖本地绑定与应用层校验

- Actuator SecurityFilterChain 对所有 endpoint `permitAll`：`src/main/java/com/instser/chat/config/ActuatorSecurityConfig.java:30-33`。
- 主安全配置也允许 `/actuator/**`、`/admin/cache/**`、`/admin/logs/**`：`src/main/java/com/instser/chat/config/SecurityConfig.java:175`、`SecurityConfig.java:190`、`SecurityConfig.java:193`。
- `application.yml` 当前将 management 绑定到 `127.0.0.1:8081`，降低了公网暴露风险，但容器、反向代理或 Kubernetes Service 配置错误时风险会上升。

建议：后续 `/ops/**`、`/admin/**` 应统一使用管理 API Key、角色、IP 白名单或内网网关策略，不建议单靠 `permitAll`。

### 中风险：外部 HTTP 客户端禁用 SSL 验证

- `WebClientConfig` 对 WebClient 与 RestTemplate 均存在“禁用 SSL 验证”逻辑。

影响：生产环境存在中间人攻击风险，也会降低面试展示时的安全工程观感。

建议：后续按环境开关控制，开发环境可选，生产环境默认启用证书校验。
