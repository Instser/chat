# 项目检查报告

- 分析时间（北京时间）: 2026-04-14 13:44
- 文档版本: v1.0
- 检查范围: 会话标题生成链路中模型编码带换行导致的 400 错误
- 检查目标: 定位 `Model does not exist` 的根因并修复所有相关请求路径的脏空白问题

## 1. 架构与模块快照

### 涉及模块
- `ChatServiceImpl`
  - 负责标题生成、普通聊天、续写等 AI 请求构造
- `AiModel`
  - 承载数据库中的模型配置，供各服务读取
- `TruncationDetectionServiceImpl`
  - 复用同一套模型配置进行截断检测

### 依赖方向
- `ChatServiceImpl` -> `AiModelService` -> `AiModel`
- `TruncationDetectionServiceImpl` -> `AiModelService` -> `AiModel`

## 2. 关键调用链

### 调用链 1：标题生成报错链路
1. `ChatServiceImpl.generateSessionTitle(...)` 读取标题模型 `ID=4L`
2. `callAiForTitleWithHttpClient(...)` 将 `model.getModelCode()` 原样写入请求体
3. 日志显示发送值为 `"\r\nQwen/Qwen2.5-7B-Instruct"`
4. 上游服务返回 `400 Model does not exist`

### 调用链 2：同类风险路径
1. 普通聊天请求使用 `model.getModelCode()/getBaseUrl()/getApiKey()/getProvider()`
2. 续写请求使用同一套模型字段
3. 截断检测也使用同一套模型字段
4. 因此如果数据库里有前后空白，问题不只会出现在标题生成

## 3. 关键发现

### 高风险

#### 1. 根因是模型配置字符串带脏空白，而请求构造层未做清洗
- 证据:
  - 用户提供日志中 `model` 实际发送值为 `"\r\nQwen/Qwen2.5-7B-Instruct"`
  - `ChatServiceImpl` 直接把 `model.getModelCode()` 放进请求体
- 结论: `Verified`

#### 2. 问题影响范围不止标题生成
- 证据:
  - 普通聊天、续写、截断检测都依赖同一 `AiModel` 实体
- 结论: `Verified`

### 中风险

#### 3. 仅在某一个请求点手动 `trim()` 会留下同类遗漏风险
- 证据:
  - 同类字段在多个服务中被直接读取
- 结论: `Verified`
- 处理:
  - 本次在 `AiModel` 实体 getter 层统一做字符串 `trim()`

## 4. 本次修复

### 修复内容
- 在 `AiModel` 中为以下关键字段 getter 增加统一 `trim()`：
  - `modelCode`
  - `modelName`
  - `provider`
  - `baseUrl`
  - `apiKey`

### 修复收益
- 标题生成不再把带前导换行的模型编码发给上游
- 普通聊天、续写、截断检测同步受益
- 即使数据库已有脏空白，运行时请求仍能得到干净值
