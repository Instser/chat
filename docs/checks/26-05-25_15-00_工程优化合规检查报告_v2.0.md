### 14. Redis 使用检查（key 命名、TTL、异常降级、缓存穿透）

**状态**：⚠️ 部分符合

**现有实现**：
- 基础设施：`RedisTemplate<String, Object>`（Jackson2Json 序列化）、Redisson Client
- 缓存体系：Spring Cache（type=redis，30min TTL）、HybridCacheManager（Caffeine L1 + Redis L2）
- Redis 熔断器：`RedisCircuitBreaker`（含事件驱动恢复）
- 分布式锁：`RedisDistributedLockService`（基于 Redisson RLock）
- 自定义 TTL 配置：user-account(15m)、package-config(1h)、model-permission(30m)

**Key 命名检查**：
| 模块 | Key 模式 | 规范性 |
|------|---------|--------|
| 分布式锁 | `order:lock:{orderNo}`, `user:payment:lock:{userId}` | ✅ 良好（命名空间:lock:标识） |
| 套餐缓存 | `user_package` (Spring Cache name) | ⚠️ 使用下划线，应为冒号分隔 |
| 日使用量 | `daily_usage:{userId}:{date}` | ⚠️ 使用下划线 |
| 用户账号 | `user:account:*` | ✅ 良好 |
| 支付相关 | `payment:*` | ✅ 良好 |
| 模型权限 | `model_permission` (组件常量) | ⚠️ 使用下划线，应统一为冒号 |
| 通用缓存 | `cacheName + "*"` (GlobalCacheManager) | ❌ 无统一前缀 |

**差距**：
- ❌ 无统一的 Redis Key 前缀/命名规范（冒号 vs 下划线混用）
- ❌ 无全局 Key 命名枚举或常量类
- ⚠️ `CacheCleanupRunner` / `GlobalCacheManager` 使用 `KEYS *` 模式匹配（生产环境 Redis KEYS 命令会阻塞）
- ⚠️ Spring Cache 注解使用的缓存名（`@Cacheable(value = "xxx")`）缺少统一命名空间前缀
- ✅ Redis 熔断器已实现
- ✅ TTL 已配置
- ⚠️ 缓存穿透保护：HybridCacheManager 的 `getOrFetch` 未找到允许缓存 null 值防穿透的逻辑

**证据**：
- `src/main/java/com/instser/chat/config/RedisConfig.java`
- `src/main/java/com/instser/chat/service/cache/HybridCacheManager.java`
- `src/main/java/com/instser/chat/component/CacheCleanupRunner.java`
