# 项目检查报告

- 分析时间（北京时间，已联网校对）：2026-04-15 17:37
- 版本标识：v1.0
- 检查范围：普通 `chat` 限制错误响应状态、`chat/retry/edit-resend` 三条限制链路、同类错误响应落库入口排查
- 检查目标：将普通 `chat` 的限制错误响应统一改为 `status=3`，并确认项目中是否还存在类似“错误响应被按普通消息落库”的问题

## 架构与模块快照

- 入口链路：
  - 普通聊天：`ChatApiController.chat` -> `ChatServiceImpl.processStreamChat`
  - 重试：`ChatApiController.retryChat` -> `ChatServiceImpl.processRetryChat`
  - 编辑重发：`ChatApiController.editResendChat` -> `ChatServiceImpl.processEditResendChat`
- 核心模块职责：
  - `ChatServiceImpl`：负责权限/限制校验、消息保存、错误响应写回
  - `ChatMessageServiceImpl`：`sendMessage` 保存普通消息，`sendErrorResponseMessage` 保存 `status=3` 错误响应
  - `ChatMessageMapper.xml`：AI 上下文查询时排除 `status=3`
- 依赖方向：Controller -> ChatServiceImpl -> ChatMessageService -> Mapper

## 关键调用链

1. 普通 `chat` 限制路径
   - `processStreamChat`

## 问题清单

### 高风险

- 普通 `chat` 原实现的限制响应通过 `saveAiLimitResponseToDatabase` 调用普通 `sendMessage(..., "assistant", ...)` 落库，状态为 `1`，因此会被后续 AI 上下文查询带入，造成限制说明参与后续对话上下文。
  - 文件证据：`src/main/java/com/instser/chat/service/serviceimpl/ChatServiceImpl.java:520`
  - 文件证据：`src/main/java/com/instser/chat/service/serviceimpl/ChatServiceImpl.java:548`
  - 结论类型：`Verified`

### 中风险

- `ChatMessageMapper.xml` 明确只排除 `status=3`，因此任何错误响应只要不是 `status=3`，都会进入上下文。问题根因不在 Mapper，而在上游错误响应落库方式。
  - 文件证据：`src/main/resources/mapper/ChatMessageMapper.xml:58`
  - 结论类型：`Verified`

### 低风险

- 经全局排查，限制错误文本相关的保存入口在本次修改后已统一收敛到 `saveErrorResponse -> sendErrorResponseMessage(status=3)`；源码中未再发现“限制说明文本按普通 assistant 消息落库”的同类入口。
  - 文件证据：`src/main/java/com/instser/chat/service/serviceimpl/ChatServiceImpl.java:526`
  - 文件证据：`src/main/java/com/instser/chat/service/serviceimpl/ChatMessageServiceImpl.java:90`
  - 结论类型：`Verified`

## 风险影响与修复优先级

- 影响面：普通 `chat` 链路的后续上下文纯净性；三条限制链路的一致性
- 触发概率：高，用户命中每日限制/频率限制即可触发
- 修复成本：低，属于单点收口
- 修复优先级：P1

## 修复说明

- 已将 `saveErrorResponseAndReturn` 中的普通 `chat` 限制响应保存逻辑，从 `saveAiLimitResponseToDatabase` 改为统一调用 `saveErrorResponse`
- 同时删除已失效的 `saveAiLimitResponseToDatabase` 方法，避免后续再被误用
- 修复后：
  - 普通 `chat` 的限制响应也以 `status=3` 入库
  - 三条限制链路 `chat/retry/edit-resend` 现在都不会把限制说明带入后续聊天上下文
