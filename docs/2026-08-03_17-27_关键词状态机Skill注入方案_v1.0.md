# 关键词 + 状态机 Active Skill 注入方案

- **时间（北京）**: 2026-08-03 17:27
- **版本**: v1.0
- **修订**: v1.0.1（2026-08-03）Redis skill 状态 TTL 由 7 天改为 **30 分钟** 滑动续期
- **范围**: 后端 system prompt 组装；会话级 skill 生命周期；与防泄露改造衔接
- **前置文档**:
  - `docs/2026-08-03_16-39_系统提示词防泄露与思考块安全优化方案_v1.0.md`
  - 推理思考块 v1.3（`deepThinking` / `g:` / reasoning 不回喂）
- **本版目标**: 落地 **关键词 detect + 会话状态机 active + 仅 active 注入 skill 全文**（不做模型自选 catalog / 完整 agent 环）

---

## 1. 背景与问题

### 1.1 现状

防泄露改造后：

- 每轮仅注入精简 `IDENTITY_SYSTEM_PROMPT`（`role=system`）
- `FRONTEND_SKILL_PROMPT` / `BACKEND_SKILL_PROMPT` 已拆为常量，**默认不注入**
- 无意图路由、无会话 skill 状态

结果：

- 身份问题泄露面下降（符合预期）
- 前后端专项规范不再每轮灌入（符合防腐败）
- 但用户明确做前端/后端任务时，也拿不到那套短 skill

### 1.2 要解决的问题

1. **按需增强**：前端/后端相关提问时注入对应 skill 全文  
2. **防重复堆叠**：同一 skill 不得在 system 中出现多份  
3. **防上下文腐败**：换题后自动卸下不再相关的 skill  
4. **不落库污染**：skill 不进 `t_chat_message`，不进多轮 content 回放  
5. **与 deepThinking / PromptLeakGuard 正交**

### 1.3 明确不做（本版）

| 不做 | 原因 |
|------|------|
| 模型自选 catalog / `load_skill` tool | 需要完整 agent 环，另立项 |
| 完整 tool-calling 多步循环 | 超出本版范围 |
| 新前端依赖 / UI mode 开关 | 可后续增强 |
| 新 Maven 依赖 | 禁止擅自加依赖 |
| 改 JDK | 固定 17 |
| 把 skill 写入聊天历史表 | 污染上下文与防泄露目标冲突 |

## 2. 设计原则（对齐社区）

参考 Agent Skills / Codex / Claude progressive disclosure 精神，在 **非 agent 聊天 API** 上取可落子集：

| 原则 | 本版落地 |
|------|----------|
| Standing rules 短且常驻 | 每轮 `IDENTITY_SYSTEM_PROMPT` |
| Skill 正文按需 | 仅 `active` 集合内 skill 注入全文 |
| 目录层可选 | 本版 **不向模型暴露 catalog**（由服务端关键词决定） |
| 防堆叠 | 渲染时每个 skill 最多一份 |
| 可撤销 | miss TTL / hard reset / 软领域切换 |
| 服务端权威 | detect 与状态变更均在服务端，模型不能直接改 active |

一句话：

> **detect 回答“像什么”；状态机回答“此刻挂哪些”；渲染只投影 active。**

## 3. 总体架构

```text
ChatRequestDTO
  └─ messages（含最新 user）
  └─ sessionId
        │
        ▼
PromptSkillRouter.detect(latestUserText)  →  Set<Skill> detected
        │
        ▼
PromptSkillStateMachine.next(prev, detected, text)  →  SkillState
        │
        ▼
PromptSkillStateStore (Redis)  save/load by sessionId
        │
        ▼
PromptAssembler.buildSystemPrompt(state)
  = IDENTITY
  + (FRONTEND_SKILL if active)
  + (BACKEND_SKILL if active)
        │
        ▼
AiStreamProcessor.buildMessagesWithPrompt
  [system] + request.messages
        │
        ▼
上游模型（deepThinking 独立）
```

### 3.1 与现有模块边界

| 模块 | 职责 |
|------|------|
| `PromptConstants` | 文案常量（已有 identity / skills） |
| `PromptSkillRouter`（新） | 关键词 detect、reset 词、fullstack 提示 |
| `PromptSkillState`（新） | 状态数据结构 |
| `PromptSkillStateMachine`（新） | active 增删、miss、切换 |
| `PromptSkillStateStore`（新） | Redis 读写 + TTL |
| `PromptAssembler`（新，可选合并进 Router） | system 字符串组装 |
| `AiStreamProcessor` | 调用组装；**删除内联仅 identity 硬编码** |
| `PromptLeakGuard` | 不变；继续过滤 reasoning/content |
| `ChatContextBuilder` | 不变；历史仍只 role+content |

## 4. Skill 枚举与文案

### 4.1 枚举

```java
public enum PromptSkill {
  FRONTEND,
  BACKEND
}
```

本版仅 2 个业务 skill。预留扩展口（如 `NETWORK`）但不实现。

### 4.2 文案来源

- `PromptConstants.IDENTITY_SYSTEM_PROMPT` — 每轮必带  
- `PromptConstants.FRONTEND_SKILL_PROMPT` — active 含 FRONTEND 时带  
- `PromptConstants.BACKEND_SKILL_PROMPT` — active 含 BACKEND 时带  

文案保持**短**（当前已是缩写版）。后续若加长，必须同步评估泄露与 token。

### 4.3 渲染格式

```text
{IDENTITY_SYSTEM_PROMPT}

[Skill: frontend]
{FRONTEND_SKILL_PROMPT}

[Skill: backend]
{BACKEND_SKILL_PROMPT}
```

- 段标题便于日志与泄露锚点维护  
- 无 active skill 时仅 identity，不出现空段标题

## 5. 关键词 Detect 设计

### 5.1 输入

- **仅**最新一条 `role=user` 的 `content`  
- 取法：从 `request.getMessages()` 自尾向前找第一条 user  
- 找不到 → `detected = ∅`  
- 规范化：`trim`；匹配时对英文 `toLowerCase(Locale.ROOT)`；中文原文 `contains`

### 5.2 词表（v1.0 初始）

#### FRONTEND（命中任一）

**中文**:  
`前端`, `页面`, `组件`, `样式`, `布局`, `交互`, `响应式`, `暗色`, `按钮`, `表单`, `弹窗`, `导航`, `UI`, `界面`, `视觉`, `动效`, `适配`

**英文/技术（小写匹配）**:  
`react`, `vue`, `angular`, `svelte`, `next.js`, `nextjs`, `nuxt`, `html`, `css`, `scss`, `tailwind`, `javascript`, `typescript`, `tsx`, `jsx`, `dom`, `webpack`, `vite`, `frontend`, `front-end`, `ui/ux`, `design system`

#### BACKEND（命中任一）

**中文**:  
`后端`, `服务端`, `接口`, `架构`, `微服务`, `网关`, `鉴权`, `权限`, `缓存`, `数据库`, `事务`, `消息队列`, `并发`, `限流`, `部署`, `运维`

**英文/技术（小写匹配）**:  
`spring`, `springboot`, `java`, `api`, `rest`, `graphql`, `grpc`, `mysql`, `redis`, `kafka`, `rabbitmq`, `jwt`, `oauth`, `backend`, `back-end`, `microservice`, `sql`, `mybatis`, `nginx`, `docker`, `k8s`, `kubernetes`

#### HARD RESET（命中则清空 active，再允许本轮 detected 重新激活）

**中文**:  
`换个话题`, `换话题`, `新问题`, `新的问题`, `不要按之前`, `忽略之前的设定`, `通用模式`, `重置技能`, `重置模式`

**英文**:  
`new topic`, `switch topic`, `reset skills`, `general mode`, `ignore previous setup`

> 不把笼统的 `ignore previous instructions` 做成唯一重置（易与攻击混淆）；用更产品向的短语。

#### FULLSTACK 提示（用于软互斥豁免）

**中文**: `全栈`, `前后端`, `联调`, `端到端`  
**英文**: `fullstack`, `full-stack`, `end-to-end`, `e2e`

### 5.3 Detect 输出

```java
Set<PromptSkill> detect(String latestUserText);
boolean isHardReset(String latestUserText);
boolean isFullstackHint(String latestUserText);
```

规则：

- 词表匹配 **OR**  
- 可同时命中 FRONTEND + BACKEND  
- 大小写不敏感（英文）  
- 不使用正则回溯；简单 `contains` 即可  
- 词表集中在 `PromptSkillRouter` 常量，便于单测与后续配置化

### 5.4 已知局限（接受）

- 同形词误伤（如口语“接口人”）— 靠 miss 淡出与短 skill 控制伤害  
- 无同义词扩展 — v1.1 可加  
- 不用 embedding — 本版明确不做

## 6. 状态机设计

### 6.1 状态结构

```java
public final class PromptSkillState {
  Set<PromptSkill> active;                 // 当前注入集合
  Map<PromptSkill, Integer> missRounds;    // 连续未命中轮数
  Map<PromptSkill, Long> lastHitAtMs;      // 可选
  int version;                             // schema 版本，默认 1
}
```

序列化：JSON 存 Redis。

### 6.2 参数（可配置，先给默认）

| 参数 | 默认 | 含义 |
|------|------|------|
| `missThreshold` (N) | **3** | 连续 N 轮未出现在 detected 则 deactivate |
| `maxActiveSkills` | **2** | 最多同时 active（与枚举数量一致） |
| `redisTtl` | **30 分钟** | key 滑动续期；会话闲置超过该时间后 skill 状态自动失效 |
| `idleDropMs` | **可选 0=关** | 若 >0，超时未 hit 也 drop |

配置位置建议：`application.yml`

```yaml
chat:
  prompt-skills:
    enabled: true
    miss-threshold: 3
    max-active: 2
    redis-ttl-minutes: 30
```

`enabled=false` 时行为退化为仅 identity（紧急回滚开关）。

> TTL 决策：skill 状态仅为短期会话策略，不需要跨天保留；**默认 30 分钟** 滑动续期即可。闲置超时后下次请求按 empty state + 本轮 detect 重建。

### 6.3 每轮转移算法（严格顺序）

```text
function next(prev, userText):
  state = copy(prev) or empty

  detected = router.detect(userText)
  hardReset = router.isHardReset(userText)
  fullstack = router.isFullstackHint(userText)

  // 1) hard reset
  if hardReset:
    state.clearActive()

  // 2) soft domain switch（非 fullstack 时）
  if not fullstack:
    if detected == {BACKEND} and FRONTEND in state.active and BACKEND not in? 
       // 更精确：
    if detected contains BACKEND and not detected contains FRONTEND
       and FRONTEND in state.active:
         state.deactivate(FRONTEND)
    if detected contains FRONTEND and not detected contains BACKEND
       and BACKEND in state.active:
         state.deactivate(BACKEND)

  // 3) activate detected（幂等）
  for s in detected:
    state.activate(s)   // active.add; miss[s]=0; lastHit=now

  // 4) miss tick + drop
  for s in state.active copy:
    if s not in detected:
      state.miss[s] += 1
      if state.miss[s] >= N:
        state.deactivate(s)

  // 5) cap（防御）
  if state.active.size > maxActive:
    // 保留 lastHit 最新的 maxActive 个
    trimByLastHit(state)

  return state
```

### 6.4 状态转移语义表

| 事件 | active 变化 |
|------|-------------|
| 首轮命中 FE | `{} → {FE}` |
| 连续聊细节但无关键词（miss&lt;N） | 保持 `{FE}`，miss++ |
| miss 达 N | 移除 FE |
| hard reset | 清空后按本轮 detected 再激活 |
| FE→纯 BE（非 fullstack） | 卸 FE，激 BE |
| 同时命中 FE+BE | `{FE, BE}` |
| 身份问 `你是谁` | detected 空；仅 miss++，不强制 clear（可用可选 soft clear，本版默认 **不** soft clear） |

### 6.5 入口差异

| 入口 | 策略 |
|------|------|
| 普通 chat | 用最新 user 跑完整状态机 |
| retry | **不**用新意图；读取现 state **不变更**（或 re-detect 原 user 文本但不双计 miss——推荐 **skip machine，沿用 store 中 state 只渲染**） |
| edit-resend | 用编辑后 user 文本跑完整状态机 |
| 新 session | 无 key → empty state |
| 中断后重发 | 同 chat |

**Retry 细则（锁定）**：

- `processRetryChat` 路径：`load state` → **不调用 next** → 仅 `buildSystemPrompt(state)`  
- 避免用户点重生成导致 miss 被错误 +1 或 skill 被卸掉  

### 6.6 空会话 / 无 sessionId

- `sessionId` 为空：不写 Redis；本轮 `active = detect(userText)` 纯瞬时（无 sticky）  
- 正常业务应总有 sessionId

## 7. 存储设计

### 7.1 Redis Key

```text
chat:prompt-skill:{sessionId}
```

### 7.2 Value 示例

```json
{
  "version": 1,
  "active": ["FRONTEND"],
  "missRounds": {"FRONTEND": 1},
  "lastHitAtMs": {"FRONTEND": 1722670000000}
}
```

### 7.3 TTL

- 写入/更新时 `EXPIRE` 为 `redis-ttl-minutes`（**默认 30 分钟**）  
- 滑动续期：每次 chat 成功组装并 `save` 后重新 touch  
- 超过 30 分钟无更新：key 过期 → 等同 empty state，不残留过期 skill  

### 7.4 失败策略

| 情况 | 策略 |
|------|------|
| Redis 读失败 | 记 warn；本轮 `prev=empty`，仅按 detected 瞬时 active（降级，不阻断聊天） |
| Redis 写失败 | 记 warn；本轮仍按内存算出的 state 渲染（降级） |
| JSON 损坏 | 丢弃并 empty |

**不**因为 skill 状态失败而中断主聊天。

### 7.5 为何不用 DB 列（本版）

- 免 SQL 迁移  
- skill 非用户资产，属会话瞬时策略  
- 后续若要审计再加 `t_chat_session.active_skills`

## 8. 组装接入点

### 8.1 `AiStreamProcessor.buildMessagesWithPrompt`

改造为：

```java
String latestUser = extractLatestUserContent(request.getMessages());
PromptSkillState state;
if (isRetryPath) { // 需能区分：见 8.2
  state = store.load(sessionId);
} else {
  PromptSkillState prev = store.load(sessionId);
  state = stateMachine.next(prev, latestUser);
  store.save(sessionId, state);
}
String system = assembler.build(state);

messages = [
  {role: system, content: system},
  ...request.messages
]
```

日志：

```text
PROMPT_SKILL sessionId={} detected={} active={} reset={} miss={}
```

### 8.2 如何区分 retry

优先方案：

- 在 `ChatRequestDTO` **不新增字段**（若避免协议变更）时：  
  - 由调用方在组装前设置 **请求作用域标记** 不优雅  
- 更干净：`buildMessagesWithPrompt` 增加参数 `SkillUpdateMode { UPDATE, REUSE_ONLY }`  
  - 普通 chat / edit-resend：`UPDATE`  
  - retry 流：`REUSE_ONLY`  

由 `AiStreamProcessor` 的公开入口或 `ChatServiceImpl` 传入 mode。  
**禁止**用“猜消息”区分 retry。

### 8.3 与 deepThinking

- skill 组装 **完全独立** 于 `deepThinking`  
- thinking 开/关不改变 active  
- PromptLeakGuard 继续处理 reasoning  

### 8.4 与联网 / 文件

- 仍在 system 之后追加 request.messages（其中可能已被 ChatContextBuilder 拼文件/联网）  
- skill **不**依赖联网结果

## 13. 安全与防泄露

| 点 | 策略 |
|----|------|
| skill 文案 | 保持短、无密钥 |
| 注入形态 | 仅 system，禁止伪 user/assistant |
| 可见 thinking | 依赖已有 `PromptLeakGuard` |
| 历史 API | 不存 skill，刷新不回放 skill 正文 |
| 词表攻击 | 用户无法通过消息写入任意 system；最多触发已有 skill |

若 skill 段标题进入 reasoning 复述，可在 Guard 增加弱锚点 `[Skill: frontend]`（P1）。

## 15. 验收标准

| 场景 | 通过条件 |
|------|----------|
| 新会话问「你是谁」 | system 仅 identity；无 FE/BE skill 段 |
| 问「用 React 写表单」 | system 含 FRONTEND skill 一次 |
| 随后 2 轮中性追问 | 仍可含 FRONTEND（miss&lt;3） |
| 第 3 轮仍中性 | 卸下 FRONTEND |
| 改问纯后端 | active 变为 BACKEND（非 fullstack） |
| 「前后端联调」 | 可同时两 skill |
| 「换个话题」 | active 清空（再按本轮 detect） |
| retry | active 不因 miss 误卸 |
| Redis down | 聊天成功；skill 降级为瞬时 detect |
| deepThinking=true | 协议与 Guard 行为不回归 |

## 17. 决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 路由方式 | 关键词 | 无 agent 环、可测、改动面小 |
| 生命周期 | 状态机 miss=3 | 兼顾粘性与防腐败 |
| 存储 | Redis | 无 SQL；TTL **30 分钟**滑动续期，避免长期粘滞 |
| 注入 | 仅 active 全文 | 对齐社区“按需正文”，防堆叠 |
| retry | REUSE_ONLY | 避免重生成打乱 skill |
| catalog 给模型 | 否 | 本版服务端裁定即可 |
| 默认开关 | enabled=true | 功能向；保留 yml 回滚 |
