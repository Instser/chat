## 需求背景

### 用户反馈
用户要求取消日志中正常的SQL记录，只有在SQL报错的时候才记录SQL语句，以减少日志输出量，提高日志可读性。

### 问题分析
当前系统配置会记录所有SQL语句：
1. **MyBatis-Plus配置**：使用`StdOutImpl`直接输出所有SQL到控制台
2. **Druid连接池**：配置了`slf4j`过滤器记录SQL执行信息
3. **日志级别设置**：MyBatis相关日志级别设置为INFO，会记录正常执行的SQL

## 解决方案

### 🔧 优化SQL日志配置

#### 1. 修改MyBatis-Plus日志实现
**文件**: `src/main/resources/application.yml`

```yaml
# 修改前
log-impl: org.apache.ibatis.logging.stdout.StdOutImpl

# 修改后  
log-impl: org.apache.ibatis.logging.slf4j.Slf4jImpl
```

**说明**: 
- 从直接控制台输出改为使用SLF4J日志框架
- 可以通过日志级别控制SQL记录行为

#### 2. 配置MyBatis SQL日志级别
**文件**: `src/main/resources/logback-spring.xml`

**开发环境配置**:
```xml
<!-- MyBatis核心日志 - 只在错误时记录 -->
<logger name="org.apache.ibatis" level="ERROR"/>

<!-- MyBatis SQL日志配置 - 只在错误时记录 -->
<logger name="com.instser.chat.dao" level="ERROR"/>
<logger name="org.apache.ibatis.logging.jdbc" level="ERROR"/>
<logger name="java.sql.Connection" level="ERROR"/>
<logger name="java.sql.Statement" level="ERROR"/>
<logger name="java.sql.PreparedStatement" level="ERROR"/>
<logger name="java.sql.ResultSet" level="ERROR"/>
```

**生产环境配置**:
```xml
<!-- 生产环境同样配置ERROR级别 -->
<logger name="org.apache.ibatis" level="ERROR"/>
<logger name="com.instser.chat.dao" level="ERROR"/>
<logger name="org.apache.ibatis.logging.jdbc" level="ERROR"/>
<logger name="java.sql.Connection" level="ERROR"/>
<logger name="java.sql.Statement" level="ERROR"/>
<logger name="java.sql.PreparedStatement" level="ERROR"/>
<logger name="java.sql.ResultSet" level="ERROR"/>
```

#### 3. 优化Druid连接池日志配置
**文件**: `src/main/resources/application.yml`

```yaml
# 修改前
filters: stat,wall,slf4j

# 修改后
filters: stat,wall
```

**说明**:
- 移除`slf4j`过滤器，避免Druid记录正常SQL执行日志
- 保留`stat`和`wall`过滤器用于监控和安全防护
- 慢SQL记录功能保持不变（slowSqlMillis=5000）

## 技术实现细节

### 1. 日志级别控制策略
- **ERROR级别**: 只记录SQL执行错误、连接异常、语法错误等
- **正常执行**: 不记录SELECT、INSERT、UPDATE、DELETE等正常SQL语句
- **慢SQL监控**: 通过Druid的slowSqlMillis参数继续监控慢查询

### 2. 日志记录范围
**会记录的情况**:
- SQL语法错误
- 数据库连接异常
- 约束违反错误
- 事务回滚异常
- MyBatis映射错误

**不会记录的情况**:
- 正常的SELECT查询
- 正常的INSERT操作
- 正常的UPDATE操作
- 正常的DELETE操作
- 正常的事务提交

### 3. 监控功能保留
- **Druid监控面板**: 继续可用，可查看SQL执行统计
- **慢SQL监控**: 超过5秒的SQL仍会被记录
- **连接池监控**: 连接池状态监控功能保持不变

## 预期效果

### ✅ 日志优化效果
1. **日志量减少**: 正常SQL执行不再产生日志，大幅减少日志输出
2. **可读性提升**: 日志中只包含错误信息，便于问题定位
3. **性能提升**: 减少日志I/O操作，轻微提升系统性能
4. **存储节省**: 日志文件大小显著减少，节省磁盘空间

### 📊 监控能力保持
1. **错误追踪**: SQL错误仍会被完整记录，便于调试
2. **慢查询监控**: 性能问题SQL继续被监控
3. **Druid面板**: Web监控界面功能完整保留
4. **统计功能**: SQL执行统计和分析功能不受影响
