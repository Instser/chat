## 一、语义修正（用户澄清）

后台三行 `deepseek-v4-flash` 是 **BEST MODEL / PERFORMANCE / STANDARD 三个独立模型级别**，只是接入了同一个上游模型。正确语义：

- **每行模型（每个级别）可单独配置多个 API Key（密钥池），聊天时仅在该行的 Key 列表内轮询**
- **不同模型行之间互不影响，绝不跨行轮换**（2026-09-15 上线的按 modelCode 跨行轮询语义错误，本次已纠正）
- 未配置密钥池的行：回退使用模型凭据中的单一 Key（行为与改造前一致）

## 二、实现

**新表 `t_ai_model_key`**：`model_id` 维度挂多条 key（api_key/remark/weight/status + success_count/fail_count/consecutive_fails/last_error/三个时间列，索引 idx_model_id(model_id,deleted,status)，不建外键，无数据迁移）。Flyway `V3__ai_model_key_table.sql`（CREATE TABLE IF NOT EXISTS 幂等；生产 Flyway 仍禁用，已手动执行）。

**轮询服务**（`AiModelRotationService` 改造）：
- 缓存与选取维度从 modelCode 改为 **modelId**：查该行的启用 key 列表，按有效权重加权随机 `max(1, weight − 20×连续失败)`
- 返回 `SelectedCredential(baseUrl, apiKey, keyId, modelRowId)`——**baseUrl 恒定取模型行，轮询只换 key，不换端点/级别**
- 双路径上报：池路径更新 key 行统计（同时异步给模型行 success/fail/last_used_time 做 +1 汇总）；兼容路径（池为空）维持行级统计语义不变（行级 consecutive_fails/last_error 只用于兼容路径）
- 「重试 + 换密钥」闭环保持：每次订阅重选，失败 key 降权，成功恢复；emitted 门控保持（已输出断流不重试不上报）

**管理端**：模型行「密钥池」弹窗（添加/权重行内改/启停/重置统计/删除，全部二次确认 + 审计 MODEL_KEY_* + 脱敏）；el-alert 与弹窗说明已更新为行内语义；行级统计列/重置统计/权重编辑保留（兼容路径与汇总展示）。

## 四、使用方式

1. 后台模型管理 → 某行模型点「密钥池」→ 添加多个 Key（可备注渠道、调权重 1-100）
2. 列表看每个 Key 的有效权重/成败/连续失败/最近错误；某 Key 持续 429 会自动降权，恢复后成功一次即回满
3. 「重置统计」清零单个 Key 的统计；行级「重置统计」清行级汇总列
