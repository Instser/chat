# 正常聊天流程数据库驱动上下文修改报告

**📅 完成时间**: 2025-07-05 18:10:00  
**👤 实施人员**: Augment Agent  
**📊 文档版本**: v1.0  

## 修改概述

将正常聊天流程从前端传递完整上下文改为后端数据库驱动上下文获取，使其与retry/edit-resend方法保持一致的实现模式。

## 修改背景

### 原有实现方式
- **前端驱动**：前端传递完整的对话历史（messages数组）
- **后端直接使用**：后端直接使用前端传递的消息列表
- **网络传输大**：每次请求都需要传输完整对话历史

### 新实现方式  
- **后端驱动**：前端只传递最新用户消息
- **数据库获取**：后端从数据库获取完整对话历史
- **网络传输小**：只传输最新消息，减少网络负载

## 核心修改内容

### 1. 消息提取逻辑

**新增方法**: `extractLatestUserMessage()`
```java
/**
 * 从前端messages参数中提取最新用户消息内容
 */
private String extractLatestUserMessage(List<Map<String, String>> messages) {
    if (messages == null || messages.isEmpty()) {
        return null;
    }
    
    // 从消息列表中找到最后一条用户消息
    for (int i = messages.size() - 1; i >= 0; i--) {
        Map<String, String> message = messages.get(i);
        if ("user".equals(message.get("role"))) {
            return message.get("content");
        }
    }
    return null;
}
```

### 2. 消息保存逻辑

**新增方法**: `saveNewUserMessage()`
```java
/**
 * 保存新的用户消息到数据库
 */
private String saveNewUserMessage(String content, String sessionId, Long userId, Long modelId, boolean hasAttachments) {
    // 保存用户消息并返回messageId
    Long messageDbId = chatMessageService.sendMessage(sessionId, "user", content, userId, modelId, hasAttachments ? 1 : 0);
    // 获取messageId用于文件关联
    ChatMessage savedMessage = chatMessageService.getById(messageDbId);
    return savedMessage != null ? savedMessage.getMessageId() : null;
}
```

### 3. 上下文重建逻辑

**修改**: `processStreamChat()`方法中的上下文处理
```java
// 从数据库获取完整的会话历史消息
List<ChatMessage> historyMessages = chatMessageService.getSessionMessages(request.getSessionId());

// 构建消息列表用于AI请求
List<Map<String, String>> messages = new ArrayList<>();
ChatMessage lastUserMessageEntity = null;
for (ChatMessage message : historyMessages) {
    Map<String, String> msgMap = new HashMap<>();
    msgMap.put("role", message.getRole());
    msgMap.put("content", message.getContent());
    messages.add(msgMap);
    
    // 记录最后一条用户消息实体，用于检查附件
    if ("user".equals(message.getRole())) {
        lastUserMessageEntity = message;
    }
}
```

### 4. 文件内容拼接逻辑

**保持不变**：使用与retry/edit-resend相同的文件处理逻辑

## 修改流程对比

### 修改前流程
1. 前端传递完整messages数组（包含历史对话）
2. 后端提取最新用户消息保存到数据库
3. 后端直接使用前端传递的messages进行文件拼接
4. 发送给AI处理

### 修改后流程
1. 前端只传递最新用户消息（messages数组只包含新消息）
2. 后端提取并保存最新用户消息到数据库
3. 后端从数据库获取完整对话历史
4. 后端重建完整上下文并进行文件拼接
5. 发送给AI处理
