# 26-08-26 23:04 图片解析器模型替换为 VL 视觉专用模型 v1.0

## 背景
`ImageDocumentParser` 把上传图片转文字描述（存入 `t_file_upload.content`），供聊天附件拼接使用。原实现把视觉模型三项配置硬编码：
- `AI_API_URL = http://203.0.113.15:3000/v1/chat/completions`
- `AI_API_KEY = a2366021253`
- `AI_MODEL = qwen2.5-omni-7b`

问题：
1. 旧服务 `203.0.113.15:3000` 已不可达（连接超时、HTTP 000），**图片附件解析功能失效**。
2. API Key 明文写死在源码，进 Git 历史。
3. 换模型/换地址/换 Key 都要改代码重编译。

VL 专用模型不走冗长思维链，直接输出识别结果，速度快 10 倍以上。选 `Qwen3-VL-8B-Instruct`（轻量快速，适合旁路解析任务）。

## 改动文件
1. `src/main/resources/application.yml` — 新增 `image-parser` 配置段
2. `src/main/java/com/instser/chat/config/ImageParserConfig.java` — 新建，启动时注入配置
3. `src/main/java/com/instser/chat/parser/impl/ImageDocumentParser.java` — 硬编码常量改为可变静态字段 + `setConfig()`

## 改动详情

### 1. application.yml
```yaml
# 图片解析配置（ImageDocumentParser 调用视觉模型把图片转文字描述）
image-parser:
  api-url: ${IMAGE_PARSER_API_URL:https://api.siliconflow.cn/v1/chat/completions}
  api-key: ${IMAGE_PARSER_API_KEY:your-siliconflow-api-key}
  model: ${IMAGE_PARSER_MODEL:Qwen/Qwen3-VL-8B-Instruct}
```
均支持环境变量覆盖，生产环境可用 `${IMAGE_PARSER_*}` 替换敏感值。

### 2. ImageParserConfig.java（新建）
`@Configuration` + `@PostConstruct`，启动时读 `@Value` 并调用 `ImageDocumentParser.setConfig()`。
原因：`ImageDocumentParser` 由 `DocumentParserFactory.getParser()` `new` 出来，不受 Spring 容器管理，无法用 `@Value` 直接注入解析器实例，故走静态注入。

### 3. ImageDocumentParser.java
```java
// 改前
private static final String AI_API_URL = "http://203.0.113.15:3000/v1/chat/completions";
private static final String AI_API_KEY = "a2366021253";
private static final String AI_MODEL = "qwen2.5-omni-7b";

// 改后
private static String AI_API_URL = "https://api.siliconflow.cn/v1/chat/completions";
private static String AI_API_KEY = "your-siliconflow-api-key";
private static String AI_MODEL = "Qwen/Qwen3-VL-8B-Instruct";

public static void setConfig(String apiUrl, String apiKey, String model) {
    AI_API_URL = apiUrl;
    AI_API_KEY = apiKey;
    AI_MODEL = model;
}
```
默认值与新配置一致，保证即便配置类未加载也能工作。
