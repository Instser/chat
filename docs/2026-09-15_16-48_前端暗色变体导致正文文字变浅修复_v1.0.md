# 前端正文文字对比度骤降（变浅几乎不可见）修复

- 时间：2026-09-15 16:48（北京时间）
- 版本：v1.0
- 涉及仓库：`tousechat/frontend`（用户前端，独立仓库）
- 改动文件：`frontend/tailwind.config.ts`（1 行恢复 + 注释澄清，未 commit）

## 现象

用户反馈聊天页部分字体颜色对比度变得很低、之前正常。两张截图证据：

1. 天气卡片会话中，AI 回复的某个段落变浅（#e5e7eb），其余段落正常；
2. 普通会话「Hello AI Help Needed」中，**所有 AI 回复正文整体变浅**，而用户气泡与 emoji 😊 颜色正常。

## 诊断过程（像素级取证）

对截图做 PNG 解码像素采样：

| 采样点 | 实测颜色 | 对应样式 |
|---|---|---|
| 变浅段落 | `#e5e7eb` | Tailwind `gray-200`（即 `dark:text-gray-200`） |
| 正常段落/标题 | `#2c2521` | `--foreground: hsl(25 15% 15%)` |
| 用户气泡 | `#1f2937` | `gray-800` |

emoji 颜色正常 + 纯文字变浅 → 是 `color` 而非 `opacity` 问题，排除 bg-clip-text（全仓库仅 3 处页面标题使用）。

## 根因

提交 `3553565`「强制使用亮色模式并移除暗色模式相关代码」将 `tailwind.config.ts` 中 `darkMode: ["class"]` **注释掉**，Tailwind 回退到默认 `darkMode: 'media'`。于是组件中残留的 `dark:` 变体（`markdown-renderer.tsx` 的 `dark:text-gray-200` 等共 8 条）改为响应**操作系统** `prefers-color-scheme: dark`；而应用背景被强制亮色（globals.css 已删暗色变量、layout.tsx `forcedTheme="light"` 只控制 `.dark` 类、对 media 策略无效）。macOS 深色模式下正文变 #e5e7eb，白底几乎不可读。

「之前没有这个问题」= 该提交近期才部署上线 / 用户系统近期切到深色（或自动）模式。

## 修复

恢复 `tailwind.config.ts` 的 `darkMode: ["class"]` 并加注释说明为何必须是 class 策略。`.dark` 类由 next-themes 控制且 `forcedTheme="light"` 永不添加 → `dark:` 变体永不触发 → 始终亮色，符合原「强制亮色」意图。未删除任何 `dark:` 规则（惰性化而非删除，保留功能完整性）。

## 验证（修复前后对比闭环）

`./node_modules/.bin/tailwindcss -i app/globals.css -o ... --config tailwind.config.ts`：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| `prefers-color-scheme: dark` 媒体查询 | 1 处（bug 存在） | **0** ✅ |
| `.dark` 选择器 | 8 | 8（`:is(.dark *)` 门控）✅ |

产物形态：`dark:text-gray-200` 由「media 查询包裹」变为「`.dark\:text-gray-200:is(.dark *)`」，永久惰性。

`npx tsc --noEmit`：14 个错误均为既有错误（chat-view.tsx 等），修复前后完全一致，与本次改动无关。
