## 📊 日志级别标准

### INFO 级别 - 关键信息
记录系统关键操作、状态变更和重要业务流程：
- 用户操作的关键节点（登录、注册、支付等）
- 业务流程的开始和结束
- 性能报告和统计信息

**示例**：
```
【用户登录】用户ID：123，邮箱：test@example.com
【聊天开始】用户ID：123，会话ID：session-456，模型：gpt-4，消息数：5
【支付创建】用户ID：123，套餐ID：1，支付方式：alipay
```

### DEBUG 级别 - 详细信息
记录详细的执行过程和数据，用于问题排查：
- 方法调用的详细参数和返回值
- 业务流程的中间步骤
- 外部系统交互的详细信息

**示例**：
```
【登录验证】用户存在检查通过，用户ID：123
【AI请求】用户ID：123，模型：gpt-4，请求体：{"messages":[...]}
【支付处理】开始验证支付请求参数，用户ID：123
```

### WARN 级别 - 警告信息
记录潜在问题或异常情况，但不影响系统正常运行：
- 业务规则验证失败
- 资源使用接近阈值
- 用户可疑行为

**示例**：
```
【登录失败】用户不存在：test@example.com
【使用限制】用户ID：123，模型：gpt-4，当前使用量：95，限制：100
【资源预警】类型：CPU，使用率：85.5%，阈值：80%
```

### ERROR 级别 - 错误信息
记录系统错误和异常，需要立即关注和处理：
- 未捕获的异常详情
- 业务流程中断
- 系统组件故障

**示例**：
```
【用户登录异常】邮箱：test@example.com，异常：数据库连接失败
【AI服务错误】用户ID：123，会话ID：session-456，模型：gpt-4，错误：API超时
【系统异常】组件：性能监控，错误：内存不足，影响：监控数据缺失
```

## 🛠️ 技术实现

### 1. 日志工具类（LogUtils）
提供了以下核心功能：
- **内容截断**：对长文本进行截断，保留前15个和后15个字符
- **异常格式化**：将异常信息格式化为简洁形式
- **请求参数格式化**：格式化请求参数并处理敏感信息

### 2. 日志配置优化
- **开发环境**：DEBUG级别，便于开发调试
- **生产环境**：INFO级别，关键业务模块保持INFO级别
- **测试环境**：DEBUG级别，便于测试验证
- **问题排查**：特定模块DEBUG级别，临时使用

### 3. 统一日志格式
所有日志都采用统一的格式：`【模块/操作】关键信息：具体内容`
