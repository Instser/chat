# 07-03 16:24 截断续写对齐算法时序修复

## 问题描述

在截断续写功能中发现了严重的时序问题：

### 原始问题
1. **对齐算法执行时机错误**：对齐算法在续写流式响应完全结束后才执行
2. **前端接收内容未对齐**：在续写过程中，`processCompleteJson`方法直接将内容发送给前端，没有经过对齐处理
3. **用户体验问题**：前端接收到的内容存在重复或不连贯的问题

### 日志分析
从用户提供的日志可以看出：
```
2025-07-03 16:08:34.830 [reactor-http-nio-1] DEBUG - 处理AI API响应
2025-07-03 16:08:34.861 [reactor-http-nio-1] INFO - 完成智能分块流式发送，总字符数: 10
...
2025-07-03 16:09:31.670 [continuation-3] INFO - 开始内容对齐，原内容长度：9655，续写内容长度：183
```

**时序问题**：对齐算法在16:09:31才执行，但流式内容在16:08:34就开始发送给前端了，导致前端接收到未对齐的内容。

## 解决方案

### 核心思路
将对齐算法的执行时机从"续写完成后"改为"续写开始响应时"，确保发送给前端的内容都是经过对齐处理的。

### 技术实现

#### 1. 新增带对齐的续写处理方法
创建`executeContinuationRequestWithAlignment`方法替代原有的`executeContinuationRequest`方法：

```java
private boolean executeContinuationRequestWithAlignment(ChatRequestDTO request, AiModel model, 
        HttpServletResponse response, String originalContent, StringBuilder continuationContent, 
        StringBuilder alignedContentForSaving, boolean[] hasContentSent, 
        boolean[] isRealAiResponse, boolean[] alignmentDone)
```

#### 2. 新增专用的续写JSON处理方法
创建`processContinuationJson`方法，在处理第一个续写响应块时就执行对齐：

```java
private String processContinuationJson(String jsonData, HttpServletResponse response, 
        String originalContent, StringBuilder continuationContent, 
        StringBuilder alignedContentForSaving, boolean[] alignmentDone)
```

#### 3. 对齐算法前置执行
- **第一个响应块**：执行对齐算法，计算需要发送给前端的内容（去除重叠部分）
- **后续响应块**：直接发送新内容，无需再次对齐

### 关键改进点

#### 1. 时序优化
```java
// 如果还没有进行对齐，先进行对齐处理
if (!alignmentDone[0]) {
    // 执行对齐算法
    String alignedContent = truncationDetectionService.alignContent(originalContent, cleanContent);
    
    // 计算需要发送给前端的内容（去除重叠部分）
    String contentToSend;
    if (alignedContent.length() > originalContent.length()) {
        contentToSend = alignedContent.substring(originalContent.length());
    } else {
        contentToSend = cleanContent; // 如果对齐失败，发送原始内容
    }
    
    alignmentDone[0] = true;
    // 发送对齐后的内容给前端
}
```

#### 2. 状态管理
- `alignmentDone[0]`：标识是否已完成对齐
- `alignedContentForSaving`：保存最终对齐后的完整内容用于数据库存储
- `continuationContent`：保存原始续写内容用于日志记录

#### 3. 内容分离
- **发送给前端**：经过对齐处理，去除重叠部分的内容
- **保存到数据库**：完整的对齐后内容（原内容+续写内容）
