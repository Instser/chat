# 系统架构模式

## 系统构建方式
采用经典的分层架构模式，结合Spring Boot的约定优于配置原则：

### 分层架构
1. **Controller层**: 处理HTTP请求，参数验证，响应格式化
2. **Service层**: 业务逻辑处理，事务管理
3. **DAO层**: 数据访问，SQL操作
4. **Entity层**: 数据实体，数据库表映射
5. **VO层**: 视图对象，前后端数据传输

### 设计模式应用
- **依赖注入**: 使用Spring的@Autowired和构造器注入
- **工厂模式**: AlipayClient的Bean创建、DocumentParserFactory文档解析器工厂
- **策略模式**: 不同支付方式的处理，包含完整的回调处理
- **转换器模式**: Entity到VO的数据转换
- **模板方法模式**: 支付回调处理的通用流程
- **状态模式**: 订单状态流转的管理和验证

## CORS跨域配置修复 (2025-06-16 01:10)

### 问题描述
前端访问后端API时出现CORS跨域错误：
```
Access to fetch at 'http://localhost:8080/api/auth/login' from origin 'http://localhost:3000'
has been blocked by CORS policy: Response to preflight request doesn't pass access control check:
No 'Access-Control-Allow-Origin' header is present on the requested resource.
```

### 根本原因分析
虽然项目已配置了WebConfig中的CORS设置，但Spring Security会拦截所有请求，需要在SecurityConfig中明确启用CORS支持。

### 解决方案
1. **在SecurityConfig中添加CORS配置源**:
   - 创建 `corsConfigurationSource()` Bean
   - 配置允许的源: `http://localhost:3000`, `http://localhost:3001`
   - 配置允许的方法: `GET`, `POST`, `PUT`, `DELETE`, `OPTIONS`
   - 配置允许的请求头: `*`
   - 启用凭据传递: `allowCredentials = true`

2. **在SecurityFilterChain中启用CORS**:
   - 添加 `.cors(cors -> cors.configurationSource(corsConfigurationSource()))`
   - 确保CORS配置在其他安全配置之前生效

### 技术实现
- 使用Spring Security的CORS配置而非仅依赖WebMvcConfigurer
- 采用CorsConfigurationSource Bean方式管理CORS配置
- 支持预检请求(OPTIONS)的正确处理

### 配置效果
✅ 支持localhost:3000前端访问
✅ 支持localhost:3001备用端口
✅ 允许携带认证凭据
✅ 支持所有必要的HTTP方法
✅ 预检请求缓存3600秒

## 文件安全性增强 (2025-06-25 17:00)

### 实现背景
原有的文件类型检测仅依赖文件名后缀和浏览器提供的Content-Type，存在安全隐患。攻击者可以通过修改文件名或伪造Content-Type来绕过文件类型限制，上传恶意文件。为了提升系统安全性，需要实现基于文件实际内容的检测机制。

### 技术实现
1. **文件魔数检测机制**:
   - 实现 `detectFileTypeByMagicNumber()` 方法，读取文件头部字节序列
   - 支持PNG、JPEG、GIF、WebP、BMP、PDF、ZIP等常见格式的魔数识别
   - 基于文件实际二进制内容而非可伪造的元数据进行类型判断

2. **智能文本文件检测**:

## OAuth2渐进式集成架构模式 (2025-07-16 21:47)

### 架构设计原则
基于零破坏性、完全兼容、渐进式集成的设计原则，构建企业级OAuth2认证系统：

1. **零破坏性原则**:
   - 现有用户登录方式完全不变
   - 与现有JWT认证体系无缝集成
   - 不修改现有数据库表结构
   - 保持原有API接口完全兼容

2. **安全优先原则**:
   - CSRF状态验证防止跨站请求伪造
   - AES加密存储OAuth令牌
   - 多层频率限制和访问控制
   - 完整的安全审计日志记录

3. **渐进式集成原则**:
   - 新增功能，不修改现有代码
   - 分阶段实施，降低实施风险
   - 支持功能开关和平滑回滚
   - 最小化系统复杂性

### 核心架构组件

1. **安全防护层**:
   - **CSRF状态验证**: 生成随机状态令牌，服务端存储验证，防止重放攻击
   - **频率限制**: 登录URL获取、回调处理、基于IP的多层访问控制
   - **令牌加密存储**: AES加密存储OAuth令牌，保护用户隐私数据
   - **安全审计日志**: 详细记录所有OAuth操作，支持安全事件监控

2. **OAuth2核心层**:
   - **OAuth2Controller**: 处理登录URL生成、回调处理、账号绑定/解绑
   - **OAuth2Service**: 业务逻辑处理，用户信息获取，账号合并策略
   - **OAuth2SecurityConfig**: 安全配置管理，状态验证，错误处理
   - **OAuth2ErrorHandler**: 统一错误处理，用户友好提示

3. **数据持久层**:
   - **UserOAuth表**: OAuth账号绑定信息，支持多提供商绑定
   - **OAuth2State表**: 状态令牌验证，防止CSRF攻击
   - **OAuth2AuditLog表**: 安全审计日志，操作追踪和异常监控

### 安全架构模式

1. **状态验证模式**:
   ```
   客户端请求 → 生成状态令牌 → 存储验证信息 → OAuth授权 →
   回调验证 → 状态匹配检查 → 一次性消费 → 继续处理
   ```

2. **令牌安全模式**:
   ```
   OAuth令牌 → AES加密 → 数据库存储 → 使用时解密 →
   过期检查 → 自动刷新 → 重新加密存储
   ```

3. **账号合并模式**:
   ```
   OAuth登录 → 检查已绑定 → 检查邮箱存在 →
   自动绑定账号 → 创建新用户 → 生成JWT令牌
   ```
