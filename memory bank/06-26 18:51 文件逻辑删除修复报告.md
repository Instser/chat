# 文件逻辑删除修复报告

**📅 修复时间**: 2025-06-26 18:51:51  
**👤 修复人员**: Augment Agent  
**📊 文档版本**: v1.0  

## 问题描述

在删除文件关联记录时，后端日志显示已经删除文件关联，但是数据库中的逻辑删除字段（deleted）依旧显示为0，表明文件并未被正确标记为删除状态。

### 问题现象
```log
2025-06-26 18:30:15.123 [http-nio-8080-exec-1] INFO  c.i.chat.service.serviceimpl.FileUploadServiceImpl - 文件5fad4c7e-ed2d-414f-afb9-52a681bd124b已标记为删除，关联消息：d286ab2f-894f-46d9-8a1a-14b71e8f8715
```

但数据库查询结果：
```sql
SELECT file_id, deleted FROM t_file_upload WHERE file_id = '5fad4c7e-ed2d-414f-afb9-52a681bd124b';
-- 结果：deleted = 0 (应该是1)
```

### 问题根因分析

经过深入分析，发现问题出现在文件删除方法的实现上：

#### 1. MyBatis-Plus逻辑删除机制
在`FileUpload`实体类中，`deleted`字段使用了`@TableLogic`注解：
```java
@TableLogic
@TableField("deleted")
private Integer deleted;
```

同时在`application.yml`中配置了逻辑删除：
```yaml
mybatis-plus:
  global-config:
    db-config:
      logic-delete-field: deleted
      logic-delete-value: 1
      logic-not-delete-value: 0
```

#### 2. 错误的删除实现
在`deleteFilesByMessageId`和`deleteFilesBySessionId`方法中，代码手动设置deleted字段并调用`updateById`：
```java
// 错误的实现方式
file.setDeleted(1);
file.setUpdateTime(LocalDateTime.now());
boolean updated = this.updateById(file);
```

#### 3. 正确的删除实现
在`deleteFile`方法中使用了正确的MyBatis-Plus逻辑删除方法：
```java
// 正确的实现方式
return removeById(fileUpload.getId());
```

### 问题原因
当使用`@TableLogic`注解时，MyBatis-Plus会自动处理逻辑删除，但手动调用`updateById`方法时，MyBatis-Plus可能不会正确处理逻辑删除字段的更新，导致deleted字段没有被正确设置。

## 修复方案

### 核心思路
统一使用MyBatis-Plus提供的`removeById`方法进行逻辑删除，而不是手动设置deleted字段。

### 修复步骤

#### 1. 修复deleteFilesByMessageId方法
**文件**: `src/main/java/com/instser/chat/service/serviceimpl/FileUploadServiceImpl.java`

**修改前**:
```java
// 验证文件所有权并执行逻辑删除
int deletedCount = 0;
for (FileUpload file : files) {
    if (file.getUserId().equals(userId)) {
        file.setDeleted(1);
        file.setUpdateTime(LocalDateTime.now());
        boolean updated = this.updateById(file);
        if (updated) {
            deletedCount++;
            log.info("文件{}已标记为删除，关联消息：{}", file.getFileId(), messageId);
        }
    } else {
        log.warn("文件{}不属于用户{}，跳过删除", file.getFileId(), userId);
    }
}
```

**修改后**:
```java
// 验证文件所有权并执行逻辑删除
int deletedCount = 0;
for (FileUpload file : files) {
    if (file.getUserId().equals(userId)) {
        // 使用MyBatis-Plus的逻辑删除方法
        boolean deleted = this.removeById(file.getId());
        if (deleted) {
            deletedCount++;
            log.info("文件{}已标记为删除，关联消息：{}", file.getFileId(), messageId);
        } else {
            log.warn("文件{}删除失败，关联消息：{}", file.getFileId(), messageId);
        }
    } else {
        log.warn("文件{}不属于用户{}，跳过删除", file.getFileId(), userId);
    }
}
```

#### 2. 修复deleteFilesBySessionId方法
**文件**: `src/main/java/com/instser/chat/service/serviceimpl/FileUploadServiceImpl.java`

**修改内容**: 与`deleteFilesByMessageId`方法相同的修复逻辑，将手动设置deleted字段改为使用`removeById`方法。

## 技术细节

1. **自动处理**: `removeById`方法会自动将deleted字段设置为配置的删除值(1)
2. **查询过滤**: 后续查询会自动过滤deleted=1的记录
3. **更新时间**: MyBatis-Plus会自动更新update_time字段
